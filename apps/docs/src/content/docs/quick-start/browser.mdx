In a browser, `@lamina/pdf` resolves through its `browser` export condition. The glue finds each `.wasm` file with `new URL("…", import.meta.url)`, so your bundler emits the files as assets next to your code, and they load from your own origin.

This app is bundled by Vite and run in Chromium in CI (`packages/pdf/test/vite.test.ts`). It loads the base module, opens a document, then loads the text module and builds a page:

<Snippet file="packages/pdf/test/vite-app/main.ts" />

- **Two modules, loaded on demand.** `init()` loads the base module (open, edit, save, vector pages). `loadText()` (or `init({ text: true })`) adds fonts and text. A page that never draws text never downloads the text module.
- **Vite:** exclude the package from dependency pre-bundling (`optimizeDeps.exclude: ["@lamina/pdf"]` in `vite.config.ts`), so the `.wasm` URLs stay next to the glue.
- **Content Security Policy:** compiling WebAssembly needs `script-src 'wasm-unsafe-eval'`. Nothing else is needed.
