You'll save an edited PDF, either by appending your changes to the original bytes or by writing the whole file again. The choice matters when a file is signed, was damaged, or is password-protected, because each one limits how it can be saved.

## Choose a save mode

Every save either appends a revision to the bytes you opened (an incremental save) or writes the whole file again (a [full rewrite](/reference/glossary/#full-rewrite)). You pick one with the `mode` option:

| `mode` | What it writes |
| --- | --- |
| `auto` (the default) | Incremental when that's allowed, otherwise a full rewrite |
| `incremental` | The original bytes unchanged, then one appended revision |
| `fullRewrite` | The whole file again |

`doc.save(options)` returns the bytes, and `doc.saveWithReport(options)` also says what it wrote. `doc.saveJob()` does the same work in steps, so a page can save a large file without freezing. The same file with the same edits always saves to the same bytes.

## When a file refuses a save

Every save makes a plan before it writes. The plan reads the file's save constraint: what its signatures, permissions, repairs and encryption allow. Then it picks a mode or refuses:

- **A signed file** saves only incrementally, and only with edits its signatures allow. Anything else fails with `would-invalidate-signatures`. Pass `invalidateSignatures: true` to save anyway, which removes the broken signatures from the output.
- **A repaired file**, one Lamina PDF had to fix as it opened, can't safely take an appended revision. It needs a full rewrite, so asking for `incremental` fails with `requires-rewrite`.
- **An edited encrypted file** saves only as a full rewrite without its encryption, and only when you pass `removeEncryption: true`. Otherwise every mode fails with `encrypted-base`.
- **An unchanged document**, even a signed, repaired or encrypted one, saves incrementally in `auto` and `incremental` mode and returns the bytes you opened. Passing `removeEncryption: true` rewrites it instead.

## See the plan before you save

`doc.plan(options)` says how a save would go, without saving. Its `constraint` is `free`, `appendOnly`, `requiresRewrite` or `conflict`, and it lists the signatures, the edits they forbid and the `refusal` code a save would fail with. Show it before the user saves. To warn before an edit instead, `doc.wouldViolate(op)` lists what one edit would break.

## Write a copy, then adopt it

`doc.saveCopy(options)` writes what a save would and leaves the document as it was: its edits stay unsaved, and a later plan still sees them. Use it for Download a copy, and for a save whose write can fail, such as one to the user's disk. Write the copy first, then call `doc.adoptCopy(bytes, report.historyCleared)`, which makes it the document's saved file. If the write fails, don't adopt it: every edit stays unsaved.

## Stamp the time of the save

Pass `metadataDate`, the time from your app's clock, and a save that writes changes records it as the modification date and gives the XMP metadata a new instance ID. `instanceId` sets that ID yourself. Lamina PDF never reads the clock, so without either option nothing is stamped. On a certified file whose edits are otherwise allowed, the stamp is left out, and the report's `metadataNotUpdated` says so.

:::note[Details]
The save constraint covers signature fields, the [DocMDP](/reference/glossary/#docmdp) and [UR3](/reference/glossary/#ur3) permissions, a signature's `/Lock` entry (the form fields it locks), document timestamps, and whether the file needed repair.
:::
