You'll draw one page of a PDF as an image at the width you choose: onto a canvas in a web page, or into a PNG file in Rust. You need this for thumbnails, a preview in a file list, or a check that a page looks right.

The canvas then holds the page as the reader would see it in a PDF viewer, at its own height for that width: an A4 page 600 pixels wide is 849 pixels tall. ## Pick a renderer

Lamina PDF reads a PDF's text, links and structure itself, but it doesn't draw pages. Two renderers do, behind one interface, `RenderBackend`, so the code that calls them is the same:

| Renderer | Where it runs | Install |
| --- | --- | --- |
| PDFium, the engine behind Chrome's PDF viewer | Browsers, as WebAssembly; Rust, as a native library loaded at run time | `@laminapdf/render-pdfium` with `@embedpdf/pdfium@2.15.1`; the `laminapdf-render-pdfium` crate |
| hayro, a renderer written in Rust | Browsers and Node, as WebAssembly; Rust, compiled into your program | `@laminapdf/render-hayro`; the `laminapdf-render` crate with its `hayro` feature |

We recommend PDFium where people look at the pages, since it draws them the way Chrome does. hayro needs no native library and reads the whole file before it draws, which suits a server or a test that already holds the file. [How a page is drawn](/concepts/drawing-pages/) explains how the two compare.

Load a renderer once and reuse it for every page. In a browser, `await initPdfium(wasmUrl)` takes the URL your bundler gives PDFium's `.wasm` file, and `await initHayro()` finds hayro's own. In Rust, `HayroBackend::new()` is ready at once, and `PdfiumBackend::bind(dir)` loads PDFium from the folder that holds `libpdfium.so`, `libpdfium.dylib` or `pdfium.dll`.

## Choose the size

A render request names the page, counting from 0, and the scale in pixels per point. A point is 1/72 of an inch, so a scale of 1 draws 72 pixels per inch, and 2 draws 144, sharp on most screens. Both examples work out the scale from the width you want and the page's width in points. A page's size in pixels rounds down, so both examples ask for half a pixel more.

The width is the page's displayed width, after any rotation the file sets, so the picture comes out the way a viewer shows it. To turn the picture further, add `rotation: 90`, `180` or `270` to the request (`with_rotation` in Rust).

## Draw part of a page

For a large page at a high zoom, draw only the part you need: `clip: { x, y, width, height }` in pixels of the whole page at that scale (`with_clip` in Rust). A viewer draws a large page this way, tile by tile. Each tile has a limit: by default, at most 16,384 pixels on a side and about 16.7 million pixels in all. A larger request fails with `render-too-large` before the renderer allocates anything, so a mistaken scale never fills your memory.

## Pixels, not text

The renderer returns straight RGBA: four bytes a pixel, red, green, blue and alpha, row by row from the top-left corner. White is the default background; `background: null` draws a transparent one. The picture holds no text. For the text of the same page, ask Lamina PDF.

On the command line, `laminapdf render` draws pages to PNG files without any code: see [extract text and render pages](/cli/extract-and-render/).
