You'll open a PDF on a web server by fetching only the parts you read. A large report opens after a few small requests, and reading its first page fetches that page and little else. You need this when files are too large to download before the first page shows.

## Each read fetches the bytes it needs

`Document.openRange` fetches only what opening needs: the end of the file, where a PDF keeps the index of its objects, and the objects that index points to first. Calls on the document stay synchronous, so a read that needs bytes not fetched yet can't wait for them. It throws `data-pending` instead, with the byte ranges it needs. `doc.ensure` runs your read, fetches those ranges when it throws, and runs it again until it returns:

<Diagram name="range-loading" />

Wrap every read after the open in `doc.ensure`, saving included: `await doc.ensure(() => doc.save())` fetches whatever the save writes. A read fails with the last `data-pending` when its fetches bring nothing new, or when it still needs bytes after 1,024 rounds of fetches. Pass `maxRounds` to `Document.openRange` to change that number.

## The server must answer `Range` requests

`httpRangeSource(url)` asks for byte ranges with the `Range` header, and most file hosts and CDNs answer them. Across origins, the server must also allow the `Range` header (`Access-Control-Allow-Headers: Range`) and expose `Content-Range`, `Content-Length` and `ETag` (`Access-Control-Expose-Headers`). It must not compress the response, or the ranges it sends wouldn't match the file's bytes.

A server that ignores `Range` and answers `200` sends the whole file. Lamina PDF then opens that one download, as `Document.open` would.

## A file that changes on the server fails the read

Every request after the first sends `If-Range` with the file's first strong `ETag`, or its `Last-Modified` date when it has none. When the file changes between two reads, the read fails with `source-changed` rather than mixing two versions. Open the file again to read the new one. An error status from the server fails with `fetch-failed`, its `data.status` holding the status code.

## Limit how much a file can make you fetch

A remote file decides how much you fetch, so cap it when the file comes from someone else. Pass `budget` to `Document.openRange`: it's the most bytes the document may hold, and past it a read fails with `source-budget-exceeded`. A `signal` among the same options stops the open's fetches, and `doc.ensure(read, { signal })` takes its own for each later read, such as `AbortSignal.timeout(10_000)`.

The [limits for files you don't trust](/guides/untrusted-files/) apply here too: pass `limits` with the other options.
