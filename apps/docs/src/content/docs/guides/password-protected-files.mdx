## Pass the password

Pass the password when you open the file: `Document.open(bytes, { password })`. The password goes only to the WebAssembly module. Lamina PDF never stores or logs it, and never puts it in an error.

A PDF can have two passwords. The user password opens the file, and the owner password also lifts its restrictions, such as on printing or copying. Lamina PDF checks your password against both:

- **Older files** (RC4 and AES-128) check the user password first.
- **AES-256 files** check the owner password first, as PDF 2.0 requires. So a password that matches both counts as the owner's.

## When the password is missing or wrong

Opening fails with `password-required` when you pass no password, and with `wrong-password` when it matches neither. Nothing else has changed, so ask your user and open the file again.

## Passwords with accents and other symbols

A character such as "é" can be written in more than one way in Unicode, so the same password can arrive as different bytes. In TypeScript, Lamina PDF tries the password as you give it and, after `wrong-password`, again in its NFKC form, the Unicode form that makes such spellings match. Older files also accept a password's Latin-1 bytes. AES-256 files accept the password as given or in the normalised form that PDF 2.0 asks for (SASLprep).

## Save an encrypted file

An encrypted file keeps its protection when you save it. An [incremental save](/reference/glossary/#incremental-save) encrypts what it appends under the key the file opened with, and a [full rewrite](/reference/glossary/#full-rewrite) encrypts every string and stream again. You don't pass the password a second time. `doc.save()` draws the random bytes it needs from `crypto.getRandomValues`, so the call is the same as for any file.

To write the file without its encryption, save with `removeEncryption: true`. That is a full rewrite with every string and stream in plain text, and anyone who gets the file can read it.

## Protect a file with a password

`doc.setEncryption({ user, owner, permissions })` protects a file when you next save it, with AES-256 (the standard security handler at revision 6). The `user` password opens the file. The `owner` password, the permissions password, lifts the limits in `permissions`: `print` (`"none"`, `"lowResolution"` or `"highResolution"`), `copy`, `fillForms`, `comment` and `assemble`, each allowed unless you set it to `false`. Give at least one password, or the edit fails with `encryption-no-password`.

```ts
using doc = Document.open(bytes);
doc.setEncryption({ user: "open sesame", owner: "owner secret", permissions: { copy: false } });
const protectedBytes = doc.save();
```

With no `user` password the file opens for anyone and carries only the limits. With no `owner` password the save makes one and returns it in `report.generatedOwnerPassword` (use `doc.saveWithReport()`). Show it once and ask your user to keep it: nothing else can lift the limits.

The save writes the whole file again, so it drops the earlier revisions and breaks any signature. On a signed file it refuses with `would-invalidate-signatures` until you allow that. A file that claims PDF/A can't be encrypted, since PDF/A forbids it: the edit fails with `encryption-pdfa-conflict`, and `removeConformanceClaims` takes the claim off first.

`doc.encryptionInfo()` says how a file is protected: the handler, revision, ciphers, key length, what the file permits and which password opened it. It never returns a key.

:::caution[Permissions ask readers, they don't lock the file]
Anyone who can open an encrypted file can read it, copy it and print it, whatever its permissions say. The limits ask readers to behave: Lamina PDF's editor honours them in its tools, and the owner password lifts them. To keep information from someone, don't give them the file, or [remove it first](/guides/check-what-a-file-hides/). A password never reaches an op log, an error message or the file.
:::

:::note[Details]
Lamina PDF reads files encrypted with the standard security handler: RC4 (revisions 2–4), AES-128 (revision 4) and AES-256 (revisions 5 and 6), including crypt filters and unencrypted metadata. It decrypts strings and streams as the file loads.
:::
