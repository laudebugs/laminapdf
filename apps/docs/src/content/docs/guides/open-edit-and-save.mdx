Edits never change the bytes you opened. A save either appends a revision (an [incremental save](/reference/glossary/#incremental-save)) or writes the whole file again (a [full rewrite](/reference/glossary/#full-rewrite)). [How Lamina PDF thinks about a PDF](/concepts/how-lamina-thinks/) explains why.

## Edits are ops in transactions

`doc.transact(tx => …)` collects ops (`setInfo`, `rotatePage`) and applies them as one transaction when the callback returns. The callback is synchronous. If it throws, nothing is applied. Inside it, another edit or a save of the same document fails with `nested-transaction`.

`doc.undo()` and `doc.redo()` revert and reapply whole transactions. Ops are also plain JSON (`{ op: "rotatePage", args: { … } }`), so `doc.apply(ops)` and `doc.applyLog({ v: 1, ops })` replay a log.

## Saving

`doc.save(options)` returns the bytes, and `doc.saveWithReport` also says what it wrote. `doc.saveJob()` does the same work in steps, for UIs that mustn't block.

| `mode` | What it writes |
| --- | --- |
| `auto` (the default) | Incremental when that's allowed, otherwise a full rewrite |
| `incremental` | The original bytes unchanged, then one appended revision |
| `fullRewrite` | The whole file again |

Every save plans first. The planner reads the file's **save constraint**: signatures, [DocMDP](/reference/glossary/#docmdp) and [UR3](/reference/glossary/#ur3) permissions, `/Lock`, document timestamps, and whether the file needed repair. Then it chooses or refuses:

- A signed file saves only incrementally, and only edits its signatures allow. Anything else fails with `would-invalidate-signatures`, unless you pass `invalidateSignatures: true`, which removes the invalidated signatures from the output.
- A repaired file can't be appended to safely, so it needs a [full rewrite](/reference/glossary/#full-rewrite). Asking for `incremental` fails with `requires-rewrite`.
- An encrypted file isn't rewritten in plaintext unless you pass `removeEncryption: true`. Otherwise saving fails with `encrypted-base`.
- An unchanged document always saves incrementally, which returns its bytes unchanged.

Output is deterministic: the same edits give the same bytes.
