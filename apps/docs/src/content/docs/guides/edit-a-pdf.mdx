Your edits live beside the bytes you opened and never change them. Nothing reaches a file until you save. [How Lamina PDF thinks about a PDF](/concepts/how-lamina-thinks/) explains why it works this way.

## Group edits into a transaction

`doc.transact(tx => …)` collects edits, such as `setMetadata` and `rotatePage`, and applies them together when the callback returns. If the callback throws, none of them apply. The callback is synchronous, and editing or saving the same document inside it fails with `nested-transaction`.

## Change the metadata

`doc.setMetadata({ title, authors })` changes a document's title, authors, subject, keywords, dates, and the creating and producing applications, and `doc.removeMetadata(["keywords"])` removes fields. A PDF keeps these facts twice, in its Info dictionary and its XMP metadata, and each edit writes both. `doc.metadata()` reads them back. [Edit the metadata](/recipes/edit-metadata/) has the whole program.

## Organise the pages

Five calls change which pages a document has and their order: `doc.deletePages(ids)`, `doc.movePages(ids, "start")`, `doc.insertBlankPages("end", 1, { width: 612, height: 792 })`, `doc.rotatePages(ids, 90, { mode: "turn" })` and `doc.reversePages(ids)`. They name pages by ID, and a page keeps its ID when it moves. Deleting a page sends the bookmarks and links that pointed at it to the nearest page left, and deleting every page is refused. [Organise pages](/recipes/organise-pages/) has the whole program.

`doc.duplicatePages(ids, "end")` copies pages. A copy shares its page's content but gets annotations and form fields of its own, so filling in the copy leaves the original alone. [Duplicate pages](/recipes/duplicate-pages/) shows a form page copied.

`doc.cropPages(ids, { top: 36, left: 36 })` crops pages by margins of the page as it shows, so one set suits every size and rotation, and `doc.setPageBoxes(ids, { trim: [x0, y0, x1, y1] })` sets any of a page's five boxes. A crop only hides content: the edit's `croppedContentRemains` lists the pages whose hidden text is still in the file. [Crop pages](/recipes/crop-pages/) has the whole program.

`doc.resizePages(ids, { width: 612, height: 792 })` puts pages on new paper, scaling their content to fit, and `doc.setOrientation(ids, "landscape")` turns pages shown the other way. Links, notes, bookmarks and the opening view move with the content. [Resize pages](/recipes/resize-pages/) has the whole program.

`doc.addSource(bytes)` opens another PDF as a source of pages. `doc.insertPagesFrom(source.id, pages, "end")` copies its pages in, and `doc.replacePages(targets, source.id, pages)` puts them in other pages' places. `doc.extractPages(ids)` makes a new PDF from some pages. [Copy pages between PDFs](/recipes/copy-pages/) shows each.

`Document.merge(files)` makes one document from several files, with a bookmark for each, and `doc.mergeDocuments(sources, "end")` merges sources into an open document as one edit. `doc.split({ bookmarks: 1 })` makes one document per chapter. A merge of tagged PDFs makes a tagged file, each file's tags under a `Part` named after it. [Merge and split PDFs](/recipes/merge-and-split/) shows both.

## Name the pages

A viewer's page box can show a page's label instead of its number: "Cover", "iv" or "A-3". `doc.setPageLabels(ranges)` replaces a document's labels. Each range starts at a page, named by its ID, and labels that page and the ones after it until the next range. A range has a style (decimal, roman or letters, upper or lower case), a prefix and a first number. The first range must start on the first page and the rest must follow in page order, or the edit fails with `invalid-label-ranges`. An empty list removes the labels.

## Undo and redo

`doc.undo()` reverts the last transaction as a whole, and `doc.redo()` applies it again. A transaction is the unit of undo, so group the edits a user would expect to undo together. A new transaction clears what redo could apply.

Both return a `Reverted` record, `{ outcome, touchedPages }`, or `undefined` when there is nothing to undo or redo. `outcome` is `applied`, or `partial` when a later edit replaced part of the change, which keeps the later value, or `skipped` when nothing could be restored. `touchedPages` lists the IDs of the pages the transaction changed, so a viewer redraws only those. `doc.apply(ops)` returns `touchedPages` too, and `changed`, which is false when the edit only set values the document already had and so left nothing to undo.

## Replay edits stored as JSON

Every edit is also a plain JSON object, such as `{ op: "rotatePage", args: { … } }`. So you can store edits, send them to a server and replay them later. `doc.apply(ops)` applies a list of them as one transaction, and `doc.applyLog({ v: 1, ops })` replays a saved log.
