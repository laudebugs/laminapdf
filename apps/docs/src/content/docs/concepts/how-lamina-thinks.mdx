lamina treats a PDF as bytes: you give it bytes, and it gives bytes back. Six ideas follow from that, and the rest of the docs build on them.

## Bytes in, bytes out

lamina never touches the file system or the network, and it never reads the clock. Your app reads the file, hands lamina the bytes and stores whatever comes back. That's why the same code runs in a browser, on a server and inside a Cloudflare Worker.

## The file you opened never changes

When you open a document, lamina keeps its bytes exactly as they were. Every edit goes into an [overlay](/reference/glossary/#overlay) on top of them. Reading the document reads the overlay first, so you see your edits; undo and redo move through them.

## Two ways to save

A save writes the overlay out in one of two ways:

- **[Incremental save](/reference/glossary/#incremental-save):** the original bytes, unchanged, followed by a new revision that holds your edits. Signatures over the original stay valid.
- **[Full rewrite](/reference/glossary/#full-rewrite):** the whole file written again, smaller and tidier, but no longer the original bytes.

The default, `auto`, saves incrementally when it can. A signed file saves only incrementally, and lamina refuses an edit that its signatures don't allow. [Open, edit and save](/guides/open-edit-and-save/) has the details.

## Three modules in JavaScript

In JavaScript, lamina is WebAssembly, split into three modules so a page downloads only what it uses:

- **Base:** open, read, edit and save; vector and image pages.
- **Extract:** everything in base, plus text extraction.
- **Text:** everything in base, plus fonts, shaped text and extraction.

`init()` loads the base module, and `init({ text: true })` or `init({ extract: true })` loads the others. Rust has one crate, with features instead.

## Same input, same bytes

lamina writes the same bytes for the same input on every run and every platform. It reads no clock, so dates and file IDs are values you pass in. So you can test, cache and compare its output byte for byte.

## You free what you create

Documents and builders live in WebAssembly memory, which the garbage collector can't see. Free each one when you're done: `using doc = …` frees it at the end of the block, and `doc.free()` frees it at once. A short script can skip this, but a long-running server shouldn't.
