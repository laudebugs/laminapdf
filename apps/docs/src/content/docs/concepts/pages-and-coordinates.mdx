Every position you pass lamina is in page space: points measured from the top-left corner of the page, with y going down. It's the way a screen or a sheet of paper reads, so a number means the same thing in every part of the API.

## Points

A point is 1/72 of an inch. An A4 page is 595 × 842 points, and a US Letter page is 612 × 792. A page with a user unit, which scales its points, has it applied for you.

## The top-left corner of the page you see

The origin is the top-left corner of the page as a viewer displays it: its crop box, turned by its rotation. So `[72, 96]` is one inch from the left edge and 96 points from the top, whichever way the page is rotated in the file.

For text, the second number is the baseline, the line the letters sit on. Letters reach up from it, and descenders such as "g" and "p" hang below it.

## Pages count from 0

The first page is page 0 everywhere: `doc.page(0)`, a link's target, a page label's start.

## PDF's own coordinates

Inside the file, PDF measures from the bottom-left corner with y going up, before rotation. That's [user space](/reference/glossary/#user-space). lamina converts for you, so you only meet it in Rust, in the types whose names start with `UserSpace`.
