This page answers three questions about a PDF before you trust it or send it: what it is, whether it's damaged, and what it holds that its pages don't show. Run these three commands on files people upload to you, and on files you're about to publish.

## Whether it's damaged: `check`

Lamina PDF reads damaged files where it can, repairing what it must and warning about each repair. `check` reads the whole file, every page and every drawing instruction, and reports those warnings. It exits 3 when there were any, so a script can tell a clean file from a repaired one:

<Transcript name="check" />

`--strict` makes the first repair an error instead (exit 1). `--warnings-ok` turns exit 3 into 0, for a job that only fails on files it can't read.

### Failed redactions

`check` also finds redactions that hide text without removing it, so the text can still be copied out of the file. It warns about three kinds:

- `covered-text`: text under a black box or an image, still in the file and still extractable.
- `redaction-not-applied`: redaction marks that someone drew but never applied.
- `text-in-earlier-revision`: words an earlier version of the file holds and the latest doesn't. An edited PDF keeps each earlier version inside it.

These stay warnings under `--strict`, because they aren't damage. `--warnings-ok` hides them along with the repairs, so a job that must stop leaked redactions should read the warning codes from `--json`, not the exit code. To run the same checks from Rust, see [Check what a file hides](/guides/check-what-a-file-hides/).

## What it holds beyond its pages: `reveal`

A PDF can carry far more than its pages show: earlier versions of itself, metadata, attachments, scripts, comments, form values and text no one can see. `reveal` lists what a file holds in each of those categories, one line per category it found, and given several files it ends with a count of them:

<Transcript name="reveal" />

The letter was edited, and its first version still holds a word the final one removed. The brochure carries 24 characters of invisible text. The categories are:

| Category | What it lists |
| --- | --- |
| `history` | Earlier revisions, what each added, changed and freed, the words they hold that the latest doesn't, and objects nothing uses |
| `metadata` | The document information entries, the XMP metadata (a block of extra metadata in XML) with its size and namespaces, and thumbnails |
| `attachments` | Embedded files, with their names, sizes and types |
| `active-content` | Scripts and actions, what runs them, and XFA forms (forms described in XML) |
| `annotations` | Annotations by type, with each comment's author and text |
| `forms` | Form fields and their values |
| `hidden-content` | Hidden text by reason (covered, invisible, off the page, tiny, clipped or too faint to read), layers that are off, and unapplied redaction marks |

`reveal` counts hidden text without printing it. With `--json` and `--include-hidden-text`, its report lists each hidden run with its page, its box and its text.

### Stop a file before it ships

`--fail-on` names the categories a file must not hold. `reveal` exits 6 when a file holds any of them, so a release job can stop it:

```sh
laminapdf reveal dist/*.pdf --fail-on history,hidden-content,active-content,attachments
```

`--fail-on all` names every category. Most files carry some metadata, such as a title, so `--fail-on metadata` stops most files; leave it out unless you strip metadata before release.

A Rust program gets the same report from `Document::reveal`: [Check what a file hides](/guides/check-what-a-file-hides/) shows how.
