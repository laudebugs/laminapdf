# `apps/docs`: the docs site

lamina's documentation site ([todo B7a](../../docs/todos/done/B7a-docs-site.md)): [Astro](https://astro.build/) with [Starlight](https://starlight.astro.build/), served from Cloudflare Workers static assets. It has quick starts per runtime, guides, an examples gallery, the `@lamina/pdf` API reference (TypeDoc) and a page on the Rust API (rustdoc).

```sh
pnpm install                        # once per worktree
pnpm --filter @lamina/docs dev      # http://localhost:4321 (no CSP in dev)
pnpm --filter @lamina/docs build    # dist/: what deploys; fails on a broken internal link
pnpm --filter @lamina/docs typecheck
```

`cargo xtask check ts` runs the build (the fast lane's TypeScript job), so a broken link, a snippet that names a missing file, or TypeDoc failing on `@lamina/pdf` fails CI.

## How the pages get their content

- **Snippets are the tested files.** `src/components/Snippet.astro` reads a file of the repository at build time (`<Snippet file="packages/pdf/examples/hello.ts" />`). It can show only the files its `import.meta.glob` lists: the TS examples and the Worker example in `packages/pdf/examples/`, the runtime runners in `packages/pdf/test/`, and the Rust examples in `crates/lamina/examples/`. All of them run in CI, so the code on the site is code that runs. Don't paste code into a page: add or extend an example and show that.
- **The code table** (`src/components/CodeTable.astro`) reads `fixtures/codes.json`. Each group the schema allows appears in the file's order, with its title made from its key (`textWarnings` becomes "Text warnings"). A new group needs no change here.
- **The API reference** is generated by [starlight-typedoc](https://github.com/HiDeoo/starlight-typedoc) from `packages/pdf/src/index.ts` into `src/content/docs/reference/pdf/` (gitignored) on every build. TypeDoc 0.28 needs the TypeScript compiler API, which TypeScript 7 doesn't have, so this package uses TypeScript 6 from the `typedoc` catalog in `pnpm-workspace.yaml`. Without `packages/wasm/dist/`, the wasm-bindgen records show by name only (`skipErrorChecking`).
- **The example PDFs** are the goldens in `fixtures/golden/examples/`, copied into `dist/examples/pdf/` after the build (`astro.config.mjs`). That step fails if the gallery links a PDF that isn't a golden.

## Headers

`public/_headers` applies [ADR 0011 §4](../../docs/decisions/0011-cloudflare-topology-and-privacy.md#4-security-headers-appswebpublic_headers-for-)'s headers to every response, with these differences for a static docs site:

- **`script-src` lists hashes.** After the build, `astro.config.mjs` replaces `'inline-script-hashes'` with the SHA-256 of every inline script the build wrote (Starlight's theme and tabs, Expressive Code's copy button), so there is no `'unsafe-inline'` for scripts. `'wasm-unsafe-eval'` is for search (Pagefind).
- **`style-src` allows `'unsafe-inline'`,** because Expressive Code colours code tokens with style attributes.
- **`connect-src` is `'self'` only.**

The example PDFs drop the CSP, so the browser's PDF viewer can open them. PR previews add `X-Robots-Tag: noindex`. `apps/docs/biome.json` turns off Biome's unused-import and unused-variable rules for `.astro` files, because Biome sees only their frontmatter and not the template that uses them.

## Deploying

`wrangler.toml` is the Worker `lamina-docs`: static assets only, no script, `preview_urls` on, workers.dev until the owner picks a domain. `.github/workflows/docs.yml` deploys it:

- **Pull requests:** every PR that touches `apps/docs/`, `packages/pdf/`, the Rust examples, their goldens or `fixtures/codes.json` gets a preview (`wrangler versions upload --preview-alias pr-<n>`) and one comment with its URL, updated on each push. PRs from forks are skipped.
- **`main`:** production (`wrangler deploy`) on every push that touches those paths, or by running the workflow by hand.
- **Without the secrets,** the job passes with a notice and deploys nothing.

### What the owner needs to do

1. In Cloudflare, create an API token (My Profile → API Tokens → Create Token → Custom token) with:
   - **Account → Workers Scripts → Edit**: uploads versions and deploys the Worker, including its workers.dev route and preview URLs.
   - **Account → Account Settings → Read**: lets Wrangler read the account it deploys to.

   Scope it to the one account (Account Resources → Include → that account). No zone permissions are needed until a custom domain is added. Optionally, set a TTL and restrict client IPs.
2. Add two repository secrets (Settings → Secrets and variables → Actions): `CLOUDFLARE_API_TOKEN` (the token) and `CLOUDFLARE_ACCOUNT_ID` (the account ID, shown on the account's Workers overview page).
3. Run the **Docs site** workflow on `main` once (Actions → Docs site → Run workflow). The first `wrangler deploy` creates the Worker, and previews need it to exist. The account also needs a workers.dev subdomain, which the dashboard asks for on first use of Workers.
4. Later, to use a custom domain: put the zone on Cloudflare, add a `routes = [{ pattern = "docs.<domain>", custom_domain = true }]` entry to `wrangler.toml`, and give the token **Zone → Workers Routes → Edit** on that zone.
