# Fixtures

Shared test inputs and golden outputs, read by every implementation by path from the repository root ([code organization §6](../docs/guidelines/code-organization.md#6-tests-and-fixtures)). Today the Rust tests in `crates/*/tests/` use them; future TypeScript and binding tests read the same files.

These files were moved here from the [`pdf-basics` spike](../spikes/pdf-basics/SPEC.md) in Round A. The spike keeps its own frozen copy in `spikes/pdf-basics/fixtures/`, so the two copies are identical today but only this one may change.

## Rules

- Every file is listed below with its origin, licence and what it exercises. A PDF without a known licence is not committed.
- `golden/` files are byte-exact expected outputs. Tests never rewrite them; a change is regenerated by an explicit command and reviewed like code.
- `corpus/expected.json` holds facts that every implementation must reproduce, extracted independently with pypdf, never by Lamina PDF (`page_count`, `encrypted`, `revisions` as the count of `%%EOF`, `has_xref_stream`, `first_page_mediabox`, `root_keys`, `header_version`, `size`, and `outline_titles` flattened depth-first). It is written by [`tools/corpus-facts/facts.py`](../tools/corpus-facts/facts.py) (`cargo xtask corpus facts`, with the pinned pypdf from its `requirements.txt` in `$LAMINA_PDF_PYTHON` or `python3`); the script reads and writes only `corpus/`. Deliberate differences go in `corpus/exceptions.toml`, each with the ADR 0003 rule behind Lamina PDF's answer.
- `encrypted/expected.json` holds the facts for the encrypted fixtures, written by `encrypted/facts.py` from pypdf and qpdf (never Lamina PDF). It is the single source of truth for `encrypted/`; `corpus/expected.json` never lists those files, so corpus regeneration (B2c) and the encrypted set don't overwrite each other.
- `differential/expected.json` holds pypdf's outcome (opened/repaired/failed), page count and outline titles for every corpus file and its fixed-seed mutants (generated by `crates/laminapdf-model/tests/common/mutants.rs`); `cargo xtask differential --update` regenerates it, and `crates/laminapdf-model/tests/differential.rs` compares Lamina PDF against it without Python. Triaged disagreements are in `differential/exceptions.toml`. `differential/text.json` (todo B9c) holds pdf.js's and pdftotext's text per page for the corpus and the text goldens (`cargo xtask differential --text --update`, [`tools/differential/text.mjs`](../tools/differential/text.mjs)), which `crates/laminapdf/tests/text_differential.rs` compares Lamina PDF's page text with (whitespace and bidi controls removed); its reasoned exceptions are in `differential/text-exceptions.json`. The full lane's set (36 mutants per corpus file) has its own `differential/full.json` and `full-exceptions.toml` (`cargo xtask differential --full [--update]`). Its `[[class]]` and `[[known]]` entries are read only by the nightly lane's live differential (`cargo xtask differential --live`), which compares the external corpus and every mutant (250 of the fast set's series and the full set's 36 per corpus file) with pdf.js, PDFium, qpdf and pypdf, applying both exceptions files.
- `corpus/pdfjs-operators.json` holds pdf.js's operator counts (`getOperatorList`, annotations off, `dependency` operators left out) for every page of `corpus/`, `golden/` and `content/`, written by [`tools/corpus-facts/pdfjs-operators.mjs`](../tools/corpus-facts/pdfjs-operators.mjs) with the pinned pdfjs-dist (Apache-2.0; tools only), never by Lamina PDF. `crates/laminapdf-content/tests/corpus.rs` maps Lamina PDF's operators to pdf.js's names ([ADR 0023](../docs/decisions/0023-content-stream-reading.md) §6) and compares; pages Lamina PDF can't interpret yet are in `corpus/pdfjs-exceptions.toml`, each with its error code and ADR 0003 rule.
- `reveal/examples/check_what_a_file_hides.txt` is the `check_what_a_file_hides` example's report on `corpus/hello-incremental.pdf` and `corpus/text-example.pdf`, under the names the docs' "Check what a file hides" guide gives them; `crates/laminapdf/tests/examples.rs` checks it, and `UPDATE_GOLDEN=1` rewrites it.
- `regressions/<target>/` (created with the first one) holds minimised fuzz crashes as raw `<hash>` files, replayed through the target's entry point by `crates/laminapdf-model/tests/regressions.rs` (`content`: `crates/laminapdf-content/tests/regressions.rs`; `ops_json` and `save_roundtrip`: `crates/laminapdf-save/tests/regressions.rs`; `extract_text`: `crates/laminapdf-text/tests/regressions.rs`), each also with a named regression test ([`fuzz/README.md`](../fuzz/README.md)).
  - `regressions/xmp_parse/a5b5f59f13e12026c3d0e84ff234cbdd72f017c2`: the full lane's 2026-11-10 crash, `golden/xmp/utf16.xmp` with NULs in the `dc` namespace URI. The reader took them, so `dc:title` was in another namespace; the canonical rewrite dropped them, and the old title read back as the title. The reader now refuses characters XML can't hold. The named test is `characters_xml_cannot_hold_are_refused`.
  - `regressions/extract_text/a4e5c15197b0b7271dc336dbb1cff7778c6e81dc`: the nightly's 2026-11-06 timeout, a right-to-left run of 11,142 glyphs that don't move the pen. `laminapdf-text`'s `by_position` scanned the whole run for each glyph to check for a letter. The named test is `a_right_to_left_run_without_widths_should_scale_linearly`.
- Goldens are regenerated only by `cargo xtask golden --update`, which rebuilds every file in `golden/` from its source and prints the list; `cargo xtask golden` checks that nothing would change.
- `ops/v1/` holds frozen JSON samples of version 1 of the op format ([ADR 0006](../docs/decisions/0006-op-log-and-undo.md) §6). They are hand-written, never rewritten by a test, and stay loadable when a later version is added (a new version gets its own `ops/vN/`).
- `codes.json` (v2, [ADR 0026](../docs/decisions/0026-error-and-diagnostic-contract.md)) lists every warning code, error code and hard-limit name that Lamina PDF exposes ([ADR 0003](../docs/decisions/0003-reader-tolerance-and-limits.md) §4). `warnings` and `errors` hold the reader's codes, `opErrors` and `opWarnings` (the metadata ops' conformance warnings) those `laminapdf-ops` adds and `saveErrors` those `laminapdf-save` adds (including `sink-not-empty`), `textErrors`/`textWarnings` those of `laminapdf-text`, `buildErrors` those of `laminapdf-build` and `facadeErrors` those of the `laminapdf` façade (`cancelled`, `job-finished`, `document-changed`), `bindingErrors` those of `laminapdf-wasm` and `packageErrors` those only `@laminapdf/sdk` raises (left out of the Rust enums and the WASM); each entry is `{ "code", "kind", "summary", "hint", "since" }` (a retired code adds `"retired": "<version>"` and stays listed). `kind` is one of ADR 0026 §2's nine; `summary` says what happened and `hint` what to do, both one lowercase sentence without document text, the hint with no parameters other than `{limit}` and `{option}`; `since` is the first release that emits the code. `limits` is a list of names, `docsUrl` the one base and suffix of every code's page (`docs/errors/<code>.md`). `codes.schema.json` is the file's JSON Schema (2020-12): `cargo xtask gen codes` validates `codes.json` against it, then generates every surface's tables from it (the façade's `ErrorCode`/`WarningCode`, `@laminapdf/sdk`'s unions, kinds, hints and explain text, the `laminapdf.error/1` schema, the tables of `docs/errors/README.md`); `cargo xtask check docs` fails when one is stale. It is the single source of truth: `crates/laminapdf-cos/tests/codes.rs` checks every group (each entry complete, its page present with the fixed headings and kind line, no page without a code); it, `crates/laminapdf-ops/tests/serde.rs`, `crates/laminapdf-save/tests/codes.rs` and `crates/laminapdf-text/tests/codes.rs` check the Rust enums' codes against it, and each crate's unit tests check every variant's `kind()` against it (`laminapdf_test_fixtures::codes`); `packages/sdk/test/codes.test.ts` checks the generated TS tables against it. A new group a crate adds is checked the same way. Codes are never renamed or reused.
- `corpus-manifest.toml` pins the **external corpora** (ADR 0018 §3) that the nightly lane reads: per source a git repository, commit, licence, licence file and sparse-checkout patterns, then every file's path, size and SHA-256. The files themselves are never committed, not even minimised: `cargo xtask corpus fetch [--source <name>]` checks them out into the gitignored `target/corpus/<name>/` (or `$LAMINA_PDF_CORPUS_DIR`) and fails on any missing, changed or unlisted file; `--update-manifest` rewrites the lists after a commit bump. Sources today: pdf.js `test/pdfs` and the PDFBox repository's PDFs (both Apache-2.0, the commits the hayro-parity spike used), PDFium `testing/resources` (BSD-3-Clause) and qpdf `qpdf/qtest/qpdf` (Apache-2.0); 2,172 files, 177 MB. A regression found in them is re-created synthetically here.
- Fixtures are data: Biome skips this folder, so files stay byte-for-byte as generated.

## Licence

Every file here was generated by Lamina PDF's own scripts, which are in the repository, and is licensed like the rest of Lamina PDF, `MIT OR Apache-2.0`. There are three exceptions. The DejaVu Sans subset in each copy of `text-example.pdf` keeps its [Bitstream Vera / DejaVu licence](fonts/DejaVu-LICENSE.txt). `fonts/` holds subsets of Noto fonts, which stay under the [SIL Open Font License 1.1](fonts/OFL.txt) (see [`fonts/`](#fonts) below). `unicode/` holds subsets of Unicode Character Database test files, which stay under the [Unicode License v3](https://www.unicode.org/license.txt) (`Unicode-3.0`, see [`unicode/`](#unicode) below). The Noto font subsets embedded in the `golden/text-*.pdf` files are under the OFL 1.1 too, which allows embedding them in documents. Where a file was written by a third-party library (pdf-lib, fpdf2, ReportLab, pypdf, pyHanko), the library only serialized content our script supplied; none of their code or assets are embedded, apart from the font subset noted for `text-example.pdf`.

`golden/xmp/` holds XMP packets for `laminapdf_model::xmp` (todo E1b), each an input with the outputs of edits made to it. Every input was written by hand for Lamina PDF and is `MIT OR Apache-2.0`. None of them was produced by the tool it is named after. No committed PDF has a packet from these producers, only the builder's own. None of these tools could make a file here either: Ghostscript, pdfTeX and LibreOffice weren't installed, and Acrobat and Word can't be run from a script. Each packet is therefore modelled on the layout that producer is documented or widely observed to write. Names, dates and IDs are made up.

| File | Modelled on | What it exercises |
| --- | --- | --- |
| `acrobat.xmp` | Adobe Acrobat and the Adobe PDF Library as InDesign exports through them: one `rdf:Description` declaring every namespace, three-space indentation, `xmpMM:History` of `rdf:parseType="Resource"` events, a `dc:title` with a second language, 2 KB of padding in lines of 100 spaces | Element form, a structure, language alternatives, padding |
| `word.xmp` | Microsoft Word's Save as PDF: one `rdf:Description` per namespace, properties on one line, padding inside `rdf:RDF`, no white space before `<?xpacket end="w"?>` | Several descriptions, no padding where the writer pads |
| `libreoffice.xmp` | LibreOffice's PDF/A export: one description per schema, `pdfaid` first, no padding | PDF/A identification, a packet with no padding |
| `pdftex.xmp` | pdfTeX with the `pdfx` package (PDF/A-1b): a `pdfaExtension` schema declaring a `pdfx:` property, a comment, single-quoted `xpacket` attributes | An extension schema, a comment, quotes |
| `ghostscript.xmp` | Ghostscript's `pdfwrite`: single quotes, `rdf:about` set to a UUID, the `xapMM` prefix for the media-management namespace, properties in attribute form on empty descriptions, the `adobe-xap-filters` processing instruction | Attribute form, prefixes that differ from the standard ones |
| `utf16.xmp` | A UTF-16BE packet with a byte-order mark | Reading UTF-16, the canonical rewrite |
| `invalid-dtd.xmp` | A packet with a DTD defining a billion-laughs entity and an external one | Refusing a DTD (`xmp-invalid`) |

The outputs are:

- `<input>.title.xmp`: the title set to `Edited title`;
- `ghostscript.producer.xmp`: an attribute-form value changed and a list added;
- `libreoffice.fields.xmp`: authors, keywords and a date added, the subject removed;
- `utf16.title.xmp`: rewritten whole, since the input isn't UTF-8;

### `reading-order/`

The reading-order corpus (todo [U2b](../docs/todos/done/U2b-reading-order-ground-truth.md)): 28 files from 14 layouts, generated by `crates/laminapdf-build/tests/common/reading_order.rs` (its `reading_order` example; `cargo xtask golden --update` rewrites them, `cargo xtask golden` and `crates/laminapdf-build/tests/reading_order.rs` check them). Licensed like the rest of Lamina PDF; the fonts are the OFL Noto subsets in `fonts/`. Each layout's blocks (page, role, text, box) are listed in reading order, the box being the block's `text_box` rectangle in page space (x, y, width, height); every block is one `text_box`, so the ground truth is the generator's, with no hand annotation. Each layout is written twice: `-ordered` (drawn in reading order) and `-reversed` (drawn last block first on each page), since an extractor that follows the content stream gets the first right for free.

| File | Origin | Exercises |
| --- | --- | --- |
| `<layout>-{ordered,reversed}.pdf` | the generator above | `one-column`, `two-columns`, `three-columns` (a newspaper), `paper` (title, authors, abstract, two columns, figure caption, footnote), `sidebar`, `table` (3 × 3 cells, row by row), `header-footer` (two pages), `rotated` (`/Rotate 90`), `arabic`, `hebrew-two-columns` (right column first), `chinese` (horizontal); and three hard layouts that `laminapdf-extract` reads out of order and warns about with `extract-column-order-uncertain`: `pull-quote` (a boxed quote over the gutter, the columns wrapping round it), `narrow-gutter` (two columns 7 pt apart, the left set flush right) and `wrapped-grid` (an unruled 3 × 3 grid with one cell on two lines, read row by row) |
| `<layout>-{ordered,reversed}.json` | the generator above | `{ file, layout, about, drawn, method, blocks: [{ page, role, text, box }] }`, blocks in reading order; roles `heading`, `paragraph`, `caption`, `footnote`, `header`, `footer`, `table-cell` |
| `threshold.json` | Hand-kept | The ratchet: `crates/laminapdf/tests/reading_order.rs` fails when the corpus mean is below `mean`, or above it by more than 0.005 (raise it with the change that raised the score); `history` records each value |

The metric (defined in `crates/laminapdf/tests/reading_order.rs`): text is tokenized once per file (words, or characters when no block has a space); extracted lines are split into the longest stretches that occur in one block as whole tokens and assigned to it; **order** is 1 − (Levenshtein distance between the sequence of blocks met and 0 … n−1) / the longer length; **text** is the mean per block of 1 − character Levenshtein distance / the longer length; a file's **score** is their mean, the corpus score the mean over files. First run (B9d's content-order extraction, 2026-10-30): mean **0.787**. Every `-ordered` file scores 1.000; the `-reversed` files lose order (0.000–0.333) and keep their text (1.000), except `table-reversed` (text 0.572: cells drawn right to left on one baseline came out joined without a space). ### `encrypted/`

Standard security handler fixtures (todo B2b), generated from one plaintext original by [`encrypted/make.py`](encrypted/make.py) and described by [`encrypted/facts.py`](encrypted/facts.py). Checked by `crates/laminapdf-cos/tests/encryption.rs`: every file opens with its user password, its owner password and (for `-empty` files) no password, and matches `expected.json` and the decoded content of `source.pdf` byte for byte.

```sh
python3 -m venv .venv && .venv/bin/pip install pypdf==6.21.3 cryptography==50.0.2
.venv/bin/python fixtures/encrypted/make.py    # needs qpdf >= 11.7 on PATH (generated with qpdf 12.4.2)
.venv/bin/python fixtures/encrypted/facts.py   # rewrites encrypted/expected.json
```

`make.py` also copies the encrypted files to `fuzz/seeds/open/encrypted/` and their passwords to `fuzz/seeds/open/passwords.txt` for the `open` fuzz target (B2c). The files are not byte-reproducible (qpdf uses random IVs and R6 salts); the facts are. Each qpdf output's `/V` and `/R` is checked with `qpdf --show-encryption`, and the script fails if a case comes out at the wrong revision.

| File | How it is made | Exercises |
| --- | --- | --- |
| `source.pdf` | `make.py` (no dependencies) | The plaintext original: Info strings (one UTF-16), an outline with a nested and a UTF-16 title, XMP metadata, two pages of Flate text, a text annotation with `/Contents` |
| `r2-rc4-40-{empty,user}.pdf` | `qpdf --allow-weak-crypto --encrypt … --bits=40 --` | V1/R2, RC4 40-bit, Algorithms 2, 4, 7 |
| `r3-rc4-128-{empty,user}.pdf` | `qpdf --allow-weak-crypto --encrypt … --bits=128 --use-aes=n --` | V2/R3, RC4 128-bit, Algorithms 5–7 |
| `r4-rc4-128-{empty,user}.pdf` | `qpdf --allow-weak-crypto --encrypt … --bits=128 --use-aes=n --force-V4 --` | V4/R4 with a `/V2` crypt filter (differs from R3) |
| `r4-aes-128-{empty,user}.pdf` | `qpdf --encrypt … --bits=128 --use-aes=y -- --object-streams=generate` | V4/R4 `/AESV2`; encrypted object streams |
| `r4-aes-128-cleartext-metadata-{empty,user}.pdf` | `qpdf --encrypt … --bits=128 --use-aes=y --cleartext-metadata --` | `/EncryptMetadata false`: XMP stored and read as plaintext, the rest decrypted |
| `r5-aes-256-{empty,user}.pdf` | `qpdf --encrypt … --bits=256 --force-R5 --` | V5/R5 (Adobe Extension Level 3, never standardised; read only), `/Perms` |
| `r6-aes-256-{empty,user}.pdf` | `qpdf --encrypt … --bits=256 -- --object-streams=generate` | V5/R6 Algorithm 2.B, `/Perms`, a UTF-8 user password (`Pässwört-6`, SASLprep), object streams |
| `identity-stmf.pdf` | `make.py` (AES-128 via pypdf's Algorithms 2/3/5 and `cryptography`) | `/StmF /Identity` with AESV2 strings; one stream selecting `/StdCF` through `/Filter [/Crypt …]` |
| `crypt-filter-identity.pdf` | `make.py`, as above | `/StmF /StdCF`; one stream left plaintext with `/Crypt` `/Name /Identity` |
| `r6-aes-256-same.pdf` | `qpdf --encrypt --user-password=same-pw --owner-password=same-pw --bits=256 --` | A password that is both user and owner is reported as the owner's (ISO 32000-2 Algorithm 2.A) |
| `v4-aes-128-cf-length.pdf` | `make.py` | V4 AESV2 with top-level `/Length 40` and `/CF/StdCF/Length 16`: the key length comes from the crypt filter (qpdf 12 reads the top-level one and can't open it) |
| `v4-rc4-40-cf-length.pdf` | `make.py` | V4 `/V2` with no top-level `/Length` and `/CF/StdCF/Length 5` (bytes): a 40-bit key |
| `objstm-catalog-aes-128.pdf` | `make.py` | The catalog inside an encrypted object stream, with an xref stream: repair has to decrypt the object stream to find `/Root` |
| `objstm-bad-padding-aes-128.pdf` | `make.py` | Damaged on purpose: the object stream's AES padding is invalid (`aes-padding-invalid`); listed under `damaged` in `passwords.json`, not in `expected.json` |
| `passwords.json` | `make.py` | Each file's user and owner password (read by `facts.py`) |
| `expected.json` | `facts.py`: pypdf 6.21.3 (page count, outline titles, Info, `/V`, key length from `/Length` or `/CF`) and qpdf (`--show-encryption` permissions, `/P`, `/R`; content and XMP hashes over a `qpdf --decrypt` copy, since pypdf can't decode a named `/Crypt` filter). For the two `/CF`-length files qpdf can't open, pypdf alone, with `/P` read by qpdf's permission rules | Facts checked by `tests/encryption.rs` |

`-empty` files have an empty user password and owner password `owner-pw`; `-user` files have user password `user-pw` (R5/R6: `Pässwört-6`), owner password `owner-pw` and some permissions cleared.
