# Fixtures

Shared test inputs and golden outputs, read by every implementation by path from the repository root ([code organization §6](../docs/guidelines/code-organization.md#6-tests-and-fixtures)). Today the Rust tests in `crates/lamina-cos/tests/` use them; future TypeScript and binding tests read the same files.

These files were moved here from the [`pdf-basics` spike](../spikes/pdf-basics/SPEC.md) in Round A. The spike keeps its own frozen copy in `spikes/pdf-basics/fixtures/`, so the two copies are identical today but only this one may change.

## Rules

- Every file is listed below with its origin, licence and what it exercises. A PDF without a known licence is not committed.
- `golden/` files are byte-exact expected outputs. Tests never rewrite them; a change is regenerated by an explicit command and reviewed like code.
- `corpus/expected.json` holds facts that every implementation must reproduce, extracted independently with pypdf, never by lamina (`page_count`, `encrypted`, `revisions` as the count of `%%EOF`, `has_xref_stream`, `first_page_mediabox`, `root_keys`, `header_version`, `size`, and `outline_titles` flattened depth-first). It is written by [`tools/corpus-facts/facts.py`](../tools/corpus-facts/facts.py) (`cargo xtask corpus facts`, with the pinned pypdf from its `requirements.txt` in `$LAMINA_PYTHON` or `python3`); the script reads and writes only `corpus/`. Deliberate differences go in `corpus/exceptions.toml`, each with the ADR 0003 rule behind lamina's answer.
- `encrypted/expected.json` holds the facts for the encrypted fixtures, written by `encrypted/facts.py` from pypdf and qpdf (never lamina). It is the single source of truth for `encrypted/`; `corpus/expected.json` never lists those files, so corpus regeneration (B2c) and the encrypted set don't overwrite each other.
- `differential/expected.json` holds pypdf's outcome (opened/repaired/failed), page count and outline titles for every corpus file and its fixed-seed mutants (generated by `crates/lamina-model/tests/common/mutants.rs`); `cargo xtask differential --update` regenerates it, and `crates/lamina-model/tests/differential.rs` compares lamina against it without Python. Triaged disagreements are in `differential/exceptions.toml`; its `[[class]]` and `[[known]]` entries are read only by the nightly lane's live differential (`cargo xtask differential --live`), which also compares 250 mutants per corpus file and the external corpus with pdf.js, PDFium, qpdf and pypdf.
- `regressions/<target>/` (created with the first one) holds minimised fuzz crashes as raw `<hash>` files, replayed through the target's entry point by `crates/lamina-model/tests/regressions.rs`, each also with a named regression test ([`fuzz/README.md`](../fuzz/README.md)).
- Goldens are regenerated only by `cargo xtask golden --update`, which rebuilds every file in `golden/` from its source and prints the list; `cargo xtask golden` checks that nothing would change.
- `codes.json` lists every warning code, error code and hard-limit name that lamina exposes ([ADR 0003](../docs/decisions/0003-reader-tolerance-and-limits.md) §4). It is the single source of truth: `crates/lamina-cos/tests/codes.rs` checks the Rust enums against it, and the TypeScript package will too. Codes are never renamed or reused.
- `corpus-manifest.toml` pins the **external corpora** (ADR 0018 §3) that the nightly lane reads: per source a git repository, commit, licence, licence file and sparse-checkout patterns, then every file's path, size and SHA-256. The files themselves are never committed, not even minimised: `cargo xtask corpus fetch [--source <name>]` checks them out into the gitignored `target/corpus/<name>/` (or `$LAMINA_CORPUS_DIR`) and fails on any missing, changed or unlisted file; `--update-manifest` rewrites the lists after a commit bump. Sources today: pdf.js `test/pdfs` and the PDFBox repository's PDFs (both Apache-2.0, the commits the hayro-parity spike used), PDFium `testing/resources` (BSD-3-Clause) and qpdf `qpdf/qtest/qpdf` (Apache-2.0); 2,172 files, 177 MB. A regression found in them is re-created synthetically here.
- Fixtures are data: Biome skips this folder, so files stay byte-for-byte as generated.

## Licence

Every file here was generated by lamina's own scripts, which are in the repository, and is licensed like the rest of lamina, `MIT OR Apache-2.0`. Where a file was written by a third-party library (pdf-lib, fpdf2, ReportLab, pypdf, pyHanko), the library only serialized content our script supplied; none of their code or assets are embedded, apart from the font subset noted for `text-example.pdf`.

### `encrypted/`

Standard security handler fixtures (todo B2b), generated from one plaintext original by [`encrypted/make.py`](encrypted/make.py) and described by [`encrypted/facts.py`](encrypted/facts.py). Checked by `crates/lamina-cos/tests/encryption.rs`: every file opens with its user password, its owner password and (for `-empty` files) no password, and matches `expected.json` and the decoded content of `source.pdf` byte for byte.

```sh
python3 -m venv .venv && .venv/bin/pip install pypdf==6.21.3 cryptography==50.0.2
.venv/bin/python fixtures/encrypted/make.py    # needs qpdf >= 11.7 on PATH (generated with qpdf 12.4.2)
.venv/bin/python fixtures/encrypted/facts.py   # rewrites encrypted/expected.json
```

`make.py` also copies the encrypted files to `fuzz/seeds/open/encrypted/` and their passwords to `fuzz/seeds/open/passwords.txt` for the `open` fuzz target (B2c). The files are not byte-reproducible (qpdf uses random IVs and R6 salts); the facts are. Each qpdf output's `/V` and `/R` is checked with `qpdf --show-encryption`, and the script fails if a case comes out at the wrong revision.

| File | How it is made | Exercises |
| --- | --- | --- |
| `source.pdf` | `make.py` (no dependencies) | The plaintext original: Info strings (one UTF-16), an outline with a nested and a UTF-16 title, XMP metadata, two pages of Flate text, a text annotation with `/Contents` |
| `r2-rc4-40-{empty,user}.pdf` | `qpdf --allow-weak-crypto --encrypt … --bits=40 --` | V1/R2, RC4 40-bit, Algorithms 2, 4, 7 |
| `r3-rc4-128-{empty,user}.pdf` | `qpdf --allow-weak-crypto --encrypt … --bits=128 --use-aes=n --` | V2/R3, RC4 128-bit, Algorithms 5–7 |
| `r4-rc4-128-{empty,user}.pdf` | `qpdf --allow-weak-crypto --encrypt … --bits=128 --use-aes=n --force-V4 --` | V4/R4 with a `/V2` crypt filter (differs from R3) |
| `r4-aes-128-{empty,user}.pdf` | `qpdf --encrypt … --bits=128 --use-aes=y -- --object-streams=generate` | V4/R4 `/AESV2`; encrypted object streams |
| `r4-aes-128-cleartext-metadata-{empty,user}.pdf` | `qpdf --encrypt … --bits=128 --use-aes=y --cleartext-metadata --` | `/EncryptMetadata false`: XMP stored and read as plaintext, the rest decrypted |
| `r5-aes-256-{empty,user}.pdf` | `qpdf --encrypt … --bits=256 --force-R5 --` | V5/R5 (Adobe Extension Level 3, never standardised; read only), `/Perms` |
| `r6-aes-256-{empty,user}.pdf` | `qpdf --encrypt … --bits=256 -- --object-streams=generate` | V5/R6 Algorithm 2.B, `/Perms`, a UTF-8 user password (`Pässwört-6`, SASLprep), object streams |
| `identity-stmf.pdf` | `make.py` (AES-128 via pypdf's Algorithms 2/3/5 and `cryptography`) | `/StmF /Identity` with AESV2 strings; one stream selecting `/StdCF` through `/Filter [/Crypt …]` |
| `crypt-filter-identity.pdf` | `make.py`, as above | `/StmF /StdCF`; one stream left plaintext with `/Crypt` `/Name /Identity` |
| `r6-aes-256-same.pdf` | `qpdf --encrypt --user-password=same-pw --owner-password=same-pw --bits=256 --` | A password that is both user and owner is reported as the owner's (ISO 32000-2 Algorithm 2.A) |
| `v4-aes-128-cf-length.pdf` | `make.py` | V4 AESV2 with top-level `/Length 40` and `/CF/StdCF/Length 16`: the key length comes from the crypt filter (qpdf 12 reads the top-level one and can't open it) |
| `v4-rc4-40-cf-length.pdf` | `make.py` | V4 `/V2` with no top-level `/Length` and `/CF/StdCF/Length 5` (bytes): a 40-bit key |
| `objstm-catalog-aes-128.pdf` | `make.py` | The catalog inside an encrypted object stream, with an xref stream: repair has to decrypt the object stream to find `/Root` |
| `objstm-bad-padding-aes-128.pdf` | `make.py` | Damaged on purpose: the object stream's AES padding is invalid (`aes-padding-invalid`); listed under `damaged` in `passwords.json`, not in `expected.json` |
| `passwords.json` | `make.py` | Each file's user and owner password (read by `facts.py`) |
| `expected.json` | `facts.py`: pypdf 6.21.3 (page count, outline titles, Info, `/V`, key length from `/Length` or `/CF`) and qpdf (`--show-encryption` permissions, `/P`, `/R`; content and XMP hashes over a `qpdf --decrypt` copy, since pypdf can't decode a named `/Crypt` filter). For the two `/CF`-length files qpdf can't open, pypdf alone, with `/P` read by qpdf's permission rules | Facts checked by `tests/encryption.rs` |

`-empty` files have an empty user password and owner password `owner-pw`; `-user` files have user password `user-pw` (R5/R6: `Pässwört-6`), owner password `owner-pw` and some permissions cleared.
