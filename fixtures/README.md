# Fixtures

Shared test inputs and golden outputs, read by every implementation by path from the repository root ([code organization §6](../docs/guidelines/code-organization.md#6-tests-and-fixtures)). Today the Rust tests in `crates/*/tests/` use them; future TypeScript and binding tests read the same files.

These files were moved here from the [`pdf-basics` spike](../spikes/pdf-basics/SPEC.md) in Round A. The spike keeps its own frozen copy in `spikes/pdf-basics/fixtures/`, so the two copies are identical today but only this one may change.

## Rules

- Every file is listed below with its origin, licence and what it exercises. A PDF without a known licence is not committed.
- `golden/` files are byte-exact expected outputs. Tests never rewrite them; a change is regenerated by an explicit command and reviewed like code.
- `corpus/expected.json` holds facts that every implementation must reproduce, extracted independently with pypdf, never by lamina (`page_count`, `encrypted`, `revisions` as the count of `%%EOF`, `has_xref_stream`, `first_page_mediabox`, `root_keys`, `header_version`, `size`, and `outline_titles` flattened depth-first). It is written by [`tools/corpus-facts/facts.py`](../tools/corpus-facts/facts.py) (`cargo xtask corpus facts`, with the pinned pypdf from its `requirements.txt` in `$LAMINA_PYTHON` or `python3`); the script reads and writes only `corpus/`. Deliberate differences go in `corpus/exceptions.toml`, each with the ADR 0003 rule behind lamina's answer.
- `encrypted/expected.json` holds the facts for the encrypted fixtures, written by `encrypted/facts.py` from pypdf and qpdf (never lamina). It is the single source of truth for `encrypted/`; `corpus/expected.json` never lists those files, so corpus regeneration (B2c) and the encrypted set don't overwrite each other.
- `differential/expected.json` holds pypdf's outcome (opened/repaired/failed), page count and outline titles for every corpus file and its fixed-seed mutants (generated by `crates/lamina-model/tests/common/mutants.rs`); `cargo xtask differential --update` regenerates it, and `crates/lamina-model/tests/differential.rs` compares lamina against it without Python. Triaged disagreements are in `differential/exceptions.toml`. The full lane's set (36 mutants per corpus file) has its own `differential/full.json` and `full-exceptions.toml` (`cargo xtask differential --full [--update]`). Its `[[class]]` and `[[known]]` entries are read only by the nightly lane's live differential (`cargo xtask differential --live`), which compares the external corpus and every mutant (250 of the fast set's series and the full set's 36 per corpus file) with pdf.js, PDFium, qpdf and pypdf, applying both exceptions files.
- `corpus/pdfjs-operators.json` holds pdf.js's operator counts (`getOperatorList`, annotations off, `dependency` operators left out) for every page of `corpus/`, `golden/` and `content/`, written by [`tools/corpus-facts/pdfjs-operators.mjs`](../tools/corpus-facts/pdfjs-operators.mjs) with the pinned pdfjs-dist (Apache-2.0; tools only), never by lamina. `crates/lamina-content/tests/corpus.rs` maps lamina's operators to pdf.js's names ([ADR 0023](../docs/decisions/0023-content-stream-reading.md) §6) and compares; pages lamina can't interpret yet are in `corpus/pdfjs-exceptions.toml`, each with its error code and ADR 0003 rule.
- `regressions/<target>/` (created with the first one) holds minimised fuzz crashes as raw `<hash>` files, replayed through the target's entry point by `crates/lamina-model/tests/regressions.rs` (`content`: `crates/lamina-content/tests/regressions.rs`; `ops_json` and `save_roundtrip`: `crates/lamina-save/tests/regressions.rs`), each also with a named regression test ([`fuzz/README.md`](../fuzz/README.md)).
- Goldens are regenerated only by `cargo xtask golden --update`, which rebuilds every file in `golden/` from its source and prints the list; `cargo xtask golden` checks that nothing would change.
- `ops/v1/` holds frozen JSON samples of version 1 of the op format ([ADR 0006](../docs/decisions/0006-op-log-and-undo.md) §6). They are hand-written, never rewritten by a test, and stay loadable when a later version is added (a new version gets its own `ops/vN/`).
- `codes.json` (v2, [ADR 0026](../docs/decisions/0026-error-and-diagnostic-contract.md)) lists every warning code, error code and hard-limit name that lamina exposes ([ADR 0003](../docs/decisions/0003-reader-tolerance-and-limits.md) §4). `warnings` and `errors` hold the reader's codes, `opErrors` those `lamina-ops` adds and `saveErrors` those `lamina-save` adds (including `sink-not-empty`), and `textErrors`/`textWarnings` those of `lamina-text`; each entry is `{ "code", "kind", "summary", "hint", "since" }` (a retired code adds `"retired": "<version>"` and stays listed). `kind` is one of ADR 0026 §2's nine; `summary` says what happened and `hint` what to do, both one lowercase sentence without document text, the hint with no parameters other than `{limit}` and `{option}`; `since` is the first release that emits the code. `limits` is a list of names, `docsUrl` the one base and suffix of every code's page (`docs/errors/<code>.md`). It is the single source of truth: `crates/lamina-cos/tests/codes.rs` checks every group (each entry complete, its page present with the fixed headings and kind line, no page without a code); it, `crates/lamina-ops/tests/serde.rs`, `crates/lamina-save/tests/codes.rs` and `crates/lamina-text/tests/codes.rs` check the Rust enums' codes against it, and each crate's unit tests check every variant's `kind()` against it (`crates/lamina-cos/tests/common/codes.rs`); the TypeScript package will too. A new group a crate adds is checked the same way. Codes are never renamed or reused.
- `corpus-manifest.toml` pins the **external corpora** (ADR 0018 §3) that the nightly lane reads: per source a git repository, commit, licence, licence file and sparse-checkout patterns, then every file's path, size and SHA-256. The files themselves are never committed, not even minimised: `cargo xtask corpus fetch [--source <name>]` checks them out into the gitignored `target/corpus/<name>/` (or `$LAMINA_CORPUS_DIR`) and fails on any missing, changed or unlisted file; `--update-manifest` rewrites the lists after a commit bump. Sources today: pdf.js `test/pdfs` and the PDFBox repository's PDFs (both Apache-2.0, the commits the hayro-parity spike used), PDFium `testing/resources` (BSD-3-Clause) and qpdf `qpdf/qtest/qpdf` (Apache-2.0); 2,172 files, 177 MB. A regression found in them is re-created synthetically here.
- Fixtures are data: Biome skips this folder, so files stay byte-for-byte as generated.

## Licence

Every file here was generated by lamina's own scripts, which are in the repository, and is licensed like the rest of lamina, `MIT OR Apache-2.0`. The exception is `fonts/`: subsets of Noto fonts under the [SIL Open Font License 1.1](fonts/OFL.txt) (see [`fonts/`](#fonts) below); the font subsets embedded in the `golden/text-*.pdf` files are under the same licence, which allows embedding them in documents. Where a file was written by a third-party library (pdf-lib, fpdf2, ReportLab, pypdf, pyHanko), the library only serialized content our script supplied; none of their code or assets are embedded, apart from the font subset noted for `text-example.pdf`.

### `encrypted/`

Standard security handler fixtures (todo B2b), generated from one plaintext original by [`encrypted/make.py`](encrypted/make.py) and described by [`encrypted/facts.py`](encrypted/facts.py). Checked by `crates/lamina-cos/tests/encryption.rs`: every file opens with its user password, its owner password and (for `-empty` files) no password, and matches `expected.json` and the decoded content of `source.pdf` byte for byte.

```sh
python3 -m venv .venv && .venv/bin/pip install pypdf==6.21.3 cryptography==50.0.2
.venv/bin/python fixtures/encrypted/make.py    # needs qpdf >= 11.7 on PATH (generated with qpdf 12.4.2)
.venv/bin/python fixtures/encrypted/facts.py   # rewrites encrypted/expected.json
```

`make.py` also copies the encrypted files to `fuzz/seeds/open/encrypted/` and their passwords to `fuzz/seeds/open/passwords.txt` for the `open` fuzz target (B2c). The files are not byte-reproducible (qpdf uses random IVs and R6 salts); the facts are. Each qpdf output's `/V` and `/R` is checked with `qpdf --show-encryption`, and the script fails if a case comes out at the wrong revision.
