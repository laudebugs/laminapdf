# laminapdf-save

Saving PDFs ([ADR 0007](../../docs/decisions/0007-save-planner.md), [ADR 0005](../../docs/decisions/0005-document-model.md) §3): the save planner that decides how a document may be saved, the writers that turn a document's overlay ([`laminapdf-cos`](../laminapdf-cos/README.md)) into bytes, the sinks they stream to, and the rebase that makes the output the new base of a [`laminapdf-ops`](../laminapdf-ops/README.md) document. Part of Lamina PDF's pure core: bytes in, bytes out.

- **`SavePlanner`** (§1–§4): `SaveConstraint { signatures, doc_mdp, rewrite_reasons, violations }` and its `kind()` (`Free`, `AppendOnly`, `RequiresRewrite`, `Conflict`), detected from the base and the overlay: signature fields with a `/V` dictionary (`/Kids` followed, `/FT` inherited), `/Perms /DocMDP` and `/UR3`, `/Reference` transforms (DocMDP `/P`, FieldMDP, UR3 rights), `/Lock`, `/Type /DocTimeStamp`, and in a repaired base every object; rewrite reasons (`RepairedBase`, `EncryptedBase`, `NoBase`, `OpRequiresRewrite`); `signatures_unknown` when part of the form can't be followed; violations from `laminapdf_ops::Document::pending_changes()`. `plan(&options)` resolves `SaveMode::Auto` and checks a requested mode per §3's table (`SavePlan::resolve` is the table alone), `would_invalidate()`, and `would_violate(&op)` for the editor. Refusals: `SaveError::WouldInvalidateSignatures` (the whole constraint), `RequiresRewrite`, `EncryptedBase` (every mode without `remove_encryption`). Overrides, off by default: `SaveOptions::with_invalidate_signatures` (the writers write the output with the invalidated `/V` and `/Perms` entries removed, direct ones included; `SaveReport::invalidated`) and `with_remove_encryption` (a plaintext full rewrite, `/ID[0]` kept; `SaveReport::encryption_removed`).
- **`IncrementalWriter`** (§7.5.6): the base bytes unchanged, copied from the `ByteSource` in 64 KiB chunks. A windowed base is read twice: once before anything is written (every missing range reported in one `DataPending`, and the base hashed for `/ID`), then to copy it. Then the overlay in number order (new objects generation 0, modified ones their base generation, deleted ones free entries with the generation incremented, linked in front of the base's free list), then a section of the base's newest kind (classic table, or an xref stream numbered with the next free number within `Limits::max_object_number`) with `/Prev`, `/Size` never below the base's or any reserved number, and the trailer's document keys (xref-section and xref-stream keys such as `/DL`, `/F` dropped). `IncrementalOutput::AppendedOnly` writes only the revision. With an empty overlay the base is written unchanged and the report has no append offset (even for a repaired or encrypted base); otherwise repaired (`RepairedBase`) and encrypted (`EncryptedBase`) bases are refused.
- **`FullWriter`**: only what the trailer's document keys reach, `/ID` excepted (iterative walk, nesting checked against `Limits::max_nesting_depth` the way the parser counts it; dangling and stale references become `null`; an object that can't be loaded fails the save); `Renumber::Keep` (default: numbers and generations kept, so `LaminaPdfId`s stay; base objects not written become free entries with the next generation) or `Renumber::Compact` (`1..=n`, with the old → new map in the report). The xref lists only numbers that hold something, so its size follows the data, not the input's `/Size`. Flate object streams of up to 100 members plus an xref stream (default, header raised to 1.5) or `XrefKind::Classic`. Every object is loaded and every number allocated before the first byte is written. Refuses encrypted bases unless the options remove the encryption (objects as decrypted, a leading `/Crypt` filter and `/Encrypt` dropped).
- **`/ID`** (§14.4): `/ID[0]` kept by every save (direct or indirect), `/ID[1]` the first 16 bytes of a SHA-256 of the content written (for an incremental save: the base and the revision up to its trailer); both derived the same way when the document has none.
- **Sinks**: `WriteSink` (append only, never seeks; `held()` lets a writer refuse a sink that already holds bytes, `SinkError::NotEmpty`), `ReadableSink::into_source` (for rebasing), impls for `Vec<u8>` (readable) and `IoWrite<W: std::io::Write>`, `CountingSink`. `SinkError`.
- **`Save`** on `laminapdf_ops::Document`: `plan(&options)`, `save(&mut sink, &options)` (plans, then writes; an incremental save rebases onto old base ‖ revision, built in memory, or chained without a copy for a windowed base; a full rewrite to a write-only sink leaves the document `SavedNotRebased` until `laminapdf_ops::Document::rebase(source)`) and `save_and_rebase(sink, &options)` (to a `ReadableSink`). States `Clean | Dirty | SavedNotRebased` (`laminapdf_ops::SaveState`): saves and ops are refused in `SavedNotRebased` and while a transaction is open. A failure before or while writing leaves the document `Dirty` with its overlay untouched; a rebase that fails after a complete write leaves it `SavedNotRebased` with the output in `SaveError::NotRebased` to retry with. The undo history survives only an incremental save that freed nothing (`PendingRebase::KeepHistory`); a full rewrite or deletions clear it, since undo could restore references to objects that are gone. `SaveOptions` (`mode`, `invalidate_signatures`, `remove_encryption`, `output`, `renumber`, `xref`, `eol`) and `SaveReport` (bytes written, mode, renumber map, append offset, invalidated signatures, encryption removed).
- **`test_support::{Writer, incremental_update}`** (feature `test-support`, off by default): the spike-era writer, moved from `laminapdf-cos` in B3b with its tests, which builds files from scratch for the workspace's tests and doc examples. It writes through the same xref-table, xref-stream, object-stream and header helpers as the two writers above (Q2d), so there is one serialiser; the crate's own tests turn the feature on through a dev-dependency on the crate itself. `XrefEol` belongs to `SaveOptions`.

Output is byte-deterministic (ADR 0001): ordered maps only, no clocks, `/ID` from a hash. Determinism is tested by save-twice tests for each writer and layout and by the property test, which saves every case twice.

Tests (`tests/`, reading the shared [`fixtures/`](../../fixtures/README.md)): moved from `laminapdf-cos` with the writer: `golden.rs` (byte-exact goldens: the frozen `hello.pdf` and `imaging-demo.pdf`, and `incremental-set-info.pdf` and `full-rewrite-hello.pdf`), `determinism.rs`, `incremental.rs`, `raw_writer.rs`, `content_builder.rs` (the spike's content builder), `roundtrip.rs` and the writer half of `review_fixes.rs`; new: `overlay_incremental.rs`, `full_rewrite.rs` (also every unencrypted corpus file in each layout), `rebase.rs`, `id.rs`, `sink_errors.rs`, `codes.rs` and `props.rs`; B3c: `constraint.rs` (detection over `fixtures/signed/` and the corpus), `planner.rs` (every row of the mode table, and on files), `override.rs`, `encrypted_base.rs` (every encrypted fixture: refusals and the plaintext rewrite), `undo_bytes.rs`, `roundtrip_suite.rs` (the Lamina PDF half of `cargo xtask roundtrip`) and `regressions.rs` (the `ops_json` and `save_roundtrip` fuzz entries over their seeds and saved crashes) (proptest, fixed seed: random ops → every writer → reopen gives the in-memory facts, twice the same bytes). `tests/common/` holds the frozen goldens' builders (`legacy.rs`, with the spike's content builder `content.rs`), the edited golden samples and the save helpers; the hand-built files and fixtures come from `laminapdf-test-fixtures`. `examples/golden.rs` writes its four goldens for `cargo xtask golden --update` and `examples/roundtrip.rs` the outputs `cargo xtask roundtrip` checks with qpdf, pdf.js and PDFium.

`laminapdf-cos`, `laminapdf-model` and `laminapdf-ops` use this crate as a dev-dependency to build their test inputs (a cycle Cargo accepts for integration tests; `laminapdf-cos`'s own unit tests build files with `tests/common/classic.rs` instead).

```sh
cargo test -p laminapdf-save
```
