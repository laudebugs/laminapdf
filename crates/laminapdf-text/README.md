# laminapdf-text

Fonts and text layout for generated PDFs, and text extraction from existing ones (todos [B4a](../../docs/todos/done/B4a-font-loading-and-subsetting.md), [B4b](../../docs/todos/done/B4b-shaping-bidi-line-breaking.md) and [B4d](../../docs/todos/done/B4d-tounicode-per-text-cids.md), [ADR 0005](../../docs/decisions/0005-document-model.md) §6): shaping, bidi and line breaking, loading fonts from caller-supplied bytes, tracking the glyphs a document uses, and embedding each font as a deterministic subset with `/W` widths and a ToUnicode CMap, so generated text is selectable and extractable. Spec: ISO 32000-2 §9.6–9.10; background in [research 03](../../docs/research/pdf/03-text-and-fonts.md) §3.5–6, §7.9 and §10. Part of Lamina PDF's pure core: bytes in, bytes out.

- **`Font`** (`skrifa`/`read-fonts`): `Font::from_bytes` (TrueType, OpenType with `glyf`, `CFF ` or `CFF2` outlines), `Font::from_collection(bytes, index)` for `.ttc`/`.otc` members, `Font::instance(&[(OpenTypeTag, f32)])` for variable fonts (clamped to each axis; an unknown axis is `unknown-axis`), `Font::glyph_for(char)`, `Font::advance(gid)`. `FontInfo`: family, PostScript name (an instance gets `_wght700`-style suffixes so instances have distinct names), units per em, glyph count, ascent/descent/cap height/x-height, italic angle, weight, bbox, descriptor flags, `is_cff`, `is_variable`, axes, `fsType`.
- **`FsType` / `EmbedPolicy`** (research 03 §6.3): a restricted-licence or bitmap-only font fails `FontRegistry::add` with `font-not-embeddable` unless the caller passes `EmbedPolicy::Override`; a "no subsetting" font is embedded whole and byte for byte (a collection member copied out as a standalone font; a CFF font as `/FontFile3 /OpenType`), with its own glyph IDs as CIDs and no subset tag. A variable-font instance or CFF2 font that forbids subsetting is rebuilt by `subsetter` with every glyph kept, with the `whole-font-rebuilt` warning.
- **`FontUse`**: per font, one CID per (glyph, text) and CID → text for ToUnicode (`BTreeMap`; B4d), so a glyph drawn for two texts (a pre-base matra standing for the consonant before it, the same glyph elsewhere for itself) extracts exactly both times. In a subset CIDs are dense in order of first (glyph, text) use, `.notdef` = 0; while no glyph has two texts they equal the subset's glyph IDs and `/CIDToGIDMap` is `/Identity`, otherwise it is a stream. A glyph that stands for no text (a dot drawn apart from its letter) takes a CID among the code points of format characters (U+200B–200F, U+202A–202E, U+2060–206F, U+FEFF, U+FFF9–FFFB) mapped to `<>`: pypdf and pdftotext read the empty destination as nothing, and pdf.js, which reads it as the code, skips a format character; past the 29 slots (or in a subset of a font with over 65 507 glyphs, which gets none) a textless glyph takes an ordinary CID and `pdf_run` covers its cluster with `/ActualText`, as it does a conflict once the CIDs run out. A font embedded whole keeps CID = GID for each glyph's first text and puts further CIDs past its glyph count. CFF outlines (`CIDFontType0`) address glyphs through the CFF charset, not `/CIDToGIDMap`, so there a glyph keeps one CID and its first text (the empty text included) and a later different text is the `tounicode-conflict` warning, for the builder to cover with `/ActualText` (decision recorded in B4d: duplicating charset entries would mean duplicating charstrings).
- **`FontRegistry`** (one per document; its `FontKey`s carry the registry's identity, so a key from another registry is `unknown-font`, and `finish_fonts` refuses a document whose reserved numbers aren't its own with `wrong-document` before writing anything): `add`, `reference` (reserves the Type 0 font object in the document's overlay at first use), `encode` (one glyph per character through the `cmap`, Identity-H bytes and the advance; a character without a glyph is `missing-glyph` with the character and the font, never a silent `.notdef`), `use_glyph` (for shaped glyphs: B4b), `warnings`, and `finish_fonts(&mut CosMut)`, which subsets each referenced font and writes its objects into the overlay.
- **Embedding**: `subsetter` (with its instancing for variable fonts; CFF2 comes back as TrueType) → Type 0 / Identity-H → `CIDFontType2` with `/FontFile2` (Flate, `/Length1`) and `/CIDToGIDMap /Identity` (a Flate stream of big-endian glyph IDs once a glyph has several CIDs), or `CIDFontType0` with `/FontFile3 /Subtype /CIDFontType0C` (the subset's bare CID-keyed CFF). `CIDSystemInfo` Adobe-Identity-0. The Type 0 `/BaseFont` is the CIDFont's name, plus `-Identity-H` for a `CIDFontType0` descendant (§9.7.6.1). The descriptor carries `Flags`, `FontBBox` (for an instance, the union of the instanced glyphs' bounds, since `head` isn't varied), `ItalicAngle`, `Ascent`, `Descent`, `CapHeight`, `XHeight`, `StemV`. `/W` comes from the subset's own `hmtx` (so it matches the instance), in thousandths with three decimals, the most common width as `/DW`, runs of three or more equal widths as `c1 c2 w` and other consecutive CIDs as `c [w …]`. ToUnicode: `bfrange` for runs of consecutive codes and single code units (never crossing a first-byte boundary or carrying out of the last destination byte), `bfchar` otherwise (ligatures map to several code units, non-BMP characters to surrogate pairs), at most 100 entries per block.
- **Shared writers**: embedded fonts and the standard 14 fonts share one ToUnicode writer and one descriptor builder. A destination stops at 512 bytes without splitting a surrogate pair, and `CapHeight` falls back to the ascent.
- **Shaping** (todo [B4b](../../docs/todos/done/B4b-shaping-bidi-line-breaking.md), research 03 §7.2): the `Shaper` trait (`shape(&Font, &str, &ShapeOptions)`, `shape_range` with the surrounding text as context) and `HarfRust` (HarfRust 0.8, on the same `read-fonts` as `skrifa`). `ShapeOptions { script, language, direction, features }`, each detected when left out; `Feature` parses HarfBuzz's syntax (`liga=0`, `-liga`, `smcp`, `aalt=2`; else `invalid-feature`); `Script` is the ISO 15924 code from ICU4X's `Script` property. `ShapedRun { glyphs: [ShapedGlyph { gid, cluster, x_advance, y_advance, x_offset, y_offset }], text_range, direction, script, units_per_em }`, clusters as UTF-8 byte offsets, positions in font units: identical to `hb-shape` on the goldens in `fixtures/shaping/`. Fonts have no glyphs for control characters, so a tab is shaped as a space (no tab stops yet) and other controls as nothing; HarfRust's per-face tables are built once per font and shared by its clones and instances.
- **Bidi** (UAX #9, §7.3): `BidiParagraph` runs `unicode-bidi`'s algorithm on ICU4X's `Bidi_Class` data: paragraph direction (given or from the first strong character), levels, `level_runs` (logical) and `visual_runs(line)` (rules L1–L2).
- **Line breaking** (UAX #14, §7.4): `line_breaks(text)` gives every `BreakOpportunity { offset, mandatory }` from `icu_segmenter`'s Unicode 17 rules (no dictionaries: Thai, Lao, Khmer and Burmese get no word breaks); `grapheme_boundaries` (UAX #29); `is_hard_break` and `is_trailing_space` (the classes a line ends at and hangs), shared with `laminapdf-build`'s unshaped standard 14 layout. `FontRegistry` is `Clone` (a snapshot with the same identity), so the builder can restore it when a page fails.
- **Itemisation and layout**: `itemize(&BidiParagraph, &[Font])` splits a paragraph into `Item`s of one script, level and font (the first font in the caller's list covering each grapheme cluster; none is `missing-glyph`; no system fallback). `break_lines(&shaper, &fonts, text, &LayoutOptions)` resolves each paragraph (ended by a line feed or U+2029) on its own and is greedy (first fit): candidates are estimated from the paragraph shaped once and the chosen line is shaped as drawn, so no line is wider than the box but one holding a single cluster wider than it; a word wider than the box breaks between grapheme clusters; trailing spaces hang. Each `Line` has its runs shaped in visual order with their x positions, its width and its x from `Alignment` (start, end, left, right, centre); justification is reserved. Styled spans (todo [T4g](../../docs/todos/done/T4g-flow-styled-spans.md)): `break_spans(&shaper, &fonts, text, &[StyledSpan], &LayoutOptions)` lays out a paragraph whose words change font, size, rise or language, such as a bold word, a superscript or an Arabic name in an English line. Each `StyledSpan` covers a byte range and sets its own font list (indices into `fonts`), size, rise, language and features, each defaulting to the options. Spans that don't cover the text once, in order, fail with `invalid-spans`. Lines still break only where UAX #14 allows, so a style change inside a word never breaks it. Consecutive spans of one style are shaped as one run, so kerning carries across them. Each `LineRun` records its spans, size and rise, and each `Line` its `ascent` and `descent` from its tallest run. `pdf_line_run` adds a run's rise to the `Ts` of its segments. `break_lines` is one span over the whole text. `Line::drawing_order()` gives the runs' indices in logical order: drawn in that order (each at its own x), extractors that keep content order across a font change (pypdf, pdf.js) read a right-to-left line of several runs in order (B4d).
- **PDF positioning** (§2.6–2.7, §5.3): `pdf_run(&ShapedRun, text, &mut FontRegistry, key)` → `PdfRun { pieces: [PdfPiece { actual_text, segments: [PdfSegment { rise, tj: [TjElement::Codes | Adjust] }] }], advance }`. `TJ` numbers make the font's `/W` widths follow the shaper's advances and x offsets exactly (integer millionths of an em, three decimals at most); y offsets become `Ts` rises. Glyphs are registered for ToUnicode (one glyph for a cluster: its text; several: each its own character, the leftovers on the widest other glyph, the rest nothing; default-ignorables such as ZWJ are never a glyph's text). With TrueType outlines (B4d) the cluster's characters are then dealt out again in reading order, each glyph keeping its share's length, so a reordered cluster (pre-base matra, reph, marks) reads back from the codes alone and a glyph standing for nothing gets a textless CID: no `/ActualText`, except for clusters holding default-ignorables. With CFF outlines (one CID per glyph) a cluster that doesn't read back in order, has a textless glyph or hits a ToUnicode conflict is flagged for `/ActualText`, and a glyph that is some character's own claims nothing; a run shaped with another font is `font-mismatch`, checked before anything is recorded; a `.notdef` glyph is `missing-glyph`.
- **Standard 14** (todo [B4c](../../docs/todos/done/B4c-standard-14-and-simple-fonts.md); ISO 32000-2 §9.6.2.2, §9.6.5, Annex D; research 03 §3.1, §3.8, §4.1): `Standard14` (the fourteen, `from_base_font`, `metrics()` → `AfmMetrics`, `width(glyph name)`, `glyph_names()`), `Font::standard(Standard14)` (a `Font` with no bytes: `FontInfo` from the AFM header, glyph 0 is `.notdef` and glyph `n` the `n`-th sorted glyph name, characters map to glyphs by name through the Adobe Glyph List), `Font::standard14()`, `Font::requires_embedding()` (`false` only for these; B8b's PDF/A and PDF/UA profiles reject them); with no font program to shape with, `HarfRust::shape` lays them out one glyph per character, left to right, with their AFM widths, and `itemize`, `break_lines` and `break_spans` use that (T4d); `pdf_run` refuses them with `font-not-shapable`, since their glyphs are one-byte codes (`FontRegistry::encode` draws them). `FontRegistry` writes them as non-embedded simple fonts: `/Type1`, `/BaseFont`, one byte per character in `/WinAnsiEncoding` (the Latin fonts) or the built-in encoding (Symbol, ZapfDingbats), `/FirstChar`, `/LastChar`, `/Widths` over the codes drawn (PDF 2.0 wants widths for these too), a `/FontDescriptor` without a font program (`Flags` with Serif/Symbolic/Nonsymbolic/Italic/FixedPitch, `FontBBox`, `ItalicAngle`, `Ascent`, `Descent`, `CapHeight`, `XHeight`, `StemV`, `StemH`), and a ToUnicode CMap (one-byte codespace, `bfchar`) from the text each code was drawn for, so extraction never depends on glyph names; a glyph drawn for two texts keeps the first (`tounicode-conflict`). `FontRegistry::use_glyph` returns a `GlyphCode` (`Cid(u16)` for embedded fonts, `Byte(u8)` here; `push_to` writes either); `FontRegistry::usage` returns `FontUsage::{Embedded(&FontUse), Simple(&SimpleUse)}`; `EmbeddedFont::embedded` is `false` for these. A Latin glyph outside `WinAnsiEncoding` (`Ł`, `ş`, `−`) takes one of the 37 codes it leaves undefined, through `/Encoding << /BaseEncoding /WinAnsiEncoding /Differences […] >>`; more than that in one font is `encoding-full` (all or nothing: the error says how many were still free). Romanian Ț ț (U+021A/B) map to `Tcommaaccent`/`tcommaaccent`. A character the font has no glyph for (`é` in Symbol, CJK anywhere) is `missing-glyph`. Kerning pairs are not bundled.
- **`Encoding`** (`Standard`, `WinAnsi`, `MacRoman`, `PdfDoc`, `Symbol`, `ZapfDingbats`): code → glyph name, glyph name → lowest code (generated reverse tables), code → Unicode (Symbol's `Omega`, `Delta`, `mu` read back as Greek letters); `PdfDoc` adapts `laminapdf_syntax::text`'s table; `Encoding::from_pdf_name` reports `MacExpertEncoding` as `UnsupportedEncoding::MacExpert`. **`glyph_name_to_unicode`** and `zapf_dingbats_to_unicode`: glyph name → Unicode by the AGL specification (`uniXXXX`, `uXXXXX`, `_` ligatures, `.suffix`), with the ITC Zapf Dingbats list. Both are for B9b's extraction too.
- **Generated tables** (`src/std14/generated/`, never edited by hand): written by [`tools/std14-gen`](../../tools/std14-gen/src/main.rs) (`cargo run -p std14-gen`) from Adobe's Core 14 AFM files, the Adobe Glyph List (BSD-3-Clause) and Annex D, which it checks by SHA-256; sources and licence terms in [`tools/std14-gen/data/README.md`](../../tools/std14-gen/data/README.md). The generator's test fails when the committed tables differ from a regeneration.
- **Subset tags**: six letters from a SHA-256 of the font bytes, the collection index, the instance coordinates and the glyphs in CID order; a collision within one document is re-hashed. The same text in the same font gives byte-identical output.
- **Extraction** (todos [B9b](../../docs/todos/done/B9b-text-extraction-core.md), [B9d](../../docs/todos/done/B9d-text-runs-quads-and-page-text.md); ISO 32000-2 §9.4–9.10; research 03 §3–5, §8.1): `TextExtractor::page(&doc, &page)` runs a page through `laminapdf_content::interpret_page` and decodes every shown string → `PageText { glyphs: [Glyph { text, mapped, code, origin, advance, size, vertical, font }], unmapped }`, `PageText::lines()` (content order; a new line where the baseline moves by over half the size, a space where the pen jumps forward by over a quarter, or where a run lies wholly behind the previous one). Fonts are read once per extractor: simple fonts (`/Encoding` name or `/Differences`, `/FirstChar`/`/Widths`, `/MissingWidth`, standard 14 AFM widths by name and common aliases, Type 3 `/FontMatrix`), Type 0 (`Identity-H`/`-V`, `Uni…-UCS2-…`/`-UTF16-…`, embedded CMap streams with `/UseCMap` followed to a fixed depth, `/W`, `/DW`, `/W2`, `/DW2`, `/CIDToGIDMap`). Unicode: ToUnicode → glyph name through the AGL → UTF-16 codes → the embedded TrueType/OpenType `cmap` read backwards → U+FFFD. An internal `CMap` is one tolerant parser for CMaps and ToUnicode CMaps (ranges kept, never expanded). Problems are reader warnings on the document: `font-invalid`, `cmap-invalid`, `unmapped-glyph`. Geometry and runs (B9d): each glyph has a `Quad` in ADR 0027 page space (its width across the font's ascent and descent from the descriptor, `/FontBBox`, the AFM or 800/−200, through the text rendering matrix; vertical glyphs placed by the `/W2` position vector), the innermost MCID, the outermost `ActualText` span and `invisible` (`Tr` 3/7); `PageText::runs` groups glyphs of one font, size, direction, MCID, span and visibility on one baseline into `PageTextRun`s (`text`, `glyphs`, `font_name`, `font_size`, `bounds`, …): a span's first run takes its `ActualText`, a run with right-to-left characters is read by position (marks on their letters in canonical order) and put in logical order by UAX #9 over grapheme clusters, a neutral run after it on its line is reversed; `lines()` joins runs (trimmed; a space between runs over a quarter of the size apart without overlapping, B9e), ordering the runs of a line with right-to-left text by UAX #9 at run level, `visible()` drops invisible text, `frame` maps quads back to user space.

Not here: hyphenation, justification, vertical text and font fallback chains (later plans), embedding simple TrueType fonts with custom encodings (later), profile enforcement, which is laminapdf-build's ([B8b](../../docs/todos/done/B8b-conformance-profiles-and-verapdf.md)), `surface.text()` ([B5b](../../docs/todos/done/B5b-builder-text-and-document-features.md)), Adobe's character-collection CMaps for extraction ([B9c](../../docs/todos/done/B9c-text-extraction-bindings-and-differential.md)), colour glyphs, `/CIDSet` (PDF/A-1–3 only).
