# lamina-text

Fonts for generated PDFs (todo [B4a](../../docs/todos/done/B4a-font-loading-and-subsetting.md), [ADR 0005](../../docs/decisions/0005-document-model.md) §6): loading fonts from caller-supplied bytes, tracking the glyphs a document uses, and embedding each font as a deterministic subset with `/W` widths and a ToUnicode CMap, so generated text is selectable and extractable. Spec: ISO 32000-2 §9.6–9.10; background in [research 03](../../docs/research/pdf/03-text-and-fonts.md) §3.5–6, §7.9 and §10. Part of lamina's pure core: bytes in, bytes out.

- **`Font`** (`skrifa`/`read-fonts`): `Font::from_bytes` (TrueType, OpenType with `glyf`, `CFF ` or `CFF2` outlines), `Font::from_collection(bytes, index)` for `.ttc`/`.otc` members, `Font::instance(&[(Tag, f32)])` for variable fonts (clamped to each axis; an unknown axis is `unknown-axis`), `Font::glyph_for(char)`, `Font::advance(gid)`. `FontInfo`: family, PostScript name (an instance gets `_wght700`-style suffixes so instances have distinct names), units per em, glyph count, ascent/descent/cap height/x-height, italic angle, weight, bbox, descriptor flags, `is_cff`, `is_variable`, axes, `fsType`.
- **`FsType` / `EmbedPolicy`** (research 03 §6.3): a restricted-licence or bitmap-only font fails `FontRegistry::add` with `font-not-embeddable` unless the caller passes `EmbedPolicy::Override`; a "no subsetting" font is embedded whole and byte for byte (a collection member copied out as a standalone font; a CFF font as `/FontFile3 /OpenType`), with its own glyph IDs as CIDs and no subset tag. A variable-font instance or CFF2 font that forbids subsetting is rebuilt by `subsetter` with every glyph kept, with the `whole-font-rebuilt` warning.
- **`FontUse`**: per font, glyph → CID (the glyph's ID in the subset: dense, in order of first use, `.notdef` = 0) and CID → text for ToUnicode (`BTreeMap`). A glyph used for two different texts keeps the first; the other is reported as the `tounicode-conflict` warning, for the builder to cover with `/ActualText`.
- **`FontRegistry`** (one per document; its `FontKey`s carry the registry's identity, so a key from another registry is `unknown-font`, and `finish_fonts` refuses a document whose reserved numbers aren't its own with `wrong-document` before writing anything): `add`, `reference` (reserves the Type 0 font object in the document's overlay at first use), `encode` (one glyph per character through the `cmap`, Identity-H bytes and the advance; a character without a glyph is `missing-glyph` with the character and the font, never a silent `.notdef`), `use_glyph` (for shaped glyphs: B4b), `warnings`, and `finish_fonts(&mut CosMut)`, which subsets each referenced font and writes its objects into the overlay.
- **Embedding**: `subsetter` (with its instancing for variable fonts; CFF2 comes back as TrueType) → Type 0 / Identity-H → `CIDFontType2` with `/FontFile2` (Flate, `/Length1`) and `/CIDToGIDMap /Identity`, or `CIDFontType0` with `/FontFile3 /Subtype /CIDFontType0C` (the subset's bare CID-keyed CFF). `CIDSystemInfo` Adobe-Identity-0. The Type 0 `/BaseFont` is the CIDFont's name, plus `-Identity-H` for a `CIDFontType0` descendant (§9.7.6.1). The descriptor carries `Flags`, `FontBBox` (for an instance, the union of the instanced glyphs' bounds, since `head` isn't varied), `ItalicAngle`, `Ascent`, `Descent`, `CapHeight`, `XHeight`, `StemV`. `/W` comes from the subset's own `hmtx` (so it matches the instance), in thousandths with three decimals, the most common width as `/DW`, runs of three or more equal widths as `c1 c2 w` and other consecutive CIDs as `c [w …]`. ToUnicode: `bfrange` for runs of consecutive codes and single code units (never crossing a first-byte boundary or carrying out of the last destination byte), `bfchar` otherwise (ligatures map to several code units, non-BMP characters to surrogate pairs), at most 100 entries per block.
- **Standard 14** (todo [B4c](../../docs/todos/done/B4c-standard-14-and-simple-fonts.md); ISO 32000-2 §9.6.2.2, §9.6.5, Annex D; research 03 §3.1, §3.8, §4.1): `Standard14` (the fourteen, `from_base_font`, `metrics()` → `AfmMetrics`, `width(glyph name)`, `glyph_names()`), `Font::standard(Standard14)` (a `Font` with no bytes: `FontInfo` from the AFM header, glyph 0 is `.notdef` and glyph `n` the `n`-th sorted glyph name, characters map to glyphs by name through the Adobe Glyph List), `Font::standard14()`, `Font::requires_embedding()` (`false` only for these; B8b's PDF/A and PDF/UA profiles reject them). `FontRegistry` writes them as non-embedded simple fonts: `/Type1`, `/BaseFont`, one byte per character in `/WinAnsiEncoding` (the Latin fonts) or the built-in encoding (Symbol, ZapfDingbats), `/FirstChar`, `/LastChar`, `/Widths` over the codes drawn (PDF 2.0 wants widths for these too), a `/FontDescriptor` without a font program (`Flags` with Serif/Symbolic/Nonsymbolic/Italic/FixedPitch, `FontBBox`, `ItalicAngle`, `Ascent`, `Descent`, `CapHeight`, `XHeight`, `StemV`, `StemH`), and a ToUnicode CMap (one-byte codespace, `bfchar`) from the text each code was drawn for, so extraction never depends on glyph names; a glyph drawn for two texts keeps the first (`tounicode-conflict`). `FontRegistry::use_glyph` returns a `GlyphCode` (`Cid(u16)` for embedded fonts, `Byte(u8)` here; `push_to` writes either); `FontRegistry::usage` returns `FontUsage::{Embedded(&FontUse), Simple(&SimpleUse)}`; `EmbeddedFont::embedded` is `false` for these. A Latin glyph outside `WinAnsiEncoding` (`Ł`, `ş`, `−`) takes one of the 37 codes it leaves undefined, through `/Encoding << /BaseEncoding /WinAnsiEncoding /Differences […] >>`; more than that in one font is `encoding-full` (all or nothing: the error says how many were still free). Romanian Ț ț (U+021A/B) map to `Tcommaaccent`/`tcommaaccent`. A character the font has no glyph for (`é` in Symbol, CJK anywhere) is `missing-glyph`. Kerning pairs are not bundled.
- **`Encoding`** (`Standard`, `WinAnsi`, `MacRoman`, `PdfDoc`, `Symbol`, `ZapfDingbats`): code → glyph name, glyph name → lowest code (generated reverse tables), code → Unicode (Symbol's `Omega`, `Delta`, `mu` read back as Greek letters); `PdfDoc` adapts `lamina_syntax::text`'s table; `Encoding::from_pdf_name` reports `MacExpertEncoding` as `UnsupportedEncoding::MacExpert`. **`agl`**: glyph name → Unicode by the AGL specification (`uniXXXX`, `uXXXXX`, `_` ligatures, `.suffix`), with the ITC Zapf Dingbats list. Both are for B9b's extraction too.
- **Generated tables** (`src/std14/generated/`, never edited by hand): written by [`tools/std14-gen`](../../tools/std14-gen/src/main.rs) (`cargo run -p std14-gen`) from Adobe's Core 14 AFM files, the Adobe Glyph List (BSD-3-Clause) and Annex D, which it checks by SHA-256; sources and licence terms in [`tools/std14-gen/data/README.md`](../../tools/std14-gen/data/README.md). The generator's test fails when the committed tables differ from a regeneration.
- **Subset tags**: six letters from a SHA-256 of the font bytes, the collection index, the instance coordinates and the glyphs in CID order; a collision within one document is re-hashed. The same text in the same font gives byte-identical output.

Not here: shaping, bidi and line breaking ([B4b](../../docs/todos/ongoing/B4b-shaping-bidi-line-breaking.md)), embedding simple TrueType fonts with custom encodings (later), profile enforcement ([B8b](../../docs/todos/ready/B8b-conformance-profiles-and-verapdf.md)), `surface.text()` ([B5b](../../docs/todos/ready/B5b-builder-text-and-document-features.md)), reading fonts back for extraction ([B9b](../../docs/todos/ready/B9b-text-extraction-core.md)), colour glyphs, `/CIDSet` (PDF/A-1–3 only).

Tests (`tests/`, reading the shared [`fixtures/`](../../fixtures/README.md), fonts in `fixtures/fonts/`): `embed.rs` (dictionaries read back with `lamina-cos`, `/W` against the subset's `hmtx` with `skrifa`, tags, determinism, missing glyphs, Arabic/Hebrew/Devanagari round trips), `tounicode.rs`, `review_fixes.rs` (the first code review's regressions), `fstype.rs` (fonts with a patched `fsType`), `variable.rs` (a `wght` 700 instance, TTC members), `std14.rs` (the standard 14: every glyph's width against the AFM files, the encoding tables, text encoding, the written simple fonts), `golden.rs` (byte-exact `fixtures/golden/text-*.pdf`), `extraction.rs` (pypdf's text and `qpdf --check` for each golden, from `fixtures/text/extracted.json`) and `codes.rs` (codes vs `fixtures/codes.json`, an explain page in `docs/errors/` for each, no font names or text in messages per ADR 0026 §4). `tests/common/` holds the test page writer (one page over an empty base, glyphs placed with `pdf_writer::Content`, saved with `lamina-save`'s `FullWriter`) and the golden samples; `examples/golden.rs` writes the goldens for `cargo xtask golden --update`.

```sh
cargo test -p lamina-text
cargo run -p std14-gen                                                # after tools/std14-gen/data/ changes
cargo xtask golden --update && python3 tools/fixtures/text_facts.py   # after a golden changes (pypdf, qpdf)
```
