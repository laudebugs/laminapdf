# lamina-text

Fonts and text layout for generated PDFs (todos [B4a](../../docs/todos/done/B4a-font-loading-and-subsetting.md) and [B4b](../../docs/todos/done/B4b-shaping-bidi-line-breaking.md), [ADR 0005](../../docs/decisions/0005-document-model.md) §6): shaping, bidi and line breaking, loading fonts from caller-supplied bytes, tracking the glyphs a document uses, and embedding each font as a deterministic subset with `/W` widths and a ToUnicode CMap, so generated text is selectable and extractable. Spec: ISO 32000-2 §9.6–9.10; background in [research 03](../../docs/research/pdf/03-text-and-fonts.md) §3.5–6, §7.9 and §10. Part of lamina's pure core: bytes in, bytes out.

- **`Font`** (`skrifa`/`read-fonts`): `Font::from_bytes` (TrueType, OpenType with `glyf`, `CFF ` or `CFF2` outlines), `Font::from_collection(bytes, index)` for `.ttc`/`.otc` members, `Font::instance(&[(Tag, f32)])` for variable fonts (clamped to each axis; an unknown axis is `unknown-axis`), `Font::glyph_for(char)`, `Font::advance(gid)`. `FontInfo`: family, PostScript name (an instance gets `_wght700`-style suffixes so instances have distinct names), units per em, glyph count, ascent/descent/cap height/x-height, italic angle, weight, bbox, descriptor flags, `is_cff`, `is_variable`, axes, `fsType`.
- **`FsType` / `EmbedPolicy`** (research 03 §6.3): a restricted-licence or bitmap-only font fails `FontRegistry::add` with `font-not-embeddable` unless the caller passes `EmbedPolicy::Override`; a "no subsetting" font is embedded whole and byte for byte (a collection member copied out as a standalone font; a CFF font as `/FontFile3 /OpenType`), with its own glyph IDs as CIDs and no subset tag. A variable-font instance or CFF2 font that forbids subsetting is rebuilt by `subsetter` with every glyph kept, with the `whole-font-rebuilt` warning.
- **`FontUse`**: per font, glyph → CID (the glyph's ID in the subset: dense, in order of first use, `.notdef` = 0) and CID → text for ToUnicode (`BTreeMap`). A glyph used for two different texts (the empty text included, B4b) keeps the first; the other is reported as the `tounicode-conflict` warning, for the builder to cover with `/ActualText`. One CID per (glyph, text), so every use extracts exactly, is [B4d](../../docs/todos/ready/B4d-tounicode-per-text-cids.md).
- **`FontRegistry`** (one per document; its `FontKey`s carry the registry's identity, so a key from another registry is `unknown-font`, and `finish_fonts` refuses a document whose reserved numbers aren't its own with `wrong-document` before writing anything): `add`, `reference` (reserves the Type 0 font object in the document's overlay at first use), `encode` (one glyph per character through the `cmap`, Identity-H bytes and the advance; a character without a glyph is `missing-glyph` with the character and the font, never a silent `.notdef`), `use_glyph` (for shaped glyphs: B4b), `warnings`, and `finish_fonts(&mut CosMut)`, which subsets each referenced font and writes its objects into the overlay.
- **Embedding**: `subsetter` (with its instancing for variable fonts; CFF2 comes back as TrueType) → Type 0 / Identity-H → `CIDFontType2` with `/FontFile2` (Flate, `/Length1`) and `/CIDToGIDMap /Identity`, or `CIDFontType0` with `/FontFile3 /Subtype /CIDFontType0C` (the subset's bare CID-keyed CFF). `CIDSystemInfo` Adobe-Identity-0. The Type 0 `/BaseFont` is the CIDFont's name, plus `-Identity-H` for a `CIDFontType0` descendant (§9.7.6.1). The descriptor carries `Flags`, `FontBBox` (for an instance, the union of the instanced glyphs' bounds, since `head` isn't varied), `ItalicAngle`, `Ascent`, `Descent`, `CapHeight`, `XHeight`, `StemV`. `/W` comes from the subset's own `hmtx` (so it matches the instance), in thousandths with three decimals, the most common width as `/DW`, runs of three or more equal widths as `c1 c2 w` and other consecutive CIDs as `c [w …]`. ToUnicode: `bfrange` for runs of consecutive codes and single code units (never crossing a first-byte boundary or carrying out of the last destination byte), `bfchar` otherwise (ligatures map to several code units, non-BMP characters to surrogate pairs), at most 100 entries per block.
- **Shaping** (todo [B4b](../../docs/todos/done/B4b-shaping-bidi-line-breaking.md), research 03 §7.2): the `Shaper` trait (`shape(&Font, &str, &ShapeOptions)`, `shape_range` with the surrounding text as context) and `HarfRust` (HarfRust 0.8, on the same `read-fonts` as `skrifa`). `ShapeOptions { script, language, direction, features }`, each detected when left out; `Feature` parses HarfBuzz's syntax (`liga=0`, `-liga`, `smcp`, `aalt=2`; else `invalid-feature`); `Script` is the ISO 15924 code from ICU4X's `Script` property. `ShapedRun { glyphs: [ShapedGlyph { gid, cluster, x_advance, y_advance, x_offset, y_offset }], text_range, direction, script, units_per_em }`, clusters as UTF-8 byte offsets, positions in font units: identical to `hb-shape` on the goldens in `fixtures/shaping/`. Fonts have no glyphs for control characters, so a tab is shaped as a space (no tab stops yet) and other controls as nothing; HarfRust's per-face tables are built once per font and shared by its clones and instances.
- **Bidi** (UAX #9, §7.3): `BidiParagraph` runs `unicode-bidi`'s algorithm on ICU4X's `Bidi_Class` data: paragraph direction (given or from the first strong character), levels, `level_runs` (logical) and `visual_runs(line)` (rules L1–L2).
- **Line breaking** (UAX #14, §7.4): `line_breaks(text)` gives every `BreakOpportunity { offset, mandatory }` from `icu_segmenter`'s Unicode 17 rules (no dictionaries: Thai, Lao, Khmer and Burmese get no word breaks); `grapheme_boundaries` (UAX #29).
- **Itemisation and layout**: `itemize(&BidiParagraph, &[Font])` splits a paragraph into `Item`s of one script, level and font (the first font in the caller's list covering each grapheme cluster; none is `missing-glyph`; no system fallback). `break_lines(&shaper, &fonts, text, &LayoutOptions)` resolves each paragraph (ended by a line feed or U+2029) on its own and is greedy (first fit): candidates are estimated from the paragraph shaped once and the chosen line is shaped as drawn, so no line is wider than the box but one holding a single cluster wider than it; a word wider than the box breaks between grapheme clusters; trailing spaces hang. Each `Line` has its runs shaped in visual order with their x positions, its width and its x from `Alignment` (start, end, left, right, centre); justification is reserved.
- **PDF positioning** (§2.6–2.7, §5.3): `pdf_run(&ShapedRun, text, &mut FontRegistry, key)` → `PdfRun { pieces: [PdfPiece { actual_text, segments: [PdfSegment { rise, tj: [TjElement::Codes | Adjust] }] }], advance }`. `TJ` numbers make the font's `/W` widths follow the shaper's advances and x offsets exactly (integer millionths of an em, three decimals at most); y offsets become `Ts` rises. Glyphs are registered for ToUnicode (one glyph for a cluster: its text; several: each its own character, the leftovers on the widest other glyph, the rest the empty string `<cid> <>` when no character maps to the glyph, or no claim when one does; default-ignorables such as ZWJ are never a glyph's text), and a cluster that doesn't read back in order (Indic reordering), has a textless glyph or hits a ToUnicode conflict is flagged for `/ActualText`; a run shaped with another font is `font-mismatch`, checked before anything is recorded; a `.notdef` glyph is `missing-glyph`.
- **Subset tags**: six letters from a SHA-256 of the font bytes, the collection index, the instance coordinates and the glyphs in CID order; a collision within one document is re-hashed. The same text in the same font gives byte-identical output.

Not here: hyphenation, justification, vertical text and font fallback chains (later plans), simple fonts and the standard 14 ([B4c](../../docs/todos/ongoing/B4c-standard-14-and-simple-fonts.md)), `surface.text()` ([B5b](../../docs/todos/ready/B5b-builder-text-and-document-features.md)), reading fonts back for extraction ([B9b](../../docs/todos/ready/B9b-text-extraction-core.md)), colour glyphs, `/CIDSet` (PDF/A-1–3 only).
