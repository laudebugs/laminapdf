# laminapdf-ops

Edit PDFs in Rust with typed operations you can serialise as JSON, group into transactions, and undo or redo. Most programs use it through [`laminapdf`](../laminapdf/README.md), which wraps the core crates in one API.

Editing PDFs through typed, serialisable ops ([ADR 0006](../../docs/decisions/0006-op-log-and-undo.md)), over the overlay of [`laminapdf-cos`](../laminapdf-cos/README.md) and the views of [`laminapdf-model`](../laminapdf-model/README.md). Part of Lamina PDF's pure core: bytes in, bytes out.

- `Op` (adjacently tagged JSON, `{ "op": "rotatePage", "args": { "page": "p12.0", "rotate": 90 } }`, unknown ops and fields rejected): `SetInfo { patch: InfoPatch, at: Option<PdfDate> }` and `RotatePage { page: PageId, rotate: Rotation }`, each with a `ModificationClass` and `requires_rewrite()`. `OpLog` is the versioned envelope `{ "v": 1, "ops": [ … ] }`; `OpLog::from_json` rejects an unknown `v` before reading any op.
- `Document`: wraps a `laminapdf_model::Document` (it dereferences to one, read-only) and is the only write path. `transact(origin, |tx| …)` is atomic (on `Err` the journal unwinds and nothing is recorded); `Tx::apply` rolls back a failing op's own changes; `Tx::savepoint` rolls back only its closure's; `begin` / `apply` / `commit` / `rollback` is the same across calls for bindings; a transaction inside an open one is `Error::NestedTransaction`. `apply_all(origin, ops)` runs a list as one transaction.
- `Applied { undo: UndoRecord, touched_pages }`: the undo record is derived from the COS journal (each changed object's or the trailer's value before and after; `properties()` per dictionary key and, for streams, the data, as a `Field`), so every op gets undo without a hand-written inverse.
- `undo()` / `redo()` (local transactions only; depth 500, `set_undo_depth`; redo cleared by a new local transaction; `transact_coalescing(key, …)`) restore each property that still holds the value the transaction set and leave the rest: `UndoOutcome::{Applied, Partial { skipped }, Skipped { skipped }}`. A stream's data and its encoding keys (`/Filter`, `/DecodeParms`, …) are restored together or not at all, and a value that changed kind (dictionary ↔ stream) is never restored into a mix. Coalescing stops at any undo or redo and at any remote or system change, and a panic inside `transact` rolls the transaction back. Undoing to the opened state leaves the overlay empty (`is_dirty()` false); `has_unsaved_changes()` / `mark_saved()` are the semantic dirty level.
- Save cycle (ADR 0005 §3): `save_state()` is `SaveState::{Clean, Dirty, SavedNotRebased}`. `laminapdf-save` calls `saved_not_rebased(PendingRebase)` once a save's bytes are written (refused inside a transaction) and `rebase(source)` when it can read them back; in `SavedNotRebased` ops, undo, redo and saves fail with `Error::SavedNotRebased` until the shell calls `rebase(saved bytes)`. `PendingRebase::KeepHistory` (an incremental save that freed nothing) keeps the undo history and reserved numbers; `ClearHistory` (a full rewrite, or deletions) drops them, since undo could restore references to objects that are gone. `rebase` without a pending save is `Error::NoPendingSave`.
- `pending_changes()` (`PendingChanges`): the op classes and rewrite need of every transaction committed since the last rebase (undo and redo add those of the entry they revert; an empty overlay clears them), for `laminapdf-save`'s planner (ADR 0007 §2). A model document wrapped while its overlay already holds changes reports `PendingChanges::unknown()` (every class, a full rewrite needed).
- The page ops (E2b, `src/pages/`): `InsertBlankPages`, `DeletePages` (with `ReferencePolicy::{Retarget, Remove}` for the outline items, links, named destinations, `/OpenAction` and structure elements that named a deleted page), `MovePages`, `RotatePages` (`RotateMode::{Set, Turn}`), `ReversePages` and `DuplicatePages` (E2k: copies with new annotations, widgets turned into new fields named `<partial>#<n>`, signature widgets left out, cloned structure elements and fresh `/StructParents` keys; `Applied::fields` and `tags_incomplete`), over `laminapdf-model`'s page-tree editor; each keeps the page labels right, reports `Applied::page_order`, `references` and its touched widgets, and names its pages before it applies (`Op::page_changes`). Deleting takes the deleted pages' widgets out of the form. Deleting every page is `Error::NoPagesLeft` (`no-pages-left`); a blank-page count or size out of range is `Error::InvalidOp` (`invalid-op`).
- Source documents (E2p): `add_source(bytes, password)` opens another PDF, with this document's `Limits`, for the ops that copy pages from it, and returns its `SourceId`, the `BlobId` (SHA-256) of its bytes, so the same file has the same ID on every device. Adding the same bytes again opens nothing twice; a password opens an encrypted source and never enters an op. `source_document(id)` returns the opened source, or `Error::UnknownSource` (`unknown-source`) for one the session lacks. The bytes stay in the session's `BlobStore` (`blobs()`) for undo, redo and a replayed log.
- Feature `tsify` (off by default; `laminapdf-wasm` enables it): derives `tsify::Tsify` on the op types for TypeScript declarations.

Tests: unit tests in `src/{record,tx,history}.rs`; `tests/ops.rs` (both ops over corpus files with indirect, direct and missing `/Info` and a file with inherited `/Rotate`; transactions and savepoints), `undo.rs` (undo, redo, remote changes, coalescing, dirty levels), `pending.rs` (pending classes), `sources.rs` (source documents and the blob store), `serde.rs` (the frozen samples in [`fixtures/ops/v1/`](../../fixtures/README.md#opsv1), rejected input, error codes) and `props.rs` (proptest, fixed seed: random transactions, undo all → empty overlay, redo all → the same overlay).
