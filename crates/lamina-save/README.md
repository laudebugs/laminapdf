# lamina-save

Saving PDFs ([ADR 0007](../../docs/decisions/0007-save-planner.md) §5–§7, [ADR 0005](../../docs/decisions/0005-document-model.md) §3): the writers that turn a document's overlay ([`lamina-cos`](../lamina-cos/README.md)) into bytes, the sinks they stream to, and the rebase that makes the output the new base of a [`lamina-ops`](../lamina-ops/README.md) document. Part of lamina's pure core: bytes in, bytes out.

- **`IncrementalWriter`** (§7.5.6): the base bytes unchanged, copied from the `ByteSource` in 64 KiB chunks. A windowed base is read twice: once before anything is written (every missing range reported in one `DataPending`, and the base hashed for `/ID`), then to copy it. Then the overlay in number order (new objects generation 0, modified ones their base generation, deleted ones free entries with the generation incremented, linked in front of the base's free list), then a section of the base's newest kind (classic table, or an xref stream numbered with the next free number within `Limits::max_object_number`) with `/Prev`, `/Size` never below the base's or any reserved number, and the trailer's document keys (xref-section and xref-stream keys such as `/DL`, `/F` dropped). `IncrementalOutput::AppendedOnly` writes only the revision. With an empty overlay the base is written unchanged and the report has no append offset (even for a repaired or encrypted base); otherwise repaired (`RepairedBase`) and encrypted (`EncryptedBase`) bases are refused.
- **`FullWriter`**: only what the trailer's document keys reach, `/ID` excepted (iterative walk, nesting checked against `Limits::max_nesting_depth` the way the parser counts it; dangling and stale references become `null`; an object that can't be loaded fails the save); `Renumber::Keep` (default: numbers and generations kept, so `LaminaId`s stay; base objects not written become free entries with the next generation) or `Renumber::Compact` (`1..=n`, with the old → new map in the report). The xref lists only numbers that hold something, so its size follows the data, not the input's `/Size`. Flate object streams of up to 100 members plus an xref stream (default, header raised to 1.5) or `XrefKind::Classic`. Every object is loaded and every number allocated before the first byte is written. Refuses encrypted bases.
- **`/ID`** (§14.4): `/ID[0]` kept by every save (direct or indirect), `/ID[1]` the first 16 bytes of a SHA-256 of the content written (for an incremental save: the base and the revision up to its trailer); both derived the same way when the document has none.
- **Sinks**: `WriteSink` (append only, never seeks; `held()` lets a writer refuse a sink that already holds bytes, `SinkError::NotEmpty`), `ReadableSink::into_source` (for rebasing), impls for `Vec<u8>` (readable) and `IoWrite<W: std::io::Write>`, `CountingSink`. `SinkError`.
- **`Save`** on `lamina_ops::Document` (B3b's names until B3c's `Document::save` and the planner): `save_incremental` (rebases onto old base ‖ revision, built in memory, or chained without a copy for a windowed base), `save_full` (to a write-only sink: the document is `SavedNotRebased` until `lamina_ops::Document::rebase(source)`), `save_full_and_rebase` (to a `ReadableSink`). States `Clean | Dirty | SavedNotRebased` (`lamina_ops::SaveState`): saves and ops are refused in `SavedNotRebased` and while a transaction is open. A failure before or while writing leaves the document `Dirty` with its overlay untouched; a rebase that fails after a complete write leaves it `SavedNotRebased` with the output in `SaveError::NotRebased` to retry with. The undo history survives only an incremental save that freed nothing (`PendingRebase::KeepHistory`); a full rewrite or deletions clear it, since undo could restore references to objects that are gone. `SaveOptions` (`output`, `renumber`, `xref`, `eol`) and `SaveReport` (bytes written, mode, renumber map, append offset).
- **`Writer` / `incremental_update` / `XrefEol`**: the spike-era writer, moved from `lamina-cos` in B3b with its tests, for building files from scratch (tests, and generation until `lamina-build`).

Output is byte-deterministic (ADR 0001): ordered maps only, no clocks, `/ID` from a hash. Determinism is tested by save-twice tests for each writer and layout and by the property test, which saves every case twice.

Tests (`tests/`, reading the shared [`fixtures/`](../../fixtures/README.md)): moved from `lamina-cos` with the writer: `golden.rs` (byte-exact goldens, now also `incremental-set-info.pdf` and `full-rewrite-hello.pdf`), `determinism.rs`, `incremental.rs`, `raw_writer.rs`, `roundtrip.rs` and the writer half of `review_fixes.rs`; new: `overlay_incremental.rs`, `full_rewrite.rs` (also every unencrypted corpus file in each layout), `rebase.rs`, `id.rs`, `sink_errors.rs`, `encrypted_base.rs`, `codes.rs` and `props.rs` (proptest, fixed seed: random ops → every writer → reopen gives the in-memory facts, twice the same bytes). `tests/common/` holds the golden samples and the save helpers, and takes the content builder and hand-built files from `lamina-cos`'s `tests/common/` by `#[path]`; `examples/golden.rs` writes the goldens for `cargo xtask golden --update`.

`lamina-cos`, `lamina-model` and `lamina-ops` use this crate as a dev-dependency to build their test inputs (a cycle Cargo accepts for integration tests; `lamina-cos`'s own unit tests build files with `tests/common/classic.rs` instead).

```sh
cargo test -p lamina-save
```
