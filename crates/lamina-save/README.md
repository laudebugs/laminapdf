# lamina-save

Saving PDFs ([ADR 0007](../../docs/decisions/0007-save-planner.md) §5–§7, [ADR 0005](../../docs/decisions/0005-document-model.md) §3): the writers that turn a document's overlay ([`lamina-cos`](../lamina-cos/README.md)) into bytes, the sinks they stream to, and the rebase that makes the output the new base of a [`lamina-ops`](../lamina-ops/README.md) document. Part of lamina's pure core: bytes in, bytes out.

- **`IncrementalWriter`** (§7.5.6): the base bytes unchanged, copied from the `ByteSource` in 64 KiB chunks (all checked first, so a `Pending` source fails with `DataPending` before the sink sees a byte), then the overlay in number order (new objects generation 0, modified ones their base generation, deleted ones free entries with the generation incremented and linked into the free list), then a section of the base's newest kind (classic table, or an xref stream numbered with the next free number) with `/Prev`, `/Size` never below the base's or any reserved number, and the trailer's document keys (xref-section keys dropped). `IncrementalOutput::AppendedOnly` writes only the revision; an empty overlay writes the base unchanged. Refuses repaired (`RepairedBase`) and encrypted (`EncryptedBase`) bases.
- **`FullWriter`**: only what the trailer's document keys reach (iterative walk, nesting bounded by `Limits::max_nesting_depth`; dangling and stale references become `null`); `Renumber::Keep` (default: numbers and generations kept, so `LaminaId`s stay) or `Renumber::Compact` (`1..=n`, with the old → new map in the report); Flate object streams of up to 100 members plus an xref stream (default, header raised to 1.5) or `XrefKind::Classic`. Every object is loaded before the first byte is written. Refuses encrypted bases.
- **`/ID`** (§14.4): `/ID[0]` kept by every save, `/ID[1]` the first 16 bytes of a SHA-256 of the content written; both derived the same way when the document has none.
- **Sinks**: `WriteSink` (append only, never seeks), `ReadableSink::into_source` (for rebasing), impls for `Vec<u8>` (readable) and `IoWrite<W: std::io::Write>`, `CountingSink`. `SinkError`.
- **`Save`** on `lamina_ops::Document` (B3b's names until B3c's `Document::save` and the planner): `save_incremental` (rebases onto old base ‖ revision, built in memory, or chained without a copy for a windowed base), `save_full` (to a write-only sink: the document is `SavedNotRebased` until `lamina_ops::Document::rebase(source)`), `save_full_and_rebase` (to a `ReadableSink`). States `Clean | Dirty | SavedNotRebased` (`lamina_ops::SaveState`): saves and ops are refused in `SavedNotRebased` and while a transaction is open; a failed save leaves the document `Dirty` with its overlay untouched. `SaveOptions` (`output`, `renumber`, `xref`, `eol`) and `SaveReport` (bytes written, mode, renumber map, append offset).
- **`Writer` / `incremental_update` / `XrefEol`**: the spike-era writer, moved from `lamina-cos` in B3b with its tests, for building files from scratch (tests, and generation until `lamina-build`).

Output is byte-deterministic (ADR 0001): ordered maps only, no clocks, `/ID` from a hash; every writer test saves twice and compares.

Tests (`tests/`, reading the shared [`fixtures/`](../../fixtures/README.md)): moved from `lamina-cos` with the writer: `golden.rs` (byte-exact goldens, now also `incremental-set-info.pdf` and `full-rewrite-hello.pdf`), `determinism.rs`, `incremental.rs`, `raw_writer.rs`, `roundtrip.rs` and the writer half of `review_fixes.rs`; new: `overlay_incremental.rs`, `full_rewrite.rs` (also every unencrypted corpus file in each layout), `rebase.rs`, `id.rs`, `sink_errors.rs`, `encrypted_base.rs`, `codes.rs` and `props.rs` (proptest, fixed seed: random ops → every writer → reopen gives the in-memory facts, twice the same bytes). `tests/common/` holds copies of `lamina-cos`'s helpers and content builder plus the golden samples; `examples/golden.rs` writes the goldens for `cargo xtask golden --update`.

`lamina-cos`, `lamina-model` and `lamina-ops` use this crate as a dev-dependency to build their test inputs (a cycle Cargo accepts for integration tests; `lamina-cos`'s own unit tests build files by hand instead).

```sh
cargo test -p lamina-save
```
