# Edit a PDF

Change an existing PDF in transactions you can undo, and replay edits stored as JSON.

You'll open a PDF, change its title and author, and save the edit after the original bytes. You need this whenever your app changes a file someone gave it: a corrected title, a rotated scan, a report marked final.

This example generates a draft report, opens its bytes and retitles it in one transaction. Then it saves incrementally, which keeps the draft's bytes at the start of the result, unchanged:

**TypeScript**

`packages/sdk/examples/generate-then-edit.ts`:

```ts
// Generate a document, then open its bytes, edit them and save incrementally. The edit changes
// the metadata in one transaction, and the incremental save keeps the generated bytes as they
// are, with one revision appended.
import { Builder, type BuilderOptions, Document, Font } from "@laminapdf/sdk";

/**
 * The generated file followed by the edit's revision. Needs `init({ text: true })`.
 *
 * @param options - can fix the file ID, the producer and the creation date.
 * @param editedAt - the modification date to record, as a PDF date string.
 */
export function generateThenEdit(options: BuilderOptions = {}, editedAt?: string): Uint8Array<ArrayBuffer> {
  return edit(generate(options), editedAt);
}

/** A one-page draft, saved (a new document is always saved as a full rewrite). */
export function generate(options: BuilderOptions = {}): Uint8Array<ArrayBuffer> {
  using b = new Builder(options);
  const page = b.page("A4");
  page.surface().text("Draft report", { font: Font.standard("Helvetica"), size: 20, at: [72, 96] });
  page.finish();
  b.metadata({ title: "Draft report" });
  using doc = b.finish();
  return doc.save();
}

/** Opens `bytes`, edits the metadata in one transaction (which `undo` could revert) and saves incrementally. */
function edit(bytes: Uint8Array, editedAt?: string): Uint8Array<ArrayBuffer> {
  using doc = Document.open(bytes);
  doc.transact((tx) =>
    tx.setMetadata(
      { title: "Final report", authors: ["Ada Lovelace"] },
      editedAt === undefined ? {} : { at: editedAt },
    ),
  );
  return doc.save({ mode: "incremental" });
}
```

**Rust**

`crates/laminapdf/examples/generate_then_edit.rs`:

````rust
//! Generate a document, then open its bytes, edit them and save incrementally.
//!
//! The edit changes the metadata with an op (undoable and serialisable), and the
//! incremental save keeps the generated bytes as they are, with one revision appended.
//!
//! ```sh
//! cargo run -p laminapdf --example generate_then_edit -- [out-dir]   # writes <out-dir>/generate_then_edit.pdf
//! ```

use std::error::Error;
use std::path::PathBuf;

use laminapdf::{
    BuildOptions, Builder, Document, Metadata, MetadataPatch, Op, OpenOptions, PageSize, PdfDate, PointPt, Pt,
    SaveMode, SaveOptions, SetMetadata, Standard14,
};

fn main() -> Result<(), Box<dyn Error>> {
    let out = PathBuf::from(std::env::args().nth(1).unwrap_or_else(|| "target/examples-out".into()));
    std::fs::create_dir_all(&out)?;
    let bytes = build(BuildOptions::new(), None)?;
    std::fs::write(out.join("generate_then_edit.pdf"), bytes)?;
    Ok(())
}

/// The generated file followed by the edit's revision. `edited_at` is recorded as the
/// modification date; `options` can fix the file ID, the producer and the creation date.
pub(crate) fn build(options: BuildOptions, edited_at: Option<PdfDate>) -> Result<Vec<u8>, Box<dyn Error>> {
    let generated = generate(options)?;
    edit(generated, edited_at)
}

/// A one-page draft, saved (a new document is always saved as a full rewrite).
pub(crate) fn generate(options: BuildOptions) -> Result<Vec<u8>, Box<dyn Error>> {
    let mut b = Builder::new(options);
    let helvetica = b.standard_font(Standard14::Helvetica)?;
    let mut page = b.page(PageSize::A4);
    page.surface().text(
        "Draft report",
        &helvetica,
        Pt::new(20.0),
        PointPt::from_points(72.0, 96.0),
    )?;
    page.finish()?;
    b.metadata(Metadata::default().with_title("Draft report"));
    Ok(b.finish()?.save(&SaveOptions::new())?.bytes)
}

/// Opens `bytes`, edits the metadata (the Info dictionary and the XMP packet together) in one
/// transaction (which `undo` could revert) and saves incrementally: `bytes` unchanged, then the
/// appended revision.
fn edit(bytes: Vec<u8>, edited_at: Option<PdfDate>) -> Result<Vec<u8>, Box<dyn Error>> {
    let mut doc = Document::open_bytes(bytes, OpenOptions::new())?;
    let patch = MetadataPatch::new()
        .title(Some("Final report"))
        .authors(&["Ada Lovelace"]);
    doc.apply(vec![Op::from(SetMetadata::new(patch, edited_at))])?;
    let options = SaveOptions::new().with_mode(SaveMode::Incremental);
    Ok(doc.save(&options)?.bytes)
}
````

Your edits live beside the bytes you opened and never change them. Nothing reaches a file until you save. [How Lamina PDF thinks about a PDF](../../pages/concepts/how-lamina-thinks.md) explains why it works this way.

## Group edits into a transaction

`doc.transact(tx => …)` collects edits, such as `setMetadata` and `rotatePage`, and applies them together when the callback returns. If the callback throws, none of them apply. The callback is synchronous, and editing or saving the same document inside it fails with `nested-transaction`.

## Change the metadata

`doc.setMetadata({ title, authors })` changes a document's title, authors, subject, keywords, dates, and the creating and producing applications, and `doc.removeMetadata(["keywords"])` removes fields. A PDF keeps these facts twice, in its Info dictionary and its XMP metadata, and each edit writes both. `doc.metadata()` reads them back. [Edit the metadata](../../pages/recipes/edit-metadata.md) has the whole program.

## Organise the pages

Five calls change which pages a document has and their order: `doc.deletePages(ids)`, `doc.movePages(ids, "start")`, `doc.insertBlankPages("end", 1, { width: 612, height: 792 })`, `doc.rotatePages(ids, 90, { mode: "turn" })` and `doc.reversePages(ids)`. They name pages by ID, and a page keeps its ID when it moves. Deleting a page sends the bookmarks and links that pointed at it to the nearest page left, and deleting every page is refused. [Organise pages](../../pages/recipes/organise-pages.md) has the whole program.

`doc.duplicatePages(ids, "end")` copies pages. A copy shares its page's content but gets annotations and form fields of its own, so filling in the copy leaves the original alone. [Duplicate pages](../../pages/recipes/duplicate-pages.md) shows a form page copied.

`doc.cropPages(ids, { top: 36, left: 36 })` crops pages by margins of the page as it shows, so one set suits every size and rotation, and `doc.setPageBoxes(ids, { trim: [x0, y0, x1, y1] })` sets any of a page's five boxes. A crop only hides content: the edit's `croppedContentRemains` lists the pages whose hidden text is still in the file. [Crop pages](../../pages/recipes/crop-pages.md) has the whole program.

`doc.resizePages(ids, { width: 612, height: 792 })` puts pages on new paper, scaling their content to fit, and `doc.setOrientation(ids, "landscape")` turns pages shown the other way. Links, notes, bookmarks and the opening view move with the content. [Resize pages](../../pages/recipes/resize-pages.md) has the whole program.

`doc.addSource(bytes)` opens another PDF as a source of pages. `doc.insertPagesFrom(source.id, pages, "end")` copies its pages in, and `doc.replacePages(targets, source.id, pages)` puts them in other pages' places. `doc.extractPages(ids)` makes a new PDF from some pages. [Copy pages between PDFs](../../pages/recipes/copy-pages.md) shows each.

`Document.merge(files)` makes one document from several files, with a bookmark for each, and `doc.mergeDocuments(sources, "end")` merges sources into an open document as one edit. `doc.split({ bookmarks: 1 })` makes one document per chapter. A merge of tagged PDFs makes a tagged file, each file's tags under a `Part` named after it. [Merge and split PDFs](../../pages/recipes/merge-and-split.md) shows both.

## Name the pages

A viewer's page box can show a page's label instead of its number: "Cover", "iv" or "A-3". `doc.setPageLabels(ranges)` replaces a document's labels. Each range starts at a page, named by its ID, and labels that page and the ones after it until the next range. A range has a style (decimal, roman or letters, upper or lower case), a prefix and a first number. The first range must start on the first page and the rest must follow in page order, or the edit fails with `invalid-label-ranges`. An empty list removes the labels.

This example labels a cover, roman front matter and a numbered body:

**TypeScript**

`packages/sdk/examples/page-labels.ts`:

```ts
// Give a document page labels, the names viewers show for its pages: "Cover" for the first,
// lowercase roman numerals for the front matter, and numbers from 1 where the body starts.
// A range names its first page by ID and labels the pages up to the next range. The edit is one
// op, saved incrementally after the original bytes.
import { Document } from "@laminapdf/sdk";

/** The document with a cover, roman front matter from its second page and numbers from its third. */
export function pageLabels(bytes: Uint8Array): Uint8Array<ArrayBuffer> {
  using doc = Document.open(bytes);
  const [cover, contents, body] = doc.pages;
  if (cover === undefined || contents === undefined || body === undefined) {
    throw new Error("the example needs three pages or more");
  }

  doc.setPageLabels([
    { page: cover.id, prefix: "Cover" },
    { page: contents.id, style: "lowerRoman" },
    { page: body.id, style: "decimal" },
  ]);

  // `doc.pages[i].label` now reads "Cover", "i", "1", "2", …
  return doc.save({ mode: "incremental" });
}
```

**Rust**

`crates/laminapdf/examples/page_labels.rs`:

````rust
//! Give a document page labels, the names viewers show for its pages: "Cover" for the first,
//! lowercase roman numerals for the front matter, and numbers from 1 where the body starts.
//!
//! A range names its first page by ID and labels the pages up to the next range. The edit is
//! one op, saved incrementally after the original bytes.
//!
//! ```sh
//! cargo run -p laminapdf --example page_labels -- in.pdf [out-dir]   # a file of three pages or more
//! ```

use std::error::Error;
use std::path::PathBuf;

use laminapdf::{Document, LabelStyle, Op, OpenOptions, PageLabelRange, SaveMode, SaveOptions, SetPageLabels};

fn main() -> Result<(), Box<dyn Error>> {
    let mut args = std::env::args().skip(1);
    let input = PathBuf::from(args.next().ok_or("usage: page_labels in.pdf [out-dir]")?);
    let out = PathBuf::from(args.next().unwrap_or_else(|| "target/examples-out".into()));
    std::fs::create_dir_all(&out)?;
    let labelled = label(std::fs::read(input)?)?;
    std::fs::write(out.join("page_labels.pdf"), labelled)?;
    Ok(())
}

/// The document with a cover, roman front matter from its second page and numbers from its
/// third, saved incrementally.
pub(crate) fn label(bytes: Vec<u8>) -> Result<Vec<u8>, Box<dyn Error>> {
    let mut doc = Document::open_bytes(bytes, OpenOptions::new())?;
    if doc.page_count()? < 3 {
        return Err("the example needs three pages or more".into());
    }
    let [cover, contents, body] = [0, 1, 2].map(|index| doc.page_info(index).map(|page| page.id));

    doc.apply(vec![Op::from(SetPageLabels::new(vec![
        PageLabelRange::new(cover?, None).with_prefix("Cover"),
        PageLabelRange::new(contents?, Some(LabelStyle::LowerRoman)),
        PageLabelRange::new(body?, Some(LabelStyle::Decimal)),
    ]))])?;

    // `doc.page_info(i)?.label` now reads "Cover", "i", "1", "2", …
    Ok(doc.save(&SaveOptions::new().with_mode(SaveMode::Incremental))?.bytes)
}
````

## Undo and redo

`doc.undo()` reverts the last transaction as a whole, and `doc.redo()` applies it again. A transaction is the unit of undo, so group the edits a user would expect to undo together. A new transaction clears what redo could apply.

Both return a `Reverted` record, `{ outcome, touchedPages }`, or `undefined` when there is nothing to undo or redo. `outcome` is `applied`, or `partial` when a later edit replaced part of the change, which keeps the later value, or `skipped` when nothing could be restored. `touchedPages` lists the IDs of the pages the transaction changed, so a viewer redraws only those. `doc.apply(ops)` returns `touchedPages` too, and `changed`, which is false when the edit only set values the document already had and so left nothing to undo.

*One undo reverts a whole transaction; redo applies it again.*

Three transactions run in order: the first runs `setInfo` and `rotatePage`, the second `rotatePage`, and the third both. `doc.undo()` reverts the last transaction as a whole, and `doc.redo()` applies it again. A new transaction clears what redo could apply.

## Replay edits stored as JSON

Every edit is also a plain JSON object, such as `{ op: "rotatePage", args: { … } }`. So you can store edits, send them to a server and replay them later. `doc.apply(ops)` applies a list of them as one transaction, and `doc.applyLog({ v: 1, ops })` replays a saved log.
