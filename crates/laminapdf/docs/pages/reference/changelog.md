# Changelog

What changed in each Lamina PDF release, newest first.

Every Lamina PDF package shares one version, so each entry covers all of them, from the Rust crates to `@laminapdf/sdk` and the viewer. The first version on npm and crates.io is `0.2.0-alpha.2`.

Each entry lists its changes under two headings:

- **Minor Changes** holds every breaking change. Before version 1.0, a breaking change raises the minor version (`0.2` to `0.3`), as the [stability policy](../../pages/reference/stability.md) explains. In the alphas, new features were listed here too. Read this list first when you upgrade: a breaking change's entry says what to change in your code.
- **Patch Changes** holds fixes and, from `0.2.0` on, new features. Neither needs a change to your code.

For example, to move from `0.2.0` to `0.3.1`, read the Minor Changes of `0.3.0`; `0.3.1` needs no code change. To move from an alpha to `0.2.0`, read both headings of every entry after your alpha: the alphas promised nothing to each other.

## 0.3.0

### Minor Changes

- [`bc1bff5`](https://github.com/laudebugs/laminapdf/commit/bc1bff5): Copy pages between documents. `doc.addSource(bytes)` opens another PDF as a source and returns its ID and page IDs. `doc.insertPagesFrom(id, pages, at)` copies its pages in, and `doc.replacePages(targets, id, pages)` puts them in other pages' places, keeping the bookmarks, links and named destinations that pointed at the old pages. A copy keeps its annotations and form fields. A field whose name is taken becomes `<name>#2`, or shares the value with `{ fields: "link" }`. A link to a page left behind is removed (`linksRemoved`). Copies come without tags (`tagsDropped`), and on a PDF/UA-1 file saving then warns with the new code `imported-tags-dropped`. `doc.extractPages(ids)` makes a new document from pages, with their labels, and `doc.exportRanges(ranges)` makes one per range.
  
In Rust: `InsertPagesFrom`, `ReplacePages`, `Carry`, `FieldClash`, `Document::add_source`, `source_pages`, `extract_pages`, `export_ranges`, `export_ranges_with` and `ExportJob`, with `Edited::links_removed` and `Edited::tags_dropped`. `laminapdf-model` gains `FieldNames::clashes`, `Document::field_by_name` and `Outline::named_destination_value`.
- [`2948e3f`](https://github.com/laudebugs/laminapdf/commit/2948e3f): Duplicate pages: `doc.duplicatePages(ids, at)` copies pages to a place in the document, as one edit that undo reverts. A copy shares its page's content but gets annotations of its own, and each form field it shows becomes a new field named `<name>#2` (or the next free number) with its own value. A signature's field isn't copied. The edit's `fields` lists each field the copy renamed or left out. In a tagged document the copy gets tags of its own. Content of an element that continues onto another page stays untagged on the copy, and the edit's `tagsIncomplete` lists that copy. On a PDF/UA-1 file, the save plan then warns with the new code `duplicate-tags-incomplete`.
  
In Rust: `DuplicatePages`, with `Edited::fields` (`FieldChange`, `FieldOutcome`) and `Edited::tags_incomplete`. `laminapdf-model` gains `Document::field_name`, `Document::field_names` and `FieldNames::unique_partial`, the rule that names a copied field (a copy of `total#2` is `total#3`).
- [`6e9dd39`](https://github.com/laudebugs/laminapdf/commit/6e9dd39): Turn images into a PDF and export pages as PNG, JPEG or TIFF from TypeScript, as Rust already can:
  
- `imagesToPdf(images, options)` makes a document with one page per image, as `laminapdf::images_to_pdf` does: JPEGs embedded as they are, each image drawn upright, and pages the image's size or a paper size (`fit: "A4"`, or `[width, height]` in points) with the image fitted inside the margins. It needs the extract or the text module (`init({ extract: true })`).
- In the web reader's worker, `ViewerClient.exportPage(index, { format, dpi, quality })` draws a page as PNG or JPEG, and `exportTiff(indexes, { dpi, multiPage })` as TIFF, every page in one file or one file each. The resolution is recorded in each file. The TIFF writer is a WebAssembly module of its own, `@laminapdf/wasm/tiff`, loaded the first time a TIFF export starts.
- In Rust, `laminapdf_render::TiffWriter` (feature `tiff`) writes a TIFF from pixels you drew yourself, a page at a time.
- [`d9b6acf`](https://github.com/laudebugs/laminapdf/commit/d9b6acf): Choose how a PDF opens, and read its article threads. `doc.setInitialView(patch)` sets the page and zoom a file opens at, the panel beside the page (bookmarks, thumbnails, attachments, layers or full screen), the page layout and the reader window's requests, such as the title in the title bar. Every PDF reader reads these choices. `doc.initialView()` reads them back, page targets in page space, and `doc.threads()` lists the file's article threads with each part's page and rectangle. An open action that runs a script is reported, never run, and never replaced: an edit that names the opening page fails with `open-action-not-destination`. In Rust: the `SetInitialView` op, `Document::initial_view` and `Document::threads`.
- [`e416ac6`](https://github.com/laudebugs/laminapdf/commit/e416ac6): Merge and split documents. `Document.merge(files)` makes one document from several files. Each file gets a bookmark named by its `title`, holding the file's own bookmarks, and `{ outline: "keep" }` or `"none"` changes that. `doc.mergeDocuments(sources, at)` merges source documents into an open one as one edit. The files' form fields, named destinations, layers and page labels come along; a destination whose name is taken becomes `<name>#2` (`renamedDestinations`), and bookmarks to pages left behind are dropped (`bookmarksDropped`). Merging into a file that claims a PDF/A level from one that doesn't claim it warns with the new code `imported-pdfa-unchecked`. `doc.split({ count })`, `split({ ranges })` and `split({ bookmarks: level })` cut a document into new ones, each with the bookmarks that go to its pages.
  
In Rust: `MergeDocuments`, `MergeSource`, `MergeOptions`, `OutlineMerge`, `MergeInput`, `RenamedDestination`, `SplitBy`, `Document::merge`, `merge_with`, `merge_job` and `MergeJob`, `Document::split`, `split_with` and `split_job`, with `Edited::renamed_destinations` and `Edited::bookmarks_dropped`. `Document::extract_pages` now carries the bookmarks that go to its pages and the layers.
- [`2081146`](https://github.com/laudebugs/laminapdf/commit/2081146): Edit bookmarks and named destinations: `addOutlineItem`, `updateOutlineItem`, `moveOutlineItem` and `deleteOutlineItem` add, change, move and delete bookmarks, with their colour and bold or italic style, and `setNamedDestination`, `renameNamedDestination` and `deleteNamedDestination` manage the names links jump to. A rename follows the bookmarks and links that use the name. The outline's links and counts stay consistent after every edit, and a broken outline is rewritten whole by the first edit. `outline()` now gives each bookmark's `id`, the name or web address it goes to, and its style; `namedDestinations()` lists every name; `destinationAt(page, view)` turns a place in the viewer into a destination. The Rust crates have the same ops (`laminapdf::AddOutlineItem` and the rest) and methods.
- [`8f21b98`](https://github.com/laudebugs/laminapdf/commit/8f21b98): Set a document's page labels, the names viewers show for its pages ("Cover", "iv", "A-3"):
  
- `doc.setPageLabels(ranges)` replaces them in one edit, and `Transaction.setPageLabels` adds the same edit to a transaction. Each range names its first page by ID, with a style (`decimal`, `upperRoman`, `lowerRoman`, `upperLetters`, `lowerLetters`), a prefix and a first number; no ranges remove the labels.
- Ranges that don't start on the first page, are out of page order or number from 0 fail with `invalid-label-ranges`, whose `data.what` says which rule.
- `doc.pages[i].label` reads the new labels.
  
In Rust: the `SetPageLabels` op with `PageLabelRange`, `LabelStyle` exported in every build, and in `laminapdf-model` `LabelRange::new`, `PageLabels::from_ranges`, `PageLabels::is_written` and the `tree-write` feature.
- [`bab4c9f`](https://github.com/laudebugs/laminapdf/commit/bab4c9f): Organise a document's pages: insert blank pages, delete pages, move them, rotate them (to an angle, or by an angle from where each one stands) and reverse their order, each as one edit that undo reverts. Pages keep their IDs while they move. Deleting a page sends the bookmarks, links, named destinations and opening view that went to it to the nearest page left, showing the whole page. Ask instead and they lose their destination. Either way, the edit lists each one. The accessibility tags and form fields that only a deleted page used go with it; signature fields stay, so their signatures still count when you save. Page labels stay with their pages. Deleting every page is refused with the new code `no-pages-left`. A blank-page count or size out of range is refused with `invalid-op`.
  
In Rust: `InsertBlankPages`, `DeletePages`, `MovePages`, `RotatePages` and `ReversePages`, applied with `Document::apply`; `Edited` gains `page_order` and `references`. `PageSize` moves to `laminapdf-model`, and `laminapdf-build` re-exports it, so its path through the builder and the façade is unchanged. Rotating the page that holds a signed signature's widget now makes the save a conflict, as deleting that page does.

### Patch Changes

- [`a815a29`](https://github.com/laudebugs/laminapdf/commit/a815a29): Documents can now list a page's annotations and change or delete them. `doc.pageAnnotations(index)` returns each annotation in page space: its ID, subtype, rectangle, text, author, dates, flags, colour, reply and group links, and its own geometry (highlight areas, ink strokes, a polygon's vertices, a line, a callout). The new `updateAnnot` op changes an annotation's text, author, subject, flags or position, keeping its appearance; `deleteAnnot` deletes it together with its pop-up, its replies and the rest of its group, and the edit lists what went with it in `alsoDeleted`. A locked annotation refuses the change.
- [`1f0cd41`](https://github.com/laudebugs/laminapdf/commit/1f0cd41): The thumbnail strip no longer raises "the worker stopped" as an unhandled error when the document worker crashes, is stopped or is terminated while a thumbnail is drawing. The thumbnail keeps its placeholder. The client's `crashed` and `restarted` events already report a crash or a restart.

## 0.2.0

### Minor Changes

- [`abd2520`](https://github.com/laudebugs/laminapdf/commit/abd2520): `builder.flow(document, { data, fonts, images })` lays out a `laminapdf.document/1` document as tagged pages that flow. It needs `init({ text: true })`. The document is plain objects, typed by `FlowDocument`, so your editor catches a misspelt key or an unknown block `type`. A template with placeholders is a `FlowTemplate`: given `data`, `flow` fills it first, and a value the data lacks fails with `template-data-missing` and its pointer. The fonts and images the document names come by name as `Font`s and `Image`s. The new `invoice-from-json` example fills a two-page invoice from JSON.
- [`97cbf89`](https://github.com/laudebugs/laminapdf/commit/97cbf89): In TypeScript, `export-failed` is a new error code: a page export's encoder failed. The functions below are Rust only for now; their TypeScript versions follow.
  
In Rust, turn images into a PDF, and export pages as PNG, JPEG or TIFF:
  
- `laminapdf::images_to_pdf(&images, &ImagesOptions)` makes a document with one page per image. JPEGs are embedded as they are, and each image is drawn upright, as its EXIF orientation says. Pages take the image's size at its resolution, or a paper size with the image fitted inside the margins (`ImagePages::Fit`). `Image::orientation()` reads the orientation.
- `laminapdf_render::export_pages` (feature `export`) draws pages one at a time and encodes them as PNG, JPEG or TIFF at a resolution you choose, with the resolution recorded in each file. A multi-page TIFF holds every page in one file.
- [`755d6ec`](https://github.com/laudebugs/laminapdf/commit/755d6ec): Edit a document's metadata with the Info dictionary and the XMP metadata kept in step:
  
- `doc.setMetadata(patch, { at, replaceMalformed })` sets or removes the title, the authors, the subject, the keywords, the creating and producing applications and the dates. In PDF 2.0 files only the dates go to the Info dictionary.
- `doc.removeMetadata(keys)` removes fields from both.
- `doc.metadata()` reads both copies together and says where they disagree.
- `doc.plan(options)` says how a save would go, without saving: the save constraint, the signatures, the refusal code, and the PDF/A and PDF/UA claims the edits break.
- `doc.wouldViolate(op)` checks one edit against the signatures.
- Saves take `metadataDate`, the time of the save, to stamp it as the modification date, and `instanceId` to set the XMP instance ID; either option turns the stamp on. The report says whether it happened (`metadataUpdated`, `metadataNotUpdated`).
- `Transaction.setMetadata` and `removeMetadata` take the same options.
- The `setInfo` op is deprecated in favour of `setMetadata`. It still applies, and now updates existing XMP metadata too.
  
In Rust: `SetMetadata`, `RemoveMetadata`, `Document::metadata`, `Document::plan`, `Document::would_violate` and `SaveOptions::with_metadata_date`; `SetInfo` is `#[deprecated]`.
- [`9f555a2`](https://github.com/laudebugs/laminapdf/commit/9f555a2): Groundwork for copying pages between documents:
  
- `unknown-source` is a new error code: an op or a call named a source document that wasn't added to the session.
  
In Rust: `laminapdf_ops::Document::add_source(bytes, password)` opens another PDF as a source document and returns its `SourceId`, the SHA-256 of its bytes, so the same file has the same ID on every device. `source_document(id)` returns it, and `blobs()` the session's `BlobStore`. `laminapdf_model::ObjectCopier` copies pages, and everything they reach, from one document into another, sharing what several pages use, within `Limits`. The ops that use them, inserting pages from another file and merging, come next.
- [`f49cfd9`](https://github.com/laudebugs/laminapdf/commit/f49cfd9): `client.metadata()` reads the open document's metadata as its edits leave it: the title, authors, subject, keywords, the creating and producing applications and the dates, from the Info dictionary and the XMP metadata together, with the fields where they disagree. A properties form can show it, then apply its changes with `viewer.edits.apply` as `setMetadata` and `removeMetadata` ops.

### Patch Changes

- [`7a59051`](https://github.com/laudebugs/laminapdf/commit/7a59051): Every export of `@laminapdf/sdk` now says which release added it: a `@since 0.2.0` tag, which the API reference shows as "Since" and editors show on hover. In Rust, every public item's docs end with "Added in 0.2.0." Items added later will name the release they first ship in. The types `ExtractFormat`, `ReadingOrder`, `SplitOn`, `TableMode`, `LayoutRegion`, `ModelInfo`, `ModelRequest`, `Models`, `OcrWord` and `RegionLabel` are now declared in `@laminapdf/sdk` with their own docs; they're the same types as before.
- [`e5fa57d`](https://github.com/laudebugs/laminapdf/commit/e5fa57d): `builder.markdown` and `builder.flow` now lay a tab in a code block out as spaces to the next multiple of four columns, so the extracted text lines up as drawn. A tab anywhere else in the text becomes one space. Before, a font with CFF outlines (an `.otf` font) raised a `tounicode-conflict` warning for each code block line with a tab.
- [`2e74d7d`](https://github.com/laudebugs/laminapdf/commit/2e74d7d): Every error's and warning's `docsUrl` now opens its page on the docs site, `https://docs.laminapdf.com/reference/codes/<code>/`, instead of the Markdown file on GitHub. The code still ends the path.
- [`8ae1bae`](https://github.com/laudebugs/laminapdf/commit/8ae1bae): `FlowTemplate` is now an interface rather than a type alias, with the same keys and the same checks, so the API reference names it where `builder.flow()` takes it instead of spelling out every key of every block. Its reference page explains the placeholders, with an example. Every type declaration in the TypeScript reference is now a code block, one key or union case to a line.
- [`cafed9f`](https://github.com/laudebugs/laminapdf/commit/cafed9f): `0.2.0` is the first release that isn't an alpha. A plain `npm install @laminapdf/sdk` or `cargo add laminapdf` now installs it, and from here on releases follow SemVer as the [stability policy](https://docs.laminapdf.com/reference/stability/) says: a breaking change raises the minor version (`0.2` to `0.3`), so an upgrade within `0.2.x` needs no change to your code. The `alpha` npm tag stays on `0.2.0-alpha.6`.
- [`bd0148e`](https://github.com/laudebugs/laminapdf/commit/bd0148e): The packages' descriptions, keywords and README openings now say what each package does for you, and each package links to the issue tracker.
- [`55fc5eb`](https://github.com/laudebugs/laminapdf/commit/55fc5eb): In Rust, the save planner now checks page edits field by field. The save is now a conflict when a page edit deletes a signed signature's widget or changes how it is shown (`Restriction::SignedWidget`), or does the same to a field that a signature's lock covers (`Restriction::FieldMdp`); `Violation::field` names the field. Moving a page breaks neither. `laminapdf_ops::Applied::widgets` and `PendingChanges::widgets()` record the fields an edit touched, and `Op::page_changes()` lists the pages it will change, so `SavePlanner::would_violate` can warn before the edit. The page edits that report them come next.
- [`82d3c07`](https://github.com/laudebugs/laminapdf/commit/82d3c07): In Rust, `Reveal::redaction_warnings()` gives the warnings `Document::redaction_warnings` would (`covered-text`, `redaction-not-applied` and `text-in-earlier-revision`, in the same order and with the same counts) from what `Document::reveal` already found. When you need both, call `reveal` and read the warnings from its result. The file's pages and earlier revisions are then read once instead of twice.
- [`414a955`](https://github.com/laudebugs/laminapdf/commit/414a955): The Rust crate `laminapdf-content` can now add content to a page without changing what the page already draws. `PageContentWriter` wraps a page's content in `q … Q`, adds streams before or after it, and registers Form XObjects, graphics states and fonts under names the page doesn't use yet. A page that shares its resources or content streams with other pages keeps them unchanged.
- [`1ad4b68`](https://github.com/laudebugs/laminapdf/commit/1ad4b68): After the document worker crashes, or `stop()` ends it, `render()` sends each render that was waiting again, once, in the restarted worker. ADR 0009 §3.6 describes this. The pages and thumbnails those renders were for are drawn again. Before, they stayed blank, and the thumbnail strip reported "the worker stopped" to the page as an unhandled error. The render that was drawing when the worker was lost still fails, so a page that crashes the engine can't loop. When the restart can't reopen the document (an encrypted one waits for its password), a waiting render rejects with an `AbortError`.

## 0.2.0-alpha.6

### Minor Changes

- [`810d0d4`](https://github.com/laudebugs/laminapdf/commit/810d0d4): Rust callers can now describe flowing pages as JSON (TypeScript support follows), in the format `laminapdf.document/1`, and lay them out with `Builder::document`. A document names its page, its text styles and its blocks (paragraphs, headings, lists, tables, figures, a contents page and more), and its fonts and images by name, with their bytes given beside it. Its JSON Schema ships in `docs/schemas/document.schema.json`.
  
A template is a document with placeholders that `flow::document::fill` replaces from data: `$data` for a value, `$each` to repeat a block or table row per item, `$item` for a value of the current item, and `$if` to keep a block only when a value is there. Templates have no expressions, so the data arrives formatted.
  
A document with an unknown key, a missing one or a value of the wrong kind fails with `invalid-document`, which names the value's place in `data.pointer` and suggests the closest key in `didYouMean`. A template whose data lacks a value fails with `template-data-missing`, and data of the wrong kind with `template-data-type`.
- [`64f7860`](https://github.com/laudebugs/laminapdf/commit/64f7860): Turn Markdown into a PDF from TypeScript: `builder.markdown(text, options)` turns CommonMark (with tables, footnotes, strikethrough and task lists) into tagged pages that flow, and takes the title and language from the front matter. Fonts come by role (`regular`, `bold`, `italic`, `boldItalic`, `mono`, `fallbacks`) and images by the name the Markdown uses; nothing is fetched. `options.page` sets the page size, margins, header and footer, and `contents` adds a contents page. `Font.fromCollection(bytes, index)` loads one face of a font collection (`.ttc`).
- [`70eb584`](https://github.com/laudebugs/laminapdf/commit/70eb584): Undo and redo say which pages to draw again. `doc.undo()` and `doc.redo()` now return `{ outcome, touchedPages }` instead of the outcome alone, so a viewer can redraw only the pages the undone or redone edit changed. `doc.apply(ops)` also says whether the edit `changed` anything: an edit that only sets values the document already had leaves nothing to undo. `doc.isEncrypted` tells you whether the file is encrypted. The Rust `Document::undo` and `redo` return the same `Reverted` record, and `Edited` has `changed`.
- [`70eb584`](https://github.com/laudebugs/laminapdf/commit/70eb584): An edit session for the open document. `viewer.edits` holds its history: each step with its label, pages and time, how many steps are done, and how many changes are unsaved. It runs `apply(ops, label)`, `undo()`, `redo()` and `goTo(step)` one after another, and each redraws only the pages it touched. An undo that could restore only part of a step says so, and `onFailed` reports a call that failed. The history keeps 500 steps. If the document worker restarts, it opens the file again and replays the session's steps, so nothing is lost; when the replay couldn't reproduce the document, it says the edits were lost. An encrypted document can't be edited yet, and says so when it opens (`encrypted`). When the zoom fits the width or the page, a page you turn is fitted again.
- [`5dca35b`](https://github.com/laudebugs/laminapdf/commit/5dca35b): The viewer can put a reader back where they stopped. `client.open()` now answers with `fingerprint`, a hash of the file's first revision (`"fp1:"` and a SHA-256). It stays the same for a renamed copy and after an incremental update, so it can key a saved position. `viewer.viewPosition()` gives the place in view as a page and point, the zoom and the rotation, and `viewer.restore(position)` goes back there as a history jump, so Back returns to page 1. When the position is restored in the task that opened the document, the first frame paints that page and no other. A view opened or restored while its container is hidden now waits until it is shown, then starts at the top or at the restored place. Before, it kept the previous document's scroll.
- [`37b5348`](https://github.com/laudebugs/laminapdf/commit/37b5348): Edits show on screen. `viewer.applyEdit(ops)` applies `@laminapdf/sdk`'s ops to the open document as one transaction and redraws only the pages they touched: a turned page draws turned, at its new size, while every other page keeps what it drew. `ViewerClient.applyEdit(ops)` makes the edit alone, and `viewer.invalidate(pages, sizes?)` redraws any pages you name. A metadata edit redraws nothing, and a failed edit leaves the pages as they were.

## 0.2.0-alpha.5

### Minor Changes

- [`526aae3`](https://github.com/laudebugs/laminapdf/commit/526aae3): Reader mode for every PDF. When a file has no tags, or its tags fail reader mode's checks, `doc.reflow()` reads the page layout instead of refusing: `source` is `"approximate"` and `reason` says why the tags weren't used. A scanned page, or one whose column order extraction doubts, comes back as a `page-image` block with `why` (`"scanned"` or `"uncertain"`) and the page's text for searching. Tables and pictures are crops, and their captions are kept with them. Only a file with nothing to show has `available: false`, with the reason `"nothing"`.
- [`5fc1f96`](https://github.com/laudebugs/laminapdf/commit/5fc1f96): `doc.properties()` reads what a properties view shows about a document in one call. It returns the Info entries, with the creation and modification dates as ISO 8601, and the XMP packet as text. It also gives the PDF version, page count, file size, whether the file is linearized and tagged, and the fonts the pages use (name, type, embedded, subset, encoding). Encryption comes with the author's permissions, and signatures are counted, never verified. `contains` says whether the file holds JavaScript, attachments or a form. It needs the extract or text module. For Rust callers, `Document::properties()` returns the same as `DocumentProperties`, and `laminapdf-model` gains `Pages::fonts()` and `Document::xmp_packet()`.
  
The viewer's client gains `properties()`, `printPage(index, { dpi, annotations })` and `fileBytes()`. `printPage` draws a page in the document worker for printing, with annotations as their print flags say, and returns it as a PNG. `fileBytes` returns a linked file's bytes as opened.
- [`95d2a70`](https://github.com/laudebugs/laminapdf/commit/95d2a70): Reader mode for tagged PDFs. `doc.reflow()` returns the document's blocks in its structure tree's order: headings, paragraphs, list items, quotes, captions and notes as text, and each figure, formula and table as a crop of its page with its alternate text, never as reflowed text. It checks the tree first: a file whose tree it can't trust comes back with `available: false` and the reason. It needs the extract module. The viewer's worker serves it as `client.reflow()`.
- [`513aeb3`](https://github.com/laudebugs/laminapdf/commit/513aeb3): Links in PDFs now work in the viewer. `doc.pageLinks(index)` lists a page's links in page space, each with what following it does: a place in the document, a web address, another file, a named action, or an action such as JavaScript, which Lamina PDF never runs. The viewer draws an anchor over each link. Links inside the document go there, web links ask the app to confirm first, and anything else does nothing. `viewer.history` records each jump, so Back returns to where the reader was, and the web reader keeps those jumps in the browser's history.
- [`771fafd`](https://github.com/laudebugs/laminapdf/commit/771fafd): Pages can be drawn in Sepia, Dark or High contrast instead of their own colours. Images and annotations keep theirs, and so does text under a highlight.
  
- **Render request:** `RenderRequest.appearance` is `"original"` (the default), `"sepia"`, `"dark"` or `{ kind: "high-contrast", ink, paper }`, for both backends.
- **Colour maps:** `recolourRgb` and `recolourTile` in `@laminapdf/render` give the same bytes as the Rust crate's.
- **Viewer:** `setAppearance()` redraws the pages in view in the new colours, keeping the scroll position. The thumbnails follow.
- [`bc3d9e0`](https://github.com/laudebugs/laminapdf/commit/bc3d9e0): Each page is now a region that screen readers name and can land on. `createViewer({ pages: { name, roleDescription, focusOnJump } })` sets each page's name, "Page 4 of 120" unless the app gives its own, such as "Page iv, 4 of 120". With `focusOnJump`, a jump moves focus to the page it lands on: a link, the outline, a thumbnail or go to page. A find match leaves focus in the find field.
- [`2675243`](https://github.com/laudebugs/laminapdf/commit/2675243): Copying from the viewer now follows the page's reading order. A selection across two columns copies the left column, then the right. A paragraph's lines join into one line, hyphenated words join again, and a blank line separates paragraphs. - [`08e123d`](https://github.com/laudebugs/laminapdf/commit/08e123d): `@laminapdf/viewer` exports only its documented API: `ViewerClient`, `createViewer` and `Viewer`, the types of their options, events and state, the protocol types `client.call` takes, and `MIN_ZOOM`/`MAX_ZOOM`. Its internal helpers (layout, canvas pool, bitmap cache, tiles, zoom maths), its byte-source functions and its protocol constants are no longer exported. Its worker no longer keeps a log of every render, which grew without bound, and no longer serves test-only methods. `@laminapdf/sdk/worker/server`'s `serve()` takes a `saveBudget` (work units per save step), and `workerStats()` reports the handles and calls a worker holds. `@laminapdf/sdk/worker` exports the `Emitter` its client uses.
- [`1c6e773`](https://github.com/laudebugs/laminapdf/commit/1c6e773): A render `data-pending` thrown inside `@laminapdf/sdk`'s worker now reaches the page with its byte ranges: `LaminaPdfError.ranges` lists them. Before, they arrived empty. `RenderError` has a new `toDiagnostic()`, which returns the plain error object every Lamina PDF surface uses, and the worker posts that object for any error that has the method. `RenderError`'s `toJSON()`, `reviveRenderError` and `SerializedRenderError` are gone, and `ByteRange` and `RenderErrorKind` name its types. The viewer's worker now throws `RenderError`s for `cancelled` and `disposed` instead of plain objects, so they reach the page with a `docsUrl`.
- [`6f7ae81`](https://github.com/laudebugs/laminapdf/commit/6f7ae81): `@laminapdf/render` has one `WasmSource` type for where an engine's `.wasm` comes from (a URL, a `Response` or a promise of one, the bytes or a compiled module). `CloneableWasmSource` is the subset a Web Worker can be sent. `initPdfium` and `initHayro` both take it: `@laminapdf/render-pdfium`'s own `PdfiumWasm` type is gone, and `initHayro` no longer takes a `Request`, a promise of anything but a `Response`, or a view of a `SharedArrayBuffer`. `RenderBackend` declares `memory()`, which both backends already had; a backend written outside this repository has to add it. The adapters share the page-index check, the read handling and the pending-range merging, so hayro now reports adjacent missing reads as one range, as PDFium did.
- [`2a9e364`](https://github.com/laudebugs/laminapdf/commit/2a9e364): The `rotatePage` op now reads a `/Rotate` stored as an integral real, such as `90.0`, as the rotation the page displays; before, it read 0. `PageBuilder.rotate` now refuses angles other than 0, 90, 180 and 270, as its type says. In the Rust crates, `Rotation` from `laminapdf-syntax` replaces `laminapdf-render`'s `ViewRotation` and the degrees in `RenderPage::rotate`, and `laminapdf_cos::Page` drops `media_box`, `crop_box` and `rotate`: read them, and their strict-mode errors, from `laminapdf-model`'s page view.

## 0.2.0-alpha.0

### Minor Changes

- [`2b4384a`](https://github.com/laudebugs/laminapdf/commit/2b4384a): Accessible and archival PDFs. A `profiles` option on the builder (`PDF/UA-1`, `PDF/A-2b`, `PDF/A-2u`, `PDF/A-3b`; `BuildOptions::with_profile` in Rust) checks each machine-checkable rule the document breaks when it finishes, with a coded error per rule: `missing-title`, `missing-lang`, `untagged-content`, `missing-alt-text`, `heading-level-skipped`, `unnumbered-heading-misused`, `invalid-structure-nesting`, `link-without-structure`, `link-without-contents`, `font-not-embedded`, `glyph-without-unicode`, `device-color-without-output-intent`, `embedded-file-forbidden`, `embedded-file-without-mime-type` and `profile-version-conflict`. The builder writes the XMP identification, `/DisplayDocTitle` for PDF/UA-1 and, for PDF/A, an sRGB output intent with a 480-byte embedded ICC profile. `attach(name, bytes, mime, { relationship })` adds associated files for PDF/A-3b, such as an e-invoice's XML. Every example that claims a profile is validated by veraPDF each night.
- [`592d285`](https://github.com/laudebugs/laminapdf/commit/592d285): `@laminapdf/sdk/worker` can be extended: `@laminapdf/sdk/worker/server`'s `serve({ methods })` adds methods to the same worker, called with `client.request(method, params, { priority, key })`. The worker runs higher priorities first and coalesces calls with the same key. `emit()` sends events to `client.on("event")`, and `connect({ onDiscard })` sees late answers (by default it closes their ImageBitmaps). The worker protocol is now version 2.
