# Rendering

`laminapdf-render`, the PDFium and hayro adapters, and their web packages.

Rendering (ADR 0004; `laminapdf-render`, C2b): `RenderBackend::open(Arc<dyn ByteSource>, &RenderOpenOptions)` (password, `RenderLimits`: `max_render_pixels` 16.7 MP, `max_render_side` 16,384, `max_input_bytes` 1 GiB) → `Box<dyn RenderDocument>` (`Send`): `page_count`, `page(i)` → `RenderPage` (displayed points, `/Rotate`), `plan(&RenderRequest)` → `TilePlan` (whole-page pixel size `max(1, floor(pt × scale))` after the view rotation, the tile, `byte_len`), `render(&req, &mut out, &CancelToken)` into straight-alpha RGBA8 rows of `width × 4`; `RenderRequest::page(i, scale)` with `with_clip(PixelRect)`, `with_rotation(Rotation)` (`laminapdf_syntax::Rotation`, re-exported; `RenderPage::rotate` is also a `Rotation`), `with_flags(RenderFlags { annotations, form_widgets, print, grayscale })`, `with_background(Option<Rgba8>)` (default white), `with_appearance(PageAppearance)` (U2c: `Original`, `Sepia`, `Dark`, `HighContrast { ink, paper }`; `src/appearance.rs`: each adapter draws the tile, then `recolour_tile` recolours it with integer colour maps, keeping opaque images, see-through images' samples and annotations as drawn; `@laminapdf/render`'s `recolourTile` ports it, `fixtures/appearance/colours.json` holds both to the same bytes). `RenderError` codes: `render-too-large`, `render-failed`, `render-backend-unavailable`, `export-failed` (feature `export`: `export_pages` to PNG, JPEG and TIFF, E3h) (`renderErrors`) plus reused ones. `HayroBackend` (feature `hayro`) reads the whole source (`read_all`: one `data-pending` lists every missing range); `laminapdf_render_pdfium::PdfiumBackend::from_env()` / `bind(dir)` (`LAMINA_PDF_PDFIUM_DIR`; one process-wide lock; pending reads recorded through custom file access). `CancelToken` lives in `laminapdf-syntax` (the façade re-exports it). Goldens: `fixtures/golden/render/<backend>/<stem>-p<N>.png` (96 dpi, white, SSIM ≥ 0.99 against the backend's own; `skip.json`), written by `laminapdf-render-pdfium`'s `goldens` example, which also writes the page appearance goldens `fixtures/golden/render-appearance/<backend>/<stem>-<appearance>.png` from `fixtures/appearance/` (`tools/fixtures/appearance.py`).

Web rendering (ADR 0004, 0009; C2c): `@laminapdf/render-pdfium`'s `await initPdfium(wasm)` (URL, `Response`, bytes or `WebAssembly.Module`; `PDFiumExt_Init`) and `@laminapdf/render-hayro`'s `await initHayro(wasm?)` return a `RenderBackend` (`name`, `version`, `memory()`); `open(source: RenderSource, { password, limits })` (`RenderSource` is `{ size, readSync(offset, length) }`, `undefined` = not there yet → `data-pending` with `ranges`; `bytesSource(bytes)`) → `RenderDocument` (`pageCount`, `page(i)`, `plan(req)` → `TilePlan`, `render(req, { signal })` → `{ width, height, pixels: Uint8ClampedArray }` straight RGBA, `close()`/`using`); requests are `{ page, scale, clip?, rotation?, flags?, background? }` (white by default, `null` transparent); `RenderError` with `isRenderError` (structural); an aborted signal throws `AbortError`, a closed document `disposed`. PDFium: custom file access over the source, a form-fill environment per document, widgets via `FPDF_RenderPageBitmap` + `FPDF_FFLDraw` at the shifted whole-page size, without widgets `FPDF_RenderPageBitmapWithMatrix` with `pageToTile`. hayro reads the whole source first and uses the Rust planner. `cargo xtask wasm` builds `lamina_pdf_render_hayro` and runs `@laminapdf/render-hayro`'s Node contract; `cargo xtask pdf-runtimes chromium|firefox|webkit` also runs both adapters' browser contract with C2b's goldens (PDFium SSIM ≥ 0.98 against the native goldens, hayro ≥ 0.99), then `@laminapdf/viewer`'s, `@laminapdf/tokens`', `@laminapdf/fonts`', `@laminapdf/icons`' and `@laminapdf/ui`'s browser tests; `cargo xtask size` checks `render_hayro` and `thirdParty.pdfium` (`pdfium.wasm` from node_modules).
