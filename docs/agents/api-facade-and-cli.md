# The façade and the CLI

The `laminapdf` façade crate and the `laminapdf` command-line tool with its MCP server.

Façade (ADR 0026, 0028; `laminapdf`, B5c): `laminapdf::Document::open_bytes(Vec<u8>, OpenOptions)` / `open_source(Arc<dyn ByteSource>, …)`; owned reads (`page_count`, `page_info(index)` → `PageInfo`, `page_infos`, `page_by_id`: one page-tree walk cached until the revision moves; `info`, `version` (the catalog's `/Version` when later than the header's), `is_encrypted`, `is_tagged` (`/MarkInfo /Marked`), `read_every_object` (for `laminapdf check`), `warnings()` → `WarningCursor::next_batch(max)`, build warnings first; `metadata()` → `DocumentMetadata`, Info and XMP read together (E1c)); `apply(Vec<Op>)` (one transaction; `Edited { touched_pages, changed, packet_rewritten, still_in_earlier_revisions }`), `apply_log(json)`, `undo`, `redo` (`Reverted { outcome, touched_pages }`); `plan(&SaveOptions)` → `PlannedSave` (mode or `refusal` code, constraint kind, signatures, violations, the metadata stamp, conformance warnings as `Warning::Conformance`) and `would_violate(&Op)` (E1c, `src/save_plan.rs`; `metadata()` in `src/metadata.rs`); `save(&SaveOptions)` → `Saved { bytes, report }` (rebased; `save_with(&SaveOptions, &CancelToken)` to stop it from another thread), or `save_job` stepped with `step(&mut doc, Budget::units(n))` → `Step::{Progress, Done}`; after `not-rebased`, `Error::saved_output()` and `rebase(bytes)`; every committed edit, undo, redo and save bumps a revision that each step checks (`document-changed`, `job-finished`, `cancelled`: `facadeErrors` in `codes.json`). `laminapdf::Error` flattens the crate errors, opaque behind `Error::Core(CoreError)` (ADR 0028 §8: no inner error type is re-exported but `BuildError` and `TextError`, which the builder's and `Font`'s own methods return; `pending_ranges()` reads a `data-pending` error's ranges), and has `code`, `kind`, `location`, `hint`, `docs_url` (read from `error_code()` → the generated `laminapdf::ErrorCode`, whose accessors are `match`es and whose `from_code` scans `ALL` (a string `match` cost the WASM modules a table as large as every code), `Warning::warning_code()` → `WarningCode`: `as_str`, `from_code`, `kind`, `summary`, `hint`, `docs_url`; a code a wrapped crate declares but `codes.json` lacks fails the build), `diagnostic()` and `Serialize` into the ADR 0026 object (document text only in `data`); `Warning` likewise. `page_text(index, &TextOptions)` / `page_texts(&TextOptions)` (all pages, one page-tree walk) (feature `extract`, which `text` implies, `laminapdf::extract`: `PageText`, `PageTextRun`, `Glyph`, `Quad`, `TextOptions::with_skip_invisible`; font cache per revision; B9d). The same feature brings `laminapdf-extract` (L3b): `Document::extract(&ExtractOptions)` / `extract_with(&options, &CancelToken)`, `extract_job(&options)` → `ExtractionJob::step(&doc, Budget)` (the façade's revision check: `document-changed`), `extract_json(&extraction, &markdown, chunks)` (adds the document's warnings), and `laminapdf::extract` re-exports the model and output types; `ExtractError` maps onto the façade's own errors (`Inner::Extract` for any other); `examples/extract_markdown.rs` (Markdown, JSON, chunks; a reading example with its own test in `tests/examples.rs`, `READERS`). Revisions (T2b, `src/revisions.rs`, every build): `revision_count()` and `open_revision(index, OpenOptions)` (the prefix up to that revision's `%%EOF`, from `laminapdf_cos::Document::revision_ends`, whose `revision_starts` `laminapdf-save`'s signature check shares, and beside it `revision_index()` (T2c: a `Revision` per revision, oldest first, with its section, end and the objects its sections list in use and free, empty when repaired); a linearized file's first-page section and a repaired file are one revision; `revision-index-out-of-range`). Failed redactions (`src/redaction.rs`, feature `extract`): `hidden_text(&CancelToken)` (`laminapdf_extract::hidden_text`, the page pass alone) and `redaction_warnings(&OpenOptions, &CancelToken)` → `Warning::Redaction(RedactionWarning)`: `covered-text` per page, `redaction-not-applied` per page with `Redact` annotations (from `Document::disclosure`), `text-in-earlier-revision` per earlier revision whose words (≥ 2 characters, counted) the latest holds less often, its `pages` those that lost them; an earlier revision that is malformed or unsupported is skipped, any other failure (a password, a limit, pending data) fails the call; so is a page whose text can't be read, in the hidden pass and the word comparison alike; counts and page indices only (`facadeWarnings` in `codes.json`). Page setup (E2g, `src/page_setup.rs`, every build): `page_boxes(index)` → `PageGeometry` (the five boxes in user space as readers use them, `OwnBoxes`, `user_unit`) and `label_ranges()` → the `PageLabelRange`s `SetPageLabels` takes back unchanged; WASM `pageBoxes`/`labelRanges` (extract and text modules), `@laminapdf/sdk`'s `doc.pageBoxes`/`doc.labelRanges`, `@laminapdf/viewer`'s `client.pageBoxes`/`client.labelRanges` (read from the worker's text-capable copy), and `EditResult.relabelled` (every page with its new label after an edit, undo or redo that sets the labels). Text boxes (E4e, E4l, `src/text_boxes.rs`, every build): `text_box_at(page, area, text)` and `callout_at(page, area, line, text)` → `AddAnnot` from page space; `text_box(id)` → `Option<TextBox>` (`page`, the text's `rect` and a callout's `line` in page space, `spec: FreeText` in user space, `color`, `simplified`), from `laminapdf_ops::read_text_box`; WASM `textBox(id)` (extract and text modules), `@laminapdf/sdk`'s `doc.textBox(id)`, `@laminapdf/viewer`'s `client.textBox(id)`. Navigation (C6a, `src/navigation.rs`, every build): `initial_view()` → `OpeningView { open: OpenTarget::{ReaderDefault, Page, Action}, page_mode, page_layout, preferences }` and `threads()` → `ArticleThread { title, parts: ThreadPart { page, rect } }` in page space (E3d, `src/initial_view.rs`), `outline()` → `OutlineNode { title, open, target, children }` and `named_destination(name)`; links (C6b, `src/links.rs`): `page_links(index)` → `PageLink { rect, quads, contents, to: LinkTo::{Destination, Uri, OtherFile, NamedAction, Unsupported} }` in page space, from `laminapdf_model::Pages::links` (`Link`, `LinkAction`, `ActionKind::as_name`; hidden links and links without a `/Rect` left out, nothing run), each `PageTarget { page, view: PageTargetView }` in page space (`At`, `Fit`, `FitWidth`, `FitHeight`, `FitRect`; `/FitH` and `/FitV` keep their fit on a quarter-turned page and drop their operand, as the builder writes it); `laminapdf_model::Outline::named_destination`; tests against pypdf's `outline_pages` and `page_labels` in `fixtures/corpus/expected.json` and the links-and-outlines golden. Properties (C6c, `src/properties.rs`, every build): `properties()` → `DocumentProperties` (Info and dates as ISO 8601, the XMP packet's text from `laminapdf_model::Document::xmp_packet`, version, page count, file size, linearized, tagged, `EncryptionSummary` with `DocumentPermissions`, `FontSummary`s from `laminapdf_model::Pages::fonts` (page resources, Form XObjects and Type 3 resources, once each), signatures counted by the save planner's constraint and signature field names, `DocumentContents`: JavaScript, attachments, forms from the disclosure scan); checked against pypdf's `properties` facts in `fixtures/corpus/expected.json` by `tests/properties.rs`; WASM `WasmDocument.properties()` (extract and text modules, as `initialView()` and `threads()` are, `src/navigation.rs`), `@laminapdf/sdk`'s `doc.properties()`. Reader mode (U4b, feature `reflow`, default, which implies `extract`; laminapdf-extract's own `reflow` feature): `reflow(&CancelToken)` → `laminapdf::extract::Reflow`; WASM `WasmDocument.reflow()` (the extract module only, which keeps the text module in its budget), `@laminapdf/sdk`'s `doc.reflow()` (typed in `src/reflow.ts`), `@laminapdf/viewer`'s `client.reflow()`. Reveal (T2c, `src/reveal.rs`, feature `extract`): `reveal(&OpenOptions, &CancelToken)` → `laminapdf::reveal::Reveal` (`revisions`: `RevisionRecord`s oldest first with `added`/`changed`/`freed` objects, the latest revision's `pages` they rewrite and the earlier revisions' removed words; `linearized`, `repaired`, every Info entry, the `/ID` in hex, the model's `Disclosure`, and the hidden runs of ADR 0030's six flags with their text), `Reveal::found()` → `Category`s (`history`, `metadata`, `attachments`, `active-content`, `annotations`, `forms`, `hidden-content`, E11d's names), `Reveal::redaction_warnings()` (`redaction_warnings`' warnings from what `reveal` found, built by the same `redaction.rs` helpers, nothing read again), `laminapdf::reveal` re-exporting the disclosure item types. `crates/laminapdf/tests/error_contract.rs` checks the error contract (every object validates against `laminapdf.error/1`; the shared cases of `fixtures/errors/contract.json` serialise exactly as `@laminapdf/sdk` throws them; no message or hint carries the marker of `fixtures/errors/marker-text.pdf`). Reading order is scored by `crates/laminapdf/tests/reading_order.rs` over `fixtures/reading-order/` (U2b: order and text scores, a ratchet threshold, the table in the job summary). `Document` is `Send + !Sync` (compile-time test). `laminapdf::Builder` wraps `laminapdf-build`'s and finishes into a `Document`; `laminapdf::Font` is a font program (`laminapdf-text`'s, with `OpenTypeTag` for `Font::instance`) and `FontHandle` one registered with a builder; `ops()`/`into_ops()` (the `laminapdf-ops` document, for Lamina PDF's own crates and tests) are `#[doc(hidden)]`, so the façade documents one `Document`. No public name is re-exported twice, and no two crates define the same `pub` type name outside `maintainability-duplicates.toml` (Q2s). Features: `build` (the builder without text, `laminapdf-build`), `text` (default; fonts and text, implies `build`), `saslprep` (default; R5/R6 password preparation, left out of WASM), `reflow` (default; reader mode, in the WASM extract module only), `explain` (off; `laminapdf::explain(code)` returns the code's `docs/errors` page, never in WASM). `laminapdf-build`'s own `text` feature gates `laminapdf-text`; the workspace dependencies on `laminapdf-build`, `laminapdf-syntax` and `laminapdf-cos` have no default features. Examples (`hello`, `invoice` (tagged), `multilingual`, `images_and_vectors`, `links_and_outlines`, `generate_then_edit`, `pdf_ua_report`, `pdf_a_archive` (writes `-2b` and `-2u`: an example may write `<name>-<variant>.pdf`), `pdf_a3_invoice_with_xml`) take their input files as parameters, and those with a fixed file ID or date (all but the three PDF/A and PDF/UA ones, whose IDs come from the content) their `BuildOptions` too; `tests/examples.rs` passes the fixed file IDs, dates and fixtures, checks them as byte goldens in `fixtures/golden/examples/` and writes them for `cargo xtask examples` and `golden --update` (its ignored `write_every_example`); they are render goldens in `fixtures/render-golden/` too.

CLI (ADR 0031; `laminapdf-cli`, L4a): the `laminapdf` binary, `publish = false` (released as binaries, Homebrew and npm instead: L4d). `laminapdf_cli::commands` has one function per command, `info`/`check`/`rotate`/`extract`/`explain(args, &Settings, &mut dyn Io) -> Result<Report, CliError>`; commands never print, so L4c's MCP adapter calls them too. `check` reads every object, then calls `redaction_warnings` (T2b) with the input's `open_options(settings)`, so its warnings also list covered text, unapplied redactions and text in earlier revisions (exit 3, `--warnings-ok` 0; `--strict` leaves them warnings). `reveal` (T2c, `src/commands/reveal.rs`, text in `src/reveal_text.rs`) maps `Document::reveal` into `laminapdf.reveal/1` (`found`, one key per category, pages as `{ index, number }`; hidden runs' text only with `--include-hidden-text`); the front end's `--fail-on CATEGORY,…|all` (`FailOn` beside `Many<RevealArgs>`) sets `Outcome::found`, which exits 6 (`ExitCode::Found`) and counts in `BatchSummary::found`. `Settings` holds `OpenArgs` (`--strict`, one flag per `codes.json` limit), the password (`--password-file` or `LAMINA_PDF_PASSWORD`, never argv), `--force`, `--dry-run`. `Io` reads `-` (once; a terminal stdin is refused) and paths, and writes atomically (temporary file + rename), refusing an existing file without `--force` (`overwrite-refused`, exit 4) and a PDF to a terminal stdout. `ranges::PageRange` is qpdf's grammar (`1-5`, `z`/`end`, `r2`, `x3`, `:odd`/`:even` of the result, 1-based) with pdftk handles (`A1-5`) and inline `file.pdf:1-3`. `exit::exit_code_for(ErrorCode)`: password codes 5, `overwrite-refused` 4, kind `usage` 2, the rest 1; warnings only 3 (`--warnings-ok` 0); `reveal --fail-on` findings 6; priority 2 > 5 > 4 > 1 > 6 > 3 > 0. `CliError` boxes an ADR 0026 `Diagnostic` (façade errors keep theirs, with CLI hints for passwords and limits); the CLI's own codes are `cliErrors` in `codes.json`. `--json` prints the report (`laminapdf.{info,check,pages,text,explain}/1`, warnings inside) on stdout (stderr when `-o -` holds the PDF); a failure is one `{"schema":"laminapdf.error/1","error":{…, input, exitCode}}` line on stderr. Schemas in `crates/laminapdf-cli/schemas/` come from `laminapdf_cli::schema::all()` (`UPDATE_GOLDEN=1 cargo test -p laminapdf-cli --test json_schemas` rewrites them). `laminapdf::did_you_mean` (from `laminapdf-syntax`, pinned by `fixtures/did-you-mean.json`) gives `didYouMean` for unknown codes and `--fields` keys. The golden `fixtures/golden/cli-rotate-hello.pdf` comes from its `examples/golden.rs` (`GOLDEN_CRATES` in xtask). MCP (L4c, feature `mcp`: rmcp `=3.9.0` and tokio, optional, so the plain CLI has neither): `laminapdf mcp --root DIR… [--allow-write [--allow-in-place]] [--max-output-bytes N ≥ 1024] [--timeout SECS ≥ 1]` (`laminapdf_cli::mcp::run(args, settings)`: documents open with the global `--strict`, limits and password; `--force` refused); tools `laminapdf_check`/`_explain`/`_extract`/`_info`/`_reveal` (its own `RevealToolArgs`: no `failOn` or `includeHiddenText`; it sets `RevealArgs::withhold_document_text`, so the report carries keys, counts and pages but no string the document wrote, `documentText: false`) and, with `--allow-write`, `laminapdf_build`, `laminapdf_pages_rotate` and `laminapdf_render`, in name order; each parses into the command's args type and runs `commands::*` on a blocking thread (a semaphore of one per CPU) through `mcp::roots::RootedIo` (paths resolved against the first root, links followed, refused outside every root: `path-outside-roots`, a missing file outside answered like an existing one); `inputSchema`/`outputSchema` from the same types, with `laminapdf.error/1` (`laminapdf::ERROR_SCHEMA`) inlined under `$defs/laminapdf-error-*` (`mcp/tools.rs`); results are `structuredContent` + text, failures tool errors whose only content is `CliError::to_line` as text (`structuredContent` must match the report's `outputSchema`, which the MCP inspector checks on errors too); past `--timeout` the call's own `Settings::cancel` token stops the command at its next step and the server waits for it up to 5 s (`cancelled`; a job still running keeps its permit until it ends; a result that finished anyway is kept); `--max-output-bytes` cuts a report on the blocking thread (`mcp/truncate.rs`: whole items from the ends of its arrays, then free-text strings, never a schema-fixed string; `"truncated": true`). Without the feature `laminapdf mcp` exits 2. Batch (L4b, `src/batch.rs`, front end `src/many.rs`): `info`/`check`/`extract` take many inputs (argv, `--files-from` with `-0`), `--jobs N` (`std::thread::scope`, results reordered by index), `--fail-fast`; NDJSON `result` lines and a `summary` (`result-line`/`summary-line.schema.json`); batch exit 0/3/1, 5 when every failure is a password's; one input prints as before. `extract --format md|json|chunks` (`commands::extract_document` → `ExtractedReport`, the `laminapdf.extract/1` document with `input` and `truncated`; `--max-chars` keeps whole blocks); `laminapdf schema [command]` (`schema::command`, `index`); `completions`, and the hidden `man-pages <dir>` that `cargo xtask cli-docs` runs. `render` (L4e, `src/commands/render.rs`): `render <inputs…> -o TEMPLATE [--pages] [--dpi N | --scale F] [--backend hayro|pdfium]` over `laminapdf-render` (`HayroBackend`; `laminapdf_render_pdfium::PdfiumBackend::from_env()`), PNG with the `png` crate, the `laminapdf.render/1` report, batch-capable (`ForInput::check_inputs` refuses clashing outputs before any input is read); `src/template.rs` parses `{stem}`/`{name}`/`{index}`/`{n:03}` templates; every output is checked against `--force` before the first write; `RenderError` converts into `CliError`; MCP adds `laminapdf_render` (with `--allow-write`) and `laminapdf_extract` answers every format (an `anyOf` output schema with `laminapdf.extract/1`'s definitions under `$defs/laminapdf-extract-*`). `build` (T4i, ADR 0032 §7, `src/commands/build.rs`): `build <input.md | -> -o OUT` with `--font ROLE=FILE[#N]` (regular, bold, italic, bold-italic, mono, repeatable fallback), `--page-size`, `--profile`, `--lang`/`--title` (used when the front matter has none) and `--creation-date` (none without it, so the bytes are deterministic) over `Builder::markdown`; images read through `Io` from the input's folder or below it (`laminapdf::markdown::image_targets`); remote, absolute, `..` and missing ones are never read, so the build warns `markdown-image-missing`; `laminapdf.build/1`; hints naming `--font` for `missing-glyph` and `font-not-embedded`; MCP `laminapdf_build` (`BuildToolArgs`: `markdown` inline, which reads no image, or `input`, whose folder its images come from); the golden `fixtures/golden/cli-build-report.pdf` (`examples/golden.rs`), `tests/build.rs`. JSON documents (T4k, `src/commands/document.rs`): a `.json` input, or standard input that is a JSON object, is built with `Builder::document`; `--data FILE|-` fills a template (`flow::document::fill`; not both on standard input); `--font NAME=FILE` and `--image NAME=FILE` give the files it names (`FlowDocument::font_names`/`image_names`), the rest read from files of those names in its folder (plain names only; standard 14 names need none); its profiles plus `--profile`; `--page-size` refused; the report adds `data`; the text error output prints `data.pointer` (and `reason`) as `= at:`; `unknown-font`/`unknown-image` get a hint naming `NAME=FILE`; MCP `document` and `data` inline (an inline document reads only files given by name), `images`; the tool's input schema inlines `laminapdf.document/1` under `$defs` (`laminapdf-document`, about 25 KB) beside an any-object branch, since a template matches it only once filled; the golden `fixtures/golden/cli-build-invoice.pdf`, `tests/build_document.rs`, and `tests/mcp.rs` builds the same bytes inline. `tests/render.rs` checks its PNGs against the render goldens through `laminapdf_test_fixtures::image` (`Bitmap`, `read_png`, `write_png`, `ssim`, shared with `laminapdf-render-pdfium`'s golden tests). `tests/mcp.rs` drives it with rmcp's client.

Form behaviour (E8f): `Document::field_behaviour(&FieldId)` → `Behaviour`, `validate(&FieldId, text)` → `FieldCheck { committed: Result<String, InvalidValue>, shown }` (nothing changes), `field_accepts(&FieldId, text)` (the keystroke check while typing), `calculate()` → `Edited` (the form's calculations as one edit; `Edited::skipped_calculations` lists totals a lock kept), `form_scripts()` → `Vec<FormScript>` (never the script text). The façade sets `SignatureLocks` on every document, so a change never conflicts with a lock through a total. The `script-inventory` example (`examples/differential/`) counts each source's scripts by state for `cargo xtask corpus scripts`.

Added content (E6b; `src/added_content.rs`): `Document::image_at(page, id, area, bytes, modified)` and `page_at(page, id, area, pdf, source_page, modified)` add the bytes as a blob and give an `AddContentObject` whose matrix stretches the unit square to `area`; `shape_on(page, id, path, fill, stroke, modified)` gives one with the identity matrix; `added_objects(page)` lists what Lamina PDF added (`AddedObject`); `update_added(page, id, modified)` and `delete_added(page, id)` give the edits that change or remove one. Re-exported: `AddContentObject`, `UpdateContentObject`, `DeleteContentObject`, `ContentId`, `ContentObjectSpec`, `PathSpec`, `Stroke`, `StrokeDash`, `Layer`, `Alt`, `AddedObject`. Every build draws them, the base WebAssembly module included. Example: `place_content`.
