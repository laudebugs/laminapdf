# Decisions and plans in brief

Every accepted ADR in one paragraph, and the plans that follow them. The ADRs in [`docs/decisions/`](../decisions/) are the source; update this summary when an ADR is accepted or amended.

Accepted so far: a Rust core, `MIT OR Apache-2.0`, bytes in / bytes out with no AGPL/GPL dependencies ([0001](../decisions/0001-core-language-and-licence.md)); wasm-bindgen + tsify bindings ([0002](../decisions/0002-binding-strategy.md)); the Cargo + pnpm + `cargo xtask` monorepo, npm packages under `@laminapdf` (amended 2026-10-31) ([0015](../decisions/0015-monorepo-layout-and-tooling.md)); one lockstep version for every crate, `@laminapdf/wasm`, `@laminapdf/sdk` and the render packages (`@laminapdf/render`, `-hayro`, `-pdfium`) and `@laminapdf/viewer`, driven by Changesets and copied into Cargo by `cargo xtask version sync`, `0.x` with `-alpha.N` pre-releases until `0.2.0` (amended 2026-11-11: the alphas end, and `0.x` follows SemVer), `v<version>` tags and a release lane that publishes on `v*` tags: crates.io trusted publishing, npm trusted publishing; amended 2026-11-05: a daily release cut and tagged by a release bot after the nightly passes, npm trusted publishing from a GitHub-hosted runner with no approval step, `docs.laminapdf.com` from each release and `next.docs.laminapdf.com` from `main` ([0017](../decisions/0017-versioning-and-release.md)); cargo-deny and licence hygiene ([0019](../decisions/0019-supply-chain-and-licence-hygiene.md)); the reader tolerance policy and `Limits` ([0003](../decisions/0003-reader-tolerance-and-limits.md)); the document model ([0005](../decisions/0005-document-model.md); generation strategy §6: our own builder over `laminapdf-cos` reusing `pdf-writer`/`subsetter`/`skrifa`/HarfRust, per the `krilla-fit` spike, accepted when its PR merges); the op log and undo ([0006](../decisions/0006-op-log-and-undo.md)); the save planner ([0007](../decisions/0007-save-planner.md)); the test strategy ([0018](../decisions/0018-test-strategy.md)); content-stream reading ([0023](../decisions/0023-content-stream-reading.md)); content-stream editing: `ContentOps`, operators keeping their source bytes grouped into objects with their graphics state and glyphs, identity by owner, ordinal and source hash (`content-object-stale`), an encoder that copies unchanged spans into new streams, copy on write for shared streams and forms, tagging kept through edits, text runs by MCID then extraction's lines, fonts reused, subset again or substituted, every edit labelled ([0022](../decisions/0022-content-stream-editing.md)); the error and diagnostic contract, `LaminaPdfError` in TS ([0026](../decisions/0026-error-and-diagnostic-contract.md)); coordinates in top-left points of the displayed CropBox, raw user space only in `UserSpace…` types, 0-based page `index` ([0027](../decisions/0027-coordinates-units-and-page-indexing.md)); the façade rules, the lock in the binding edge (core stays `Send + !Sync`), `Job::step(Budget)` in work units and `CancelToken` ([0028](../decisions/0028-facade-rules-jobs-and-cancellation.md)); mobile bindings: UniFFI `=0.32.2`, a `crates/lamina-ffi` edge crate, hand-written Swift/Kotlin layers that cancel async calls through a Rust token, SwiftPM and Maven Central AARs, 16 KB pages, `mobile-release` and size budgets ([0029](../decisions/0029-mobile-bindings-and-packaging.md)); the CLI and MCP contract: one `laminapdf` binary over a command library, verb-first grammar, qpdf page ranges with pdftk handles, `-` for stdin and stdout, exit codes 0–5, versioned JSON with committed schemas, errors on stderr, read-only MCP with required roots ([0031](../decisions/0031-cli-and-mcp-contract.md)); the extraction output `laminapdf.extract/1`: blocks in reading order with top-left boxes, structure tree then XY-Cut++, hidden text never in text, models only as licence-checked plug-ins ([0030](../decisions/0030-extraction-output-and-model-plugins.md)); for the web reader: the `RenderBackend` trait (bounded RGBA tiles, never model data from the renderer), PDFium by default on every viewer surface (pinned and SHA-256 checked) with hayro as the CI oracle and measured switch criteria, MuPDF prohibited, the two-parsers rule ([0004](../decisions/0004-render-backend.md)); React 19 chrome around a framework-free `@laminapdf/viewer`, one document worker per document, a typed RPC extending `@laminapdf/sdk/worker`, transferred `ImageBitmap`s, single-threaded with no COOP/COEP in v0.1 ([0009](../decisions/0009-web-client-architecture.md)); one `Platform` interface with capability flags and no platform checks in UI code ([0010](../decisions/0010-platform-adapter.md)); static-assets Workers on Cloudflare (the website at `laminapdf.com`, the reader at `app.laminapdf.com` with staging at `staging-app.` and production only from `web-v*` tags; amended 2026-11-05), documents never through our servers (`#url=` fragment), ten testable privacy guarantees, strict headers, opt-in-only telemetry and hosted features ([0011](../decisions/0011-cloudflare-topology-and-privacy.md)); the app shell UX: a docked inverted-L layout, registered modes that each own one secondary toolbar, one command registry behind the palette, toolbars, menus and shortcut help (every command with a visible home besides the palette), selection surfaces chosen by pointer (no floating toolbar on touch), page appearance separate from the UI theme, the phone shell, and `--paper-` tokens in primitive → semantic → component layers ([0024](../decisions/0024-app-shell-ux.md)); PDF JavaScript never run: Acrobat's `AF*` helper calls recognised as data and run natively, every other script reported and strippable, authored scripts stored as text, a sandbox only by amendment ([0021](../decisions/0021-pdf-javascript-policy.md)); flowing layout as our own engine in `laminapdf-build` over `Surface` (Typst measured and rejected by the `flow-layout` spike), greedy pagination with keep rules, page templates, tagged by default, Markdown and `laminapdf.document/1` with JSON Pointer templates, `laminapdf build` and its MCP tool ([0032](../decisions/0032-flowing-layout-and-document-inputs.md)). The plan for the rest is in `docs/plans/architecture.md`, with the shareable libraries (contracts, CLI/MCP, AI extraction, agent docs, mobile; Rounds L1–L6; ADRs 0029, 0030 and 0031 accepted) in `docs/plans/shareable-libraries.md`, and the work that the Hacker News research (`docs/research/hacker-news/`) found users lack (published proof, checks for what files hide, extraction users can check, flowing layout; Round T; ADR 0032) in `docs/plans/trust-and-proof.md`, and the reader as a browser extension for Chrome, Edge, Firefox and Safari (Round K, a nice-to-have that starts after the web reader's launch; research in `docs/research/browser-extension/`) in `docs/plans/browser-extension.md`; don't assume decisions that aren't in an ADR.
