- Date: 2026-10-31
- Amended 2026-11-05 (owner; the [releases plan](../plans/releases.md)): `docs.laminapdf.com` deploys from each release instead of from `main`, and `main`'s docs move to `next.docs.laminapdf.com` (the Worker `lamina-pdf-docs-next`). This amendment edits §1's host table; [P4](../todos/ongoing/P4-docs-match-the-release.md) implements it.
- Amended: 2026-11-05 ([W1a](../todos/done/W1a-domain-map.md), the [website plan](../plans/website.md)): the website is at `laminapdf.com` and the reader moves to `app.laminapdf.com`, with its staging at `staging-app.laminapdf.com`. This amendment edits §1–§4 in place: the hosts (§1), the `#url=` links (§2), the origin the guarantees name and the website's own rules (§3), and the website's headers and the HSTS preload (§4).

## Context

The web reader ([web-app plan](../plans/web-app.md)) is served from Cloudflare. lamina will also be a hosted service with login and cloud features ([architecture §8](../plans/architecture.md#8-open-questions-for-the-team) Q2, decided 2026-10-28), but every server feature is opt-in and the app works fully without an account ([architecture §2](../plans/architecture.md#principles-each-becomes-part-of-an-adr), principle 6). People open legal, medical and financial documents in a reader, so "privacy first" has to be a set of statements a test can check, not a slogan.

What the research found ([Cloudflare notes §1, §4](../research/architecture/notes/cloudflare.md); [research: Cloudflare](../research/architecture/app-and-package-architecture.md#cloudflare-hosts-everything-for-about-5-a-month-with-heavy-jobs-in-containers)):
- **Workers rather than Pages:** Cloudflare's Pages docs tell new projects to start on Workers. Workers static assets support `_headers`, an SPA fallback (`not_found_handling`) and `run_worker_first` for routes that need code.
- **Static-asset requests are free and unlimited.** A pure SPA needs no `main` script.
- **Limits:** each asset can be at most 25 MiB. PDFium's 4.6 MB `.wasm` fits.
- **`_headers` doesn't cover Worker responses.** It is not applied to responses that Worker code generates, so such code must set headers itself.
- **Preview URLs per version** need `preview_urls` and are served on the Workers domain. Custom domains need the zone on Cloudflare.
- **The `cf` CLI** has been in beta since 2026-09-28 and is the planned successor to Wrangler. Its config and commands may change, and secondary sources say it sends anonymous telemetry by default.
- **Retention:** Workers Logs keeps 3 days on Free and 7 on Paid. R2 lifecycle rules can expire objects. Workflows, Queues and D1 Time Travel have their own retention.

Telemetry was decided by the owner on 2026-10-29: none in v0.1; afterwards optional, opt-in and off by default ([U5c](../todos/ready/U5c-opt-in-usage-telemetry.md)). The domain, `laminapdf.com`, was chosen by the owner on 2026-10-31 ([web-app §8](../plans/web-app.md#8-open-questions) Q1); the product name is still open. On 2026-11-05 the owner put a website at the apex and the reader at `app.laminapdf.com` ([website plan](../plans/website.md)).

## Decision

### 1. Topology

- **One Worker per environment (`lamina-pdf-web`, and `lamina-pdf-web-staging` below),** with static assets from `apps/web`'s Vite `dist/`:
  - `assets.directory`;
  - `not_found_handling: "single-page-application"`;
  - **no `main` script and no `/api` routes in v0.1.**

  Every request is answered by the asset server, so no lamina code runs per request.
- **`run_worker_first: ["/api/*"]` is reserved** for the later opt-in features (telemetry, accounts, cloud storage). Adding it is an amendment to this ADR. Responses generated by Worker code set the §4 headers in code, because `_headers` doesn't apply to them.
- **`compatibility_date` is pinned** in `apps/web/wrangler.jsonc`, ≥ 2025-04-01, so browser navigations go straight to assets.
- **Tooling:** Wrangler is pinned exactly in CI, at the workspace catalog's version (4.149.0 today). The `cf` CLI is tried in a branch once it reaches GA, with its telemetry turned off; adopting it is a deliberate PR.
- **Environments are two Workers,** so a staging deploy can never replace production. Both come from one `wrangler.jsonc` with a Wrangler environment `staging`.
  - **`lamina-pdf-web-staging`:** custom domain `staging-app.laminapdf.com`, deployed from every push to `main`. Its PR previews are Workers preview URLs on `workers.dev`, posted as a PR comment (C4d).
  - **`lamina-pdf-web`:** custom domain `app.laminapdf.com`, deployed **only from `web-v*` release tags**, after the release lane's gates pass (C7c), with preview URLs off.
- **`noindex`:** the build takes the environment as an input (`LAMINA_PDF_ENV=staging|production`) and writes `_headers` from one template. Staging and preview builds add `X-Robots-Tag: noindex`; production doesn't. Everything else in §4 is identical, and C4d compares the two files.
- **Assets:**
  - Built files are content-hashed and served with `Cache-Control: public, max-age=31536000, immutable`.
  - `index.html`, the service worker and the web manifest are served `no-cache`.
  - The WASM modules are static assets of the same origin (ADR 0009 §2), never a CDN's.
- **The website is a Worker of its own, `lamina-pdf-site`** (`apps/site`, [W1b](../todos/done/W1b-site-scaffold-and-deploys.md)): static assets from Astro's `dist/`, `not_found_handling: "404-page"` and no Worker code, like the docs site. Every push to `main` deploys it, with a preview per PR. It never serves the reader: it links to the reader and forwards nothing.
- **The domain is `laminapdf.com`** (the owner's choice, 2026-10-31; it was a `<domain>` placeholder until then). Since 2026-11-05 the website holds the apex and the reader `app.` ([website plan §2](../plans/website.md#2-the-domain-map)). Every host, its Worker and what deploys it:

  | Host | Serves | Worker | Deployed from |
  | --- | --- | --- | --- |
  | `laminapdf.com` | the website (`apps/site`) | `lamina-pdf-site` | `main`, with a preview per PR |
  | `www.laminapdf.com` | a 301 to `laminapdf.com`, path and query kept | none: a Cloudflare redirect rule | set once by the owner |
  | `app.laminapdf.com` | the reader (`apps/web`) | `lamina-pdf-web` | `web-v*` release tags only |
  | `staging-app.laminapdf.com` | the reader's staging | `lamina-pdf-web-staging` | every push to `main` |
  | `docs.laminapdf.com` | the docs site (`apps/docs`) for the latest release | `lamina-pdf-docs` | each release ([ADR 0017 §7](0017-versioning-and-release.md#7-publishing)), with a preview per PR |

  Every name but `next.docs.laminapdf.com` is one label deep, so the zone's universal certificate (the apex and `*.laminapdf.com`) covers it. That one is two labels deep: its Workers custom domain gets a certificate of its own, which P4 checks before it deploys. The HSTS preload submission follows the website's first production deploy (§4).

### 2. Documents never pass through our servers

- **Local files** are read in the document worker and never leave the device.
- **Remote documents** come from the **`#url=` fragment** only (`https://app.laminapdf.com/#url=https://…`). The website at `laminapdf.com` forwards no fragment: the apex never served the reader, so no link expects it to. Browsers never send a fragment, so neither our Worker nor Cloudflare's request logs learn which document was opened. The worker fetches the file **directly from its host**:
  - with range requests (`httpRangeSource`, L2c);
  - with `credentials: "omit"`, `referrerPolicy: "no-referrer"` and `cache: "no-store"`;
  - following the host's own HTTP redirects (`redirect: "follow"`; hosted PDFs often redirect to a storage or CDN host). The viewer shows the final host's name in the document's properties.
- **CORS:** a host without CORS gets an explanation, never a silent proxy. An opt-in CORS proxy would see the bytes, so it is a later server feature under §6, if ever ([web-app §8](../plans/web-app.md#8-open-questions) Q2).
- **The URL is in-memory state:** the app reads the fragment and then replaces it in the address bar (`history.replaceState`), so it isn't left in history or copied by accident. It is never written to storage, the recent list or logs. The OPFS block cache of a remote document (C4c) is keyed by a random ID generated when the document opens, never by the URL or a hash of it, and is deleted when the document closes or at the next start.

### 3. The v0.1 privacy guarantees (testable)

Each statement is an assertion in C4c's Playwright suite (and, where noted, C4d's header checks), and the text of C7c's privacy page. "Our origin" is the reader's, `https://app.laminapdf.com` (and `staging-app.` for staging):

1. **No document bytes leave the device.** No request from the app to any origin carries a body containing bytes of the opened document. No request to our origin has a body at all.
2. **Our origin never learns the remote document's URL.** No request to our origin contains it, or any part of it, in the URL, the request line or any header, including `Referer`.
3. **Remote documents go only to their own host and its redirects.** Requests for a `#url=` document go only to that URL's origin and the origins its HTTP redirects lead to, with no cookies or credentials and no `Referer`. The app never adds a host of its own.
4. **No cookies.** No response from our origin sets a cookie, and `document.cookie` stays empty. This holds for anonymous use in every later version too (§6).
5. **No third parties.** Every script, style sheet, font, image, worker and WASM module comes from our origin. The only other origin the app ever contacts is a remote document's host, at the user's request.
6. **No telemetry in v0.1.** Every request the app makes to our origin is a `GET`, with no query string and no body, for a file of the deployed build: one listed in the build's asset manifest (lazily loaded chunks, WASM modules and hayro's fonts and CMaps included), `/sw.js` or the web manifest. In particular there are no analytics, error reports, beacons or pings. C4c asserts every request to our origin against the manifest. App state that must not reach the server, such as the debug menu (`#debug`) and remote documents (`#url=`), lives in the fragment, never in the query string.
7. **No fingerprinting.** Nothing is collected, and there are no third-party scripts that could. The app reads no device APIs it doesn't need: the §4 Permissions-Policy denies them.
8. **Passwords stay in the worker.** A password is posted once, to the document worker, and is never stored, logged or sent anywhere (C3a asserts the message flow).
9. **Local data is the user's to clear.** The app stores only:
   - the OPFS cache of opened files;
   - the recent list (name, size, time and a reopen handle; never bytes or URLs);
   - settings;
   - the service worker's cache of the app itself.

   "Clear local data" in settings removes all of them except the app cache.
10. **Strict headers.** Every response from our origin carries the §4 headers. C4d checks them on preview, staging and production.

**The website's rules.** The website at `laminapdf.com` holds pages of text, not documents, so it keeps the guarantees that apply to a page. W1b's post-build checks test every built page against them:

- **No cookies** (4): no page or response sets one.
- **No third parties** (5): every script, style sheet, font and image comes from the website's own origin.
- **No analytics** (6, 7): no beacon, ping or counter of any kind; the progress dashboard is data built into the page, not a request.
- **No Worker code** (§1): every request is answered by the asset server.
- **Strict headers** (10): every response carries the website's §4 headers.

Guarantees 1–3, 8 and 9 have nothing to act on there: the website opens no document, takes no password and stores nothing on the device.

### 4. Security headers (`apps/web/public/_headers`, for `/*`)

```
Content-Security-Policy: default-src 'none'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self'; img-src 'self' blob: data:; font-src 'self'; connect-src 'self' https:; worker-src 'self'; manifest-src 'self'; frame-src 'self'; frame-ancestors 'self'; base-uri 'none'; form-action 'none'; object-src 'none'; upgrade-insecure-requests
Referrer-Policy: no-referrer
Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=(), serial=(), hid=(), bluetooth=(), browsing-topics=(), clipboard-read=(), clipboard-write=(self)
Strict-Transport-Security: max-age=63072000; includeSubDomains
X-Content-Type-Options: nosniff
X-Frame-Options: SAMEORIGIN
Cross-Origin-Resource-Policy: same-origin
```

- **No inline scripts and no `unsafe-eval`.** `'wasm-unsafe-eval'` is the only exception, and WebAssembly compilation needs it.
- **`connect-src https:`** is what lets the worker fetch a remote document from any host (§2); everything else is `'self'`.
- **`frame-src 'self'` with `frame-ancestors 'self'` and `X-Frame-Options: SAMEORIGIN`** allow the same-origin print iframe (C6c) and refuse framing by every other site. Styles are set through the CSSOM, never through `style` attributes in markup.
- **No COOP or COEP in v0.1** (ADR 0009 §5). The threaded variant would add them on its own route.
- **`preload` is added to HSTS** after the website's first production deploy, once every subdomain answers over HTTPS only. The preload list checks the apex's header, and the website now serves the apex. A one-line PR adds `preload` to the website's `Strict-Transport-Security` header (W1b's post-merge checks), and the owner then submits `laminapdf.com`.
- **Changes are amendments:** a change that loosens any directive is an amendment to this ADR, and C4d's header test pins the exact values.

**The website's headers** (`apps/site/public/_headers`, for `/*`; W1b) are the set above with two differences, each with its reason:

- **`script-src 'self'` plus one `'sha256-…'` hash per inline script the build writes**, filled in after the build as the docs site does, because Astro writes small inline scripts. No `'wasm-unsafe-eval'`: the website runs no WebAssembly.
- **`connect-src 'self'`**: the website fetches nothing remote.

`style-src 'self'` stays as it is: the build sets Astro's `build.inlineStylesheets: "never"`, so every style sheet is a file, and pages set no `style` attributes. Preview builds add `X-Robots-Tag: noindex`, as the reader's do (§1). The website has no staging.

Any other difference is added here, with its reason, before W1b ships it.

### 5. Observability without content

- **v0.1 runs no Worker code** (§1), so there are no Workers Logs to configure. `observability` stays disabled in `wrangler.jsonc`, and Logpush is not set up.
- **What Cloudflare still sees:** as the CDN, Cloudflare processes request lines and headers. That is the reason §2 keeps document URLs in the fragment and §3 keeps bodies off our origin, so those logs never contain anything sensitive. Cloudflare Web Analytics (its beacon) is not used.
- **When `/api/*` arrives:**
  - Worker logs must not include request bodies, query strings or headers other than method, path template, status and duration.
  - Logs use the shortest retention the plan offers (7 days on Paid).
  - Client IPs are never stored by lamina's code.
  - A test of each new route asserts its log line.

### 6. The hosted service and later server features

These rules bind every later round that adds a server feature: telemetry (U5c), accounts, cloud storage and sync (E18), and heavy jobs (ADR 0013).

1. **Opt-in, per feature.** The app works fully without an account. Signing in changes nothing until the user turns a cloud feature on, and turning it off stops it.
2. **Opt-in per document for anything that uploads.** Before a document or any part of it leaves the device, a dialog names what is sent, where it is stored and for how long, and the user confirms for that document. There is no "remember for all documents" option for content uploads.
3. **Retention:**
   - **Processing temporaries** (heavy jobs, conversions) expire within **24 hours**, through R2 lifecycle rules. Queues and Workflows use their shortest retention.
   - **Documents a user stores in the cloud** are kept until the user deletes them. An account deletion removes the live data at once (within 24 hours), so that **no copy can be restored 30 days after the request**: D1 Time Travel's window (30 days on Paid) is counted from the request, and any other backup keeps to the same limit.
   - **End-to-end encryption:** a feature that doesn't need server-side processing (storage and sync of the file itself) encrypts on the client before upload, so the server only stores ciphertext. The feature's ADR says when that is impossible and why.
4. **Telemetry (when U5c lands):**
   - **Consent:** optional, opt-in and off by default, as one setting per install. The exact payload is shown before the user agrees.
   - **Payload:** cookieless and aggregate. Daily counts per command id and mode, the app version and the platform family.
   - **Nothing personal:** no user, device or session identifiers, and no document content, names, URLs or text.
   - **Endpoint:** sent to our own origin (`/api/telemetry`), so the CSP doesn't change.
   - **Retention:** raw batches are deleted within 7 days, and aggregates are kept for 13 months.
   - **Error reports** are a separate opt-in. They hold ADR 0026 codes and kinds, which are content-free by design, plus stack frames of lamina's own code. They never carry messages that contain document text, file names or URLs, and they follow the same retention.
5. **Accounts:**
   - The login stack is chosen by H1 and added to this ADR by amendment. Until then, no round may ship sign-in.
   - Session cookies exist only for signed-in users, only on `/api` routes, as first-party `HttpOnly; Secure; SameSite=Strict` cookies. Anonymous use stays cookie-free (§3.4).
   - Sign-in flows must work without COOP/COEP on the main app (ADR 0009 §5).

## Consequences

- **Hosting v0.1 costs close to nothing:** static assets are free, and no Worker code runs per request.
- **The privacy page is a set of tested statements.** A regression (a new third-party script, a request carrying the document URL, a cookie) fails CI instead of shipping.
- **No proxy means some files can't open:** remote documents without CORS don't open, and the app explains why instead of quietly proxying.
- **`connect-src https:`** is broader than `'self'`. It is required by direct fetching, and contained by allowing scripts from `'self'` only.
- **Every later server feature starts from opt-in, per-document consent and fixed retention.** Its ADR has to justify any exception.
- **One more governance task:** the domain choice touched every `<domain>` placeholder in a single PR (`laminapdf.com`, 2026-10-31).
- **Two origins (amendment 2026-11-05):** the reader's storage, service worker and permissions live at `app.laminapdf.com`, apart from the website. No website page can read or clear the reader's local data, and the reader's offline cache never captures a website page.

## Alternatives considered

- **Cloudflare Pages.** Rejected: Cloudflare directs new projects to Workers, and Workers static assets cover the SPA fallback, `_headers` and previews.
- **A Worker script in front of every request** (for headers or logging). Rejected: it costs invocations, adds a code path that sees every request, and `_headers` already covers static responses.
- **A server-side fetch proxy for `#url=`** (no CORS problems). Rejected for v0.1: the server would see every document. It is possible only as an opt-in feature under §6.
- **Remote URLs in the query string** (`?url=`). Rejected: query strings reach our server and its logs. The fragment never does.
- **Privacy-friendly analytics in v0.1** (cookieless, aggregate). Rejected by the owner's decision on 2026-10-29: none in v0.1, opt-in later (U5c).
- **Shipping COOP/COEP now** for future threads. Rejected (ADR 0009 §5): it breaks cross-origin documents and embeds for no v0.1 benefit.
- **Adopting the `cf` CLI now.** Rejected while it is in beta: config and commands may still change, and its default telemetry needs turning off.
