## Goal

Get lamina's docs to coding agents, because a new library is a low-frequency API to every model and models guess wrong without current docs ([report: a new library is a rare API to every model](../../research/libraries/shareable-libraries.md#a-new-library-is-a-rare-api-to-every-model)). The docs site publishes:

- `llms.txt` and `llms-full.txt`;
- a `.md` twin of every page;
- version-matched docs inside the npm package and the crate, so an agent can read them from `node_modules` or the cargo registry.

Users get an `AGENTS.md` snippet for their own repositories. A machine-readable rename log tells agents what old names became. A fixed agent-eval task list, run once against the examples, records a baseline, so later changes to names and docs can be measured.

## Scope

**In scope**

- **`llms.txt` and `llms-full.txt`**, generated by the docs build into the site root:
  - `llms.txt` follows llmstxt.org: H1 `lamina`, a one-paragraph blockquote, then H2 sections (Quick starts, Guides, API, Errors, Examples) of links to `.md` pages.
  - `llms-full.txt` inlines every page in a fixed order.
  - Both name the package version they describe.
- **`.md` twin of every page**: `/guides/fonts/` also served as `/guides/fonts.md`, rendered from the MDX source with imported snippets inlined. The API reference comes as Markdown via a TypeDoc Markdown plugin. Recommendation: evaluate an existing Starlight llms plugin first, after a licence check; otherwise use a small Astro integration in `apps/docs`.
- **Docs inside the packages**, built at pack time from the same Markdown:
  - `packages/sdk/docs/` (guides, API Markdown, `explain` pages, `schemas/`, `renames.json`, `llms.txt`), listed in `files`.
  - The `laminapdf` crate's `docs/` via `include` in `Cargo.toml`.
  - Each file's front matter carries `version`, equal to the package version.
- **`AGENTS.md` snippet**: a docs page "Using lamina with coding agents" with a copy-paste block for users' `AGENTS.md` (or `CLAUDE.md`). It covers:
  - where the version-matched docs live (`node_modules/@laminapdf/sdk/docs/`);
  - `init()` before sync calls;
  - top-left points and 0-based page index (ADR 0027);
  - errors by `code`, with `explain` pages;
  - the `llms.txt` URL.

  The same block goes in `packages/sdk/examples/AGENTS.md`.
- **Rename log**: `renames.json` with schema `laminapdf.renames/1`: `[{ from, to, surface: "rust" | "ts" | "cli", kind, since, note }]`.
  - A check fails when a `#[deprecated]` Rust item or `@deprecated` TSDoc tag has no entry naming its replacement, and when an entry points at a symbol that no longer exists.
  - Shipped in the packages and on the site.
- **Agent-eval baseline** (recorded, not gating):
  - `tools/agent-eval/tasks/*.md`: 10–20 fixed tasks, each with a checker script that validates the result with lamina itself and `qpdf --check`. Example tasks: build a two-page invoice; open an encrypted file and handle `wrong-password` by code; rotate page 3 and save incrementally; read page sizes in points; extract text if [B9c](../done/B9c-text-extraction-bindings-and-differential.md) has merged.
  - A runner that starts a pinned coding agent in a scratch project, once with no docs and once with the shipped docs, and writes pass/fail per task.
  - The first run's results go in `docs/research/libraries/agent-eval-baseline.md`, with the agent, model, date and laminapdf version.

**Out of scope** (and which todo covers it)

- A Context7 listing and an MCP docs server: after the first registry prerelease ([P2](../done/P2-first-registry-prerelease.md)); a `laminapdf docs <symbol>` command belongs with the CLI ([L4b](../ready/L4b-cli-batch-render-schema.md)).
- Running the eval in CI or gating on it: not planned (it needs a paid API key and is non-deterministic).
- Writing the guides themselves: [B7a](../done/B7a-docs-site.md).

## Risks and open questions

- **Evidence is thin:** no controlled study shows llms.txt improves agent correctness ([LLM note (A) gaps](../../research/libraries/notes/llm-api-and-ai-extraction.md#a-what-makes-llmsagents-write-correct-code-against-a-library-api-and-what-lamina-should-do)). The baseline eval is how lamina finds out for itself; keep the work small.
- **Tarball size:** shipping docs grows the npm package. Recommendation: Markdown only (no images), with the size reported by `cargo xtask size` and a soft budget. The owner decides on a hard budget.
- **Eval reproducibility:** agent output varies run to run. Recommendation: three runs per task and condition, with pass counts recorded. Pin the agent version, and record the cost.
- **Docs site host** is `https://docs.laminapdf.com` ([architecture §8](../../plans/architecture.md#8-open-questions-for-the-team) Q3); `llms.txt` links use it. Generate them from one constant, shared with ADR 0026's `docsUrl` once its base moves from GitHub to the docs site.
- **Crate `include` limits:** crates.io caps the package size (10 MB, to verify). Markdown docs should fit; check with `cargo package`.
