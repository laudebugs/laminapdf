## Goal

Mark the pages whose column order the layout rules guessed, with a warning and a lower `confidence` on the blocks concerned, so a pipeline can check those pages or send them to a model. Reading order across columns comes up in 226 extraction comments, steady all decade, and users say "two-column layouts and footers etc often still mess up the content" ([43979397](https://news.ycombinator.com/item?id=43979397)) and "The lines from the two columns are mixed" ([46206703](https://news.ycombinator.com/item?id=46206703)). Nobody can see when the order is wrong. Lamina PDF's one order warning, `extract-reading-order-ambiguous`, covers only pages that mix horizontal and vertical writing.

## Context

- [Report R4: make extraction checkable](../../research/hacker-news/pdf-users-on-hacker-news.md#r4-make-extraction-checkable) and the [extraction note](../../research/hacker-news/notes/extraction.md): want 7 (reading order), complaint 8 (columns in the wrong order, 80 comments), §6 priority 5 ("say when you are unsure").
- [ADR 0030 §2](../../decisions/0030-extraction-output-and-model-plugins.md#2-reading-order): XY-Cut++ masks blocks at least 60% as wide as the page's text that cross a column gap and share no height with a narrower block, then cuts each band at its widest gap, columns before rows, except in a group of one-line blocks, which reads row by row. §1: `confidence` is "lower for inferred structure; callers may threshold it".
- The code, and where each guess is made:
  - `crates/laminapdf-extract/src/lines.rs`: `split()` keeps two runs on one baseline in one line unless the gap between them is wider than `GUTTER` (1.0 font size). A gutter narrower than one font size is read across, so the two columns' lines interleave.
  - `crates/laminapdf-extract/src/page.rs`: `segments()` cuts a run at a pen jump wider than the same `GUTTER`, so a narrow gutter inside one run is read across too.
  - `crates/laminapdf-extract/src/xycut.rs`: `Cutter::mask` (the 60% rule, `WIDE`), `Cutter::gap` (any gap over `MIN_GAP`, 1 pt, is a cut) and `Cutter::cut` (columns first; `grid` when every block is one line; a group with no gap reads top to bottom). A block across the gutter that shares height with the column text (a pull quote, a box the text wraps around) is never masked, so the band is cut by rows and the columns interleave.
  - `crates/laminapdf-extract/src/page.rs`: `LAYOUT_CONFIDENCE` (0.75) and `CONTENT_CONFIDENCE` (0.5); `extract_page` raises `extract-reading-order-ambiguous` for mixed writing.
- [U2b](../done/U2b-reading-order-ground-truth.md)'s corpus, `fixtures/reading-order/`: 22 files from 11 layouts, generated by `crates/laminapdf-build/tests/common/reading_order.rs` (`layouts()`). `crates/laminapdf-extract/tests/reading_order.rs` (`LAYOUTS`) already reads all 22 in order by layout, so the corpus has no wrong page: it is the clean set, and this todo adds the hard pages. `crates/laminapdf/tests/reading_order.rs` scores the corpus's content-order text against a ratchet in `fixtures/reading-order/threshold.json`.
- [L3f](../done/L3f-extraction-benchmark.md): olmOCR-bench's `multi_column` subset (884 order tests on 231 pages, 52.1% passed) checks the warning on real pages; `tools/bench/olmocr_score.py` scores, `crates/laminapdf/examples/differential/extract-bench.rs` extracts.
- [L3g](../done/L3g-extract-structure-tree.md) adds structure-tree order; a page read from its tree gets none of these checks.

## Scope

**In scope**

- **Three checks**, run only when the order comes from XY-Cut++ (`ReadingOrder::Auto` or `Layout`), and skipped on pages with vertical writing, which `extract-reading-order-ambiguous` already covers:
  1. **`narrow-gutter`**: `lines::split()` records, on the `Line`, where the right-hand run starts (the left-hand run's end on a right-to-left line) whenever it keeps two runs together across a gap wider than `NEAR_GUTTER` (new, 0.6 font size) but not wider than `GUTTER`. `page::segments()` records the same for such a pen jump kept inside a run, on the `Piece`, and the line takes it from its pieces. A block with at least three lines that record such a point within half a font size of one another has probably read across a narrow gutter.
  2. **`columns-revisited`**: on the order XY-Cut++ returns, band by band (between masked blocks), the order leaves a block for one beside it (no horizontal overlap) and later comes back to a block below the first one, in the same column (horizontal overlap of at least 30% of the narrower block, as `blocks.rs`'s `OVERLAP`). A column-first reading never comes back to a column within a band; row cuts forced by a block across the gutter do. Triples whose blocks are all one line are skipped, since the grid rule reads them row by row on purpose. The check stops at its first find.
  3. **`near-grid`**: in `Cutter::cut`, a group of at least 4 blocks with both a column gap and a row gap, three quarters or more of them one line but not all, is cut by columns. Cut it by rows too and compare: if the two orders differ, the grid rule's all-or-nothing test decided the order (an unruled table with one wrapped cell reads column by column). At most 8 such second cuts per page (`MAX_ALTERNATIVES`, new), each polling the cancel token as the first cut does.
- **What a doubt does:** `extract_page` raises `extract-column-order-uncertain` (new, kind `unsupported`) once for the page, with the data field `reason` (`narrow-gutter`, `columns-revisited` or `near-grid`, the first found in that order) and the page in its location. Each text block a doubt covers gets `confidence` 0.5 (`UNCERTAIN_CONFIDENCE`, new, the value content order gets) instead of 0.75; a table block keeps its own, which measures its grid. The order itself doesn't change.
- **`xycut::order` returns what it found:** its result carries the order and, when a check fired, the reason and the blocks it covers (a small struct in `xycut.rs`).
- **Three hard layouts in the corpus**, each drawn in reading order and in reverse (6 files), with the generator's ground truth:
  - `pull-quote`: two columns of 10 pt text with a boxed quote over the gutter halfway down, and the paragraphs beside it narrowed so the text wraps round it; the `about` names where the truth puts the quote. XY-Cut++ cuts the page into rows and interleaves the columns.
  - `narrow-gutter`: two columns of 10 pt text 7 pt apart, the left one set flush right (`TextBoxOptions::with_align(Alignment::Right)`) so every line ends at the gutter, as justified newspaper columns do. Each line is read across both columns.
  - `wrapped-grid`: an unruled 3 × 3 grid of short cells, as `table` has, with one cell wrapping onto a second line; the truth reads row by row, as `table`'s does. XY-Cut++ reads it column by column.
- **The bench split:** `extract-bench` records each file's warning codes, the scorer reports passes per PDF, and the report gives the `multi_column` order tests' pass rate on warned and unwarned pages.

**Out of scope** (and which todo covers it)

- Better order on these pages (wrapping text round a box, narrow gutters, near-grids): later rule changes, measured by this warning; models are [L3c](../done/L3c-model-plugins.md)'s.
- Structure-tree order: [L3g](../done/L3g-extract-structure-tree.md).
- A per-page order confidence key in the JSON: blocks' `confidence` and the warning carry it (Risks).
- Mixed horizontal and vertical writing: `extract-reading-order-ambiguous`, unchanged.

## Risks and open questions

- **False alarms.** Real pages with sidebars, forms or magazine layouts may trip `columns-revisited`. The bench split is the check, and the cut-offs are tuned against it before merge. A page that is read as XY-Cut++ means to (a full-width figure under 60% wide between two sections) is honestly uncertain, and a warning there is fair.
- **Narrow gutters below 0.6 font size** look like word spaces and stay unseen.
- **The ratchet.** `threshold.json`'s mean is meant only to rise. Adding files changes what it measures, so the new mean is recorded with a history entry; the owner may prefer the hard layouts in a separate set that the ratchet skips.
- **Two order warnings.** `extract-reading-order-ambiguous` (writing modes) and `extract-column-order-uncertain` (column splits) sit side by side; their pages link each other. The name says "column" to keep them apart, where the report said "reading order uncertain".
- **One warning per page.** Warnings are deduplicated by code and page, so a page with two doubts reports the first; the blocks' confidence marks both.
- **For the owner: a page-level key?** A `readingOrder: { confidence }` on each page of `laminapdf.extract/1` would let a pipeline filter pages without reading warnings. This todo keeps the block `confidence` and the warning, which need no schema change.
