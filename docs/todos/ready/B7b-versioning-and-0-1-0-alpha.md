## Goal

Version the library as one lockstep release and prove it installs outside the repo, without publishing anything (owner decision, 2026-10-28). Changesets drive versions for npm packages and a sync script keeps every core crate, `@lamina/wasm` and `@lamina/pdf` on the same version; ADR 0017 records the versioning policy; `0.1.0-alpha.0` is tagged locally; a clean project outside the repository installs the `pnpm pack` tarballs and a git/path dependency on the `lamina` crate and runs the quick start in each runtime.

## Scope

**In scope**

- `@changesets/cli` in the pnpm root, `.changeset/config.json` (fixed group: `@lamina/wasm`, `@lamina/pdf`; `privatePackages: { version: true, tag: true }`), contributor docs on adding a changeset.
- `cargo xtask version sync` (and `--check` in the fast lane): reads the npm fixed-group version and writes it to `[workspace.package] version` and every internal path dependency's `version`; fails CI when out of sync.
- ADR 0017 (versioning half): lockstep versions for core crates + `@lamina/wasm` + `@lamina/pdf`; `0.x` semantics (breaking changes bump minor); pre-release identifiers (`-alpha.N`); changelog generation; tag format `v0.1.0-alpha.0`; what the release lane runs; publishing (OIDC, provenance, attestations, name reservation) explicitly deferred to [P1](./P1-reserve-names-and-trusted-publishing.md).
- Drafts (not published): `docs/stability-policy.md` (what 0.x promises; error/warning codes never renamed; op JSON versioned per ADR 0006) and `CHANGELOG.md` generated by Changesets.
- `cargo xtask verify-install`: creates temp projects outside the repo (Node, Deno, Bun, a Vite browser app, a Worker via `wrangler dev --local` smoke, a Rust binary) that install `packages/*/lamina-*.tgz` from `pnpm pack` and depend on `lamina` via `path =` and via `git = <repo>` pinned to the ref under test (`--git-ref <tag-or-sha>`: in the release lane the tag that triggered it, e.g. `v0.1.0-alpha.0`; on a branch run the `v0.0.0-test.N` tag or `rev = <HEAD sha>`), then run the quick start; runs in the release lane on tags.
- Release-lane workflow on `v*` tags: full + nightly suites (the nightly jobs from [X3a](./X3a-nightly-lane.md)'s `nightly.yml`, called as a reusable workflow), publint/attw, `verify-install`; **no publish step**.
- Release-lane guard (owned here, not in X3a): refuse to release when the latest `nightly.yml` run on `main` failed (queried with `gh run list --workflow nightly.yml --branch main`).
- Local tag `v0.1.0-alpha.0` created after merge by the owner (or the merging agent with permission), pushed to GitHub.

**Out of scope** (and which todo covers it)

- Name reservation, OIDC trusted publishing, provenance, attestations, release workflow publish job: [P1](./P1-reserve-names-and-trusted-publishing.md).
- First registry pre-release, public stability policy, cargo-semver-checks against the registry: [P2](./P2-first-registry-prerelease.md).

## Acceptance criteria

- [ ] `cargo xtask version sync --check` passes; changing one crate's version by hand makes it fail
- [ ] `pnpm changeset version` bumps npm packages and the sync updates every crate to the same version
- [ ] `cargo xtask verify-install` passes on Linux for Node 22/24/26, Deno, Bun, Chromium (Vite app), workerd (local) and a Rust binary using both a path and a git dependency; before merge the git dependency points at the PR head (`rev = <HEAD sha>` or the throwaway `v0.0.0-test.N` tag), since `v0.1.0-alpha.0` only exists after merge
- [ ] The release-lane workflow passes `actionlint`, contains no publish step, and runs on the branch (temporary `push` trigger on a throwaway `v0.0.0-test.N` tag pushed from the branch, or `act`); the guard refuses when the latest nightly is red (tested by pointing it at a failed run)
- [ ] ADR 0017 Accepted (versioning part)
