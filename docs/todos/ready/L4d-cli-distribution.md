## Goal

Make `laminapdf` installable without a Rust toolchain: prebuilt binaries for macOS, Windows and Linux on x86_64 and aarch64, a Homebrew tap, and an npm package (`@laminapdf/cli`) that picks the right binary through per-platform optional dependencies, the pattern Biome and esbuild use. Every artefact has a checksum and a build-provenance attestation, and CI installs each one and runs it. Nothing is published yet: publishing waits for the owner's decision (P1), so this PR builds and verifies everything with dry runs.

## Scope

**In scope**

- **cargo-dist** (the `dist` tool, pinned 0.32.x in `tools/xtask/src/doctor.rs`) config for `laminapdf-cli` only: targets `x86_64-apple-darwin`, `aarch64-apple-darwin`, `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`, `x86_64-unknown-linux-musl`, `aarch64-unknown-linux-musl`, `x86_64-pc-windows-msvc`, `aarch64-pc-windows-msvc`. Release binaries build with the `mcp` feature on.
- Archives with the binary, `LICENSE-MIT`, `LICENSE-APACHE`, third-party notices (`cargo about` or the tool ADR 0019 picked), completions and man pages from L4b if merged.
- `sha256` checksums for every archive; GitHub artifact attestations (`actions/attest-build-provenance`) for archives and npm tarballs; a CycloneDX SBOM per release.
- **Homebrew**: a formula generated by dist for a tap repository (`<owner>/homebrew-tap`, name decided by the owner); not homebrew-core yet.
- **npm**: `packages/cli` → `@laminapdf/cli` with `bin: { "laminapdf": "bin/laminapdf.js" }` (a tiny launcher that resolves the platform package and execs the binary) and `optionalDependencies` on `@laminapdf/cli-darwin-arm64`, `-darwin-x64`, `-linux-x64-gnu`, `-linux-arm64-gnu`, `-linux-x64-musl`, `-linux-arm64-musl`, `-win32-x64`, `-win32-arm64`, each with `os`, `cpu` and (Linux) `libc` fields. Recommendation: this own Biome-style layout instead of dist's npm installer, so installs need no postinstall download. A script in `tools/` generates the platform packages from dist's artefacts.
- `.github/workflows/cli-release.yml`: `dist plan` on PRs that touch `crates/laminapdf-cli` or the dist config; full builds on `workflow_dispatch` with `dry-run: true` (default); a `publish` job in P1's protected `release` environment that only runs when the owner sets a repository variable (e.g. `LAMINA_PDF_PUBLISH_CLI=true`) and pushes a `laminapdf-cli-v*` tag.
- **Install verification in CI** (dry-run builds): on macOS, Windows and Linux runners, extract the archive and run `laminapdf --version` and `laminapdf info` on a fixture; `npm pack` the platform package and the wrapper, install them from the tarballs into a temporary project and run `npx laminapdf --version`; `brew install` the formula pointed at the local archive (`file://` URL) on macOS and run it; musl binary run in an Alpine container.

**Out of scope** (and which todo covers it)

- Actually publishing a release, crates.io publishing of `laminapdf-cli`, npm publishing: the owner's decision; publishing mechanics in [P1](../done/P1-reserve-names-and-trusted-publishing.md), first registry release in [P2](../done/P2-first-registry-prerelease.md).
- Code signing and notarisation of the binaries (macOS, Windows): reuse [D6c](./D6c-macos-signing-and-notarisation.md) and [D6d](./D6d-windows-signing.md) when they land; note the gap in the README until then.
- winget, Scoop, apt/rpm repositories, homebrew-core: later, on demand.
- A `wasm32-wasip2` build of the CLI: an open question below.

## Risks and open questions

- **Unsigned binaries:** macOS Gatekeeper and Windows SmartScreen warn on unsigned downloads. Homebrew and npm installs avoid most of it; signing waits for D6c/D6d.
- **PDFium in the binary:** if ADR 0004 picks PDFium for the CLI's `render`, every archive needs the PDFium library per target; hayro avoids that. Decide with C2a's result before the first release.
- **musl and aarch64 Windows:** cross-compiling may need extra runners; drop a target rather than ship one CI cannot run.
- **dist's npm installer vs our own packages:** dist's version is less work but downloads at install time; the recommendation is our own packages, but revisit if dist adds an optionalDependencies mode.
- **WASI build** (`wasm32-wasip2` under wasmtime with preopened directories as a sandbox): a research recommendation that was not verified; worth a spike after L4c.
