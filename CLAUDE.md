# CLAUDE.md

Guidance for Claude Code (and humans) working in this repository.

## What lamina is

lamina is a platform for anything and everything PDF: creating PDFs from code, parsing and extracting content, rendering, editing, form filling, signing, and transforming documents. The first core crates (`lamina-syntax` and `lamina-cos`, ported from the pdf-basics spike, `lamina-model`, `lamina-ops`, `lamina-save`, `lamina-content`, `lamina-text` and `lamina-build`) and the `lamina` façade over them exist, with its WASM bindings (`lamina-wasm`, built into the private `@lamina/wasm` package) and the TypeScript API over them (`@lamina/pdf`, private); there are no apps yet. Decisions are recorded as ADRs in `docs/decisions/`; accepted so far: a Rust core, `MIT OR Apache-2.0`, bytes in / bytes out with no AGPL/GPL dependencies ([0001](docs/decisions/0001-core-language-and-licence.md)); wasm-bindgen + tsify bindings ([0002](docs/decisions/0002-binding-strategy.md)); the Cargo + pnpm + `cargo xtask` monorepo ([0015](docs/decisions/0015-monorepo-layout-and-tooling.md)); cargo-deny and licence hygiene ([0019](docs/decisions/0019-supply-chain-and-licence-hygiene.md)); the reader tolerance policy and `Limits` ([0003](docs/decisions/0003-reader-tolerance-and-limits.md)); the document model ([0005](docs/decisions/0005-document-model.md); generation strategy §6: our own builder over `lamina-cos` reusing `pdf-writer`/`subsetter`/`skrifa`/HarfRust, per the `krilla-fit` spike, accepted when its PR merges); the op log and undo ([0006](docs/decisions/0006-op-log-and-undo.md)); the save planner ([0007](docs/decisions/0007-save-planner.md)); the test strategy ([0018](docs/decisions/0018-test-strategy.md)); content-stream reading ([0023](docs/decisions/0023-content-stream-reading.md)); the error and diagnostic contract, `LaminaError` in TS ([0026](docs/decisions/0026-error-and-diagnostic-contract.md)); coordinates in top-left points of the displayed CropBox, raw user space only in `UserSpace…` types, 0-based page `index` ([0027](docs/decisions/0027-coordinates-units-and-page-indexing.md)); the façade rules, the lock in the binding edge (core stays `Send + !Sync`), `Job::step(Budget)` in work units and `CancelToken` ([0028](docs/decisions/0028-facade-rules-jobs-and-cancellation.md)); mobile bindings: UniFFI `=0.32.2`, a `crates/lamina-ffi` edge crate, hand-written Swift/Kotlin layers that cancel async calls through a Rust token, SwiftPM and Maven Central AARs, 16 KB pages, `mobile-release` and size budgets ([0029](docs/decisions/0029-mobile-bindings-and-packaging.md)); for the web reader: the `RenderBackend` trait (bounded RGBA tiles, never model data from the renderer), PDFium by default on every viewer surface (pinned and SHA-256 checked) with hayro as the CI oracle and measured switch criteria, MuPDF prohibited, the two-parsers rule ([0004](docs/decisions/0004-render-backend.md)); React 19 chrome around a framework-free `@lamina/viewer`, one document worker per document, a typed RPC extending `@lamina/pdf/worker`, transferred `ImageBitmap`s, single-threaded with no COOP/COEP in v0.1 ([0009](docs/decisions/0009-web-client-architecture.md)); one `Platform` interface with capability flags and no platform checks in UI code ([0010](docs/decisions/0010-platform-adapter.md)); static-assets Workers on Cloudflare (staging separate, production only from `web-v*` tags), documents never through our servers (`#url=` fragment), ten testable privacy guarantees, strict headers, opt-in-only telemetry and hosted features ([0011](docs/decisions/0011-cloudflare-topology-and-privacy.md)). The plan for the rest is in `docs/plans/architecture.md`, with the shareable libraries (contracts, CLI/MCP, AI extraction, agent docs, mobile; Rounds L1–L6; ADR 0029 accepted, 0030–0031 proposed) in `docs/plans/shareable-libraries.md`; don't assume decisions that aren't in an ADR.

## Working agreements

- **Always work in a git worktree.** Start every piece of work in a new worktree off main (see docs/guidelines/git-workflow.md). The repo is a bare clone; worktrees are folders inside it: `git worktree add -b <type>/<desc> <type>-<desc> main`. Never `git stash` across worktrees; remove the worktree after merge.
- **Work from the todo board.** Every PR implements one todo from [`docs/todos/`](docs/todos/README.md) (`ready/` → `ongoing/` → `done/`), except bot, CI-maintenance, typo and board-only PRs. Pick one from `ready/` whose dependencies are all `done/`; claim it with a small claim PR that moves it to `ongoing/` on `main`; move it to `done/` in the work PR before merge, updating links and regenerating the board (`cargo xtask todos`). Plans link to their todos. See [git workflow §2](docs/guidelines/git-workflow.md#pick-work-from-the-todo-board).
- **Pull requests only.** `main` was initialized directly; every change since goes through a branch + PR. Branch names: `<type>/<short-description>` (e.g. `docs/pdf-research`).
- **Review every PR with `/code-review`, then merge.** After opening a PR, run `/code-review high <PR#>` (trivial and claim PRs: `low`) without `--comment`: don't post review comments. Fix the findings in new commits whose messages list each finding and its fix. If there were more than 6 findings, run `/code-review low <PR#>` after the fixes and record those the same way. Run `cargo xtask ci` locally, then squash-merge once CI is green. See [review and merge process](docs/guidelines/git-workflow.md#7-review-and-merge-process).
- **Conventional Commits** for commit messages: `type(scope): summary`.
- **Document as you go.** Plans go in `docs/plans/`, decisions in `docs/decisions/`, research in `docs/research/`. Update the folder's `README.md` index whenever you add a file.
- **Cite sources.** PDF behavior claims should point to ISO 32000-2 (PDF 2.0) or another primary source. Clearly label recommendations and opinions.
- **Spec first.** When implementing PDF features, read the relevant research chapter in `docs/research/` and the spec section before writing code. Real-world PDFs are frequently malformed — parsers must be tolerant, writers must be strict.
- **Use the project's skills.** Load the `/rust-best-practices` skill before writing or reviewing any Rust code, and the `/tauri-v2` skill before any Tauri work (`apps/desktop`, `src-tauri`, `tauri.conf.json`, commands, IPC, capabilities, the updater, bundling). Tell subagents to load them too. Where a skill and the guidelines in `docs/guidelines/` disagree, the guidelines win; record the difference in the guideline.
- **Mind licenses.** Many PDF libraries are AGPL or dual-licensed (e.g. iText, MuPDF/PyMuPDF). Don't add a dependency without checking its license.

## Code organization

Conventions that hold whatever the architecture ADRs decide (crate/package names in them are examples):

- [`docs/guidelines/code-organization.md`](docs/guidelines/code-organization.md): layout (`crates/lamina-*`, `packages/` as `@lamina/*`, `apps/`, `fixtures/`, `tools/xtask`, `spikes/` outside every workspace), dependency direction (pure bytes-in/bytes-out core, platform code only at the edges), public API, tests, when to split.
- [`docs/guidelines/rust.md`](docs/guidelines/rust.md): edition 2024, workspace `[lints]`, no `unwrap`/`expect`/`panic`/indexing in libraries, `unsafe` only in edge crates with `// SAFETY:`, `thiserror` errors.
- [`docs/guidelines/typescript.md`](docs/guidelines/typescript.md): strict tsconfig, ESM-only, no Node-only APIs in shared packages, named exports only, Biome, Vitest.

## Commands

Every repo-wide task goes through `cargo xtask` (source: `tools/xtask`). It runs from any directory and is exactly what CI runs. Needs rustup (the toolchain in `rust-toolchain.toml` installs itself), Node ≥ 22 (`.nvmrc`: 24) and pnpm (version pinned in `package.json`).

```sh
pnpm install                 # once per worktree: Biome, TypeScript (needed by the TS checks)
cargo xtask check            # everything a PR must pass: `check docs` + `check rust` + `check ts`
cargo xtask check docs       # docs-links + todos --check + portable paths + capability matrix static checks
                             #   + gen codes --check (fast; no network, no build, no node_modules)
cargo xtask check rust       # fmt --check, portability, clippy native + wasm32 (-D warnings), tests, rustdoc, cargo-deny
cargo xtask check ts         # biome ci, typecheck and tests of packages/* and apps/*, npm licences
cargo xtask fmt              # format Rust and TS/JSON (fmt --check only verifies)
cargo xtask lint             # clippy (native all-targets + wasm32 core crates) and biome ci
cargo xtask test             # cargo nextest (or cargo test) + doc tests, then TS tests
cargo xtask portability      # core crates: no fs/net/process/thread/clocks, no edge deps, forbid(unsafe),
                             #   cargo check for wasm32-unknown-unknown, aarch64-apple-ios, aarch64-linux-android
cargo xtask wasm             # build the wasm32 crates with the `wasm-release` profile, then @lamina/wasm's three modules
                             #   (wasm-bindgen + wasm-opt, binaryen fetched into target/tools/) into packages/wasm/dist/,
                             #   and their Node tests (wasm-bindgen-test, test/smoke.test.ts), then @lamina/pdf over them
                             #   (tsc, typecheck, Vitest in Node and Vite, publint, attw --pack)
cargo xtask size             # raw/gzip/brotli of each module, min+gzip glue and @lamina/pdf's JS; fails above packages/wasm/size-budgets.json
                             #   (ADR 0016 §6), writes target/size-report.json, twiggy diff on > 5 % growth
cargo xtask pdf-runtimes [node|chromium|firefox|webkit|deno|bun|workerd]…  # @lamina/pdf's example suite per runtime (default
                             #   all; after `wasm`): byte-identical to the goldens; hello/report timings and WebAssembly memory
                             #   vs pdf-library §4 in the job summary (recorded, not asserted); `node` is the one on PATH;
                             #   Deno, Bun, wrangler and Playwright are dev deps (`playwright install` runs first);
                             #   --history <dir> --runner <label> --record appends them to history.jsonl (nightly)
cargo xtask gen codes [--check|--md]  # validate fixtures/codes.json against codes.schema.json, then write the error contract:
                             #   the façade's ErrorCode/WarningCode (crates/lamina/src/generated/codes.rs), @lamina/pdf's
                             #   unions, KINDS/HINTS and explain text (packages/pdf/src/generated/), the lamina.error/1
                             #   schema (packages/pdf/schemas/, crates/lamina/schemas/) and docs/errors/README.md's tables;
                             #   --check fails naming each stale file; --md prints the tables (for the docs site)
cargo xtask deny             # cargo-deny (licences, advisories, bans, sources) + npm licence check
cargo xtask npm-licenses     # npm licence check only
cargo xtask docs-links       # every relative link and #anchor in tracked *.md resolves (GitHub slugs); --json for tooling
cargo xtask docs-links --external  # nightly: every http(s) URL in tracked *.md answers (links, bare URLs, HTML href/src;
                             #   curl, one retry, per-host rate limit, allowlist .config/link-check.toml; report in target/nightly/links/)
cargo xtask todos            # regenerate docs/todos/README.md and each todo's Blocks from its Depends on links
cargo xtask todos --check    # fail if the board or a Blocks field is stale, or the todo graph is inconsistent
cargo xtask capabilities     # run the tests tagged `/// capability: <ID> <surface> <status>`, regenerate docs/capabilities/README.md
cargo xtask capabilities --check  # full lane: fail if that page differs from what the passing tagged tests prove
cargo xtask golden --update  # regenerate every golden in fixtures/golden/ (and fixtures/reading-order/) from its source, print the list
                             #   (and fixtures/shaping/ with hb-shape when HarfBuzz is installed)
cargo xtask examples         # run the lamina examples into target/examples-out/, byte-compare with
                             #   fixtures/golden/examples/, qpdf --check each (needs qpdf)
cargo xtask render-golden [--update]  # every page of fixtures/golden/examples/ by PDFium (Python with
                             #   tools/render/requirements.txt) and hayro at 72 dpi vs fixtures/render-golden/,
                             #   and hayro vs PDFium at 150 dpi
cargo xtask corpus facts     # rewrite fixtures/corpus/expected.json with pypdf ($LAMINA_PYTHON or python3)
cargo xtask differential     # lamina vs pypdf's precomputed facts (corpus + fixed-seed mutants; part of `test`)
cargo xtask differential --update  # regenerate fixtures/differential/expected.json with pypdf
cargo xtask differential --text [--update]  # lamina's page text vs pdf.js and pdftotext (whitespace and bidi controls removed) from
                             #   fixtures/differential/text.json (tools/differential/text.mjs), exceptions in text-exceptions.json
cargo xtask quads [--update] # lamina's glyph quads vs PDFium's loose char boxes, fixtures/text/charboxes.json (tools/render/charbox.py)
cargo xtask differential --full [--update]  # the full lane's set: 36 mutants per corpus file (full.json; needs cargo-nextest)
cargo xtask roundtrip [--tools qpdf,pdfjs,pdfium]  # lamina saves fixtures x ops x modes, reopens each output; qpdf --check,
                             #   pdf.js and PDFium check them (needs qpdf, Node, Python with tools/roundtrip/requirements.txt)
cargo xtask fuzz <target> [--time N]  # cargo +nightly fuzz: lex, parse_object, flate_decode, open, page_tree, content,
                                      #   ops_json, save_roundtrip, extract_text
cargo xtask fuzz --all [--time N] [--jobs N]  # every fuzz target, N at once (the full lane: --jobs 4,
                                      #   30 s per target on PRs, 120 s on pushes to main)
cargo xtask fuzz cmin [<target>]      # minimise fuzz/corpus/ (the full lane does this before caching it on main)
cargo xtask changes [--base <rev>]    # paths changed since the merge base with <rev> (default origin/main, else main);
                                      #   code=true unless all are on the docs allowlist
cargo xtask fuzz tmin <target>        # minimise every crash in fuzz/artifacts/<target>/
cargo xtask corpus fetch     # external corpora (pinned commits, SHA-256 per file in fixtures/corpus-manifest.toml) → target/corpus/
cargo xtask differential --live [--corpus external|mutants|all] [--source <name>]… [--tools pdfjs,pdfium,qpdf,pypdf] [--sample N]
                             # nightly: lamina vs live pdf.js, PDFium, qpdf, pypdf over the external corpus and the mutants
                             #   (250 per corpus file from the fast set's series + the full set's 36); --sample is stratified per source
cargo xtask scaling          # nightly: release-mode #[ignore]d tests (scaling ratios), one retry reported as flaky
cargo xtask bench [--quick]  # nightly: criterion benches (crates/lamina-cos/benches, crates/lamina-save/benches, crates/lamina/benches:
                             #   the 100-page text report); --history <dir> flags >10% regressions
cargo xtask nightly [--quick]  # the whole nightly lane locally, in the workflow's order (--quick: short budgets)
cargo xtask ci               # the whole fast lane locally: check + wasm + size
cargo xtask doctor           # are rustc, node, pnpm, cargo-deny, cargo-nextest, wasm-opt … at the pinned versions?
cargo xtask doctor --install # install the pinned cargo tools
```

A single crate: `cargo test -p lamina-cos` or `cargo test -p lamina-save` (integration tests read the shared `fixtures/`; golden files are never rewritten by a test). Hangs are caught by nextest's per-test timeout in `.config/nextest.toml` (robustness tests: 30 s), not by wall-clock asserts (ADR 0018); plain `cargo test` runs the same tests without the timeout.

CI has two PR lanes ([ADR 0018 §2](docs/decisions/0018-test-strategy.md#2-ci-lanes) and its implementation note). The fast lane (`.github/workflows/ci.yml`) runs on every PR, but skips its jobs on docs-only PRs (same `cargo xtask changes` classification); its `pdf-runtimes` jobs run `cargo xtask pdf-runtimes` in Node 22, 26 and Chromium over the `wasm` job's build (an artifact; Node 24, `.nvmrc`, is the `wasm` job's own run); the full lane's `changes` job runs `cargo xtask check docs` on every PR, so docs-only PRs are still checked under `gate`. The full lane (`.github/workflows/full.yml`) runs on every PR too: its `changes` job (`cargo xtask changes`) classifies the PR against the docs allowlist (defined once, in `is_docs` in `tools/xtask/src/changes.rs`); for code PRs and every push to `main` it runs the full differential set, every fuzz target (30 s each on PRs, 2 minutes on `main`, 4 at once), the capability matrix check (`cargo xtask capabilities --check`) and the round-trip suite (`cargo xtask roundtrip`: qpdf, pdf.js and PDFium on the runner; the fast lane runs only its lamina half, `lamina-save`'s `roundtrip_suite.rs`) and the `lamina` examples (`cargo xtask examples`, `cargo xtask render-golden`; the fast lane runs `crates/lamina/tests/examples.rs`), and `@lamina/pdf` in Firefox, WebKit, Deno, Bun and workerd (`pdf-build` builds it once, `pdf-runtimes` is a matrix; Playwright browsers stay in each runner's tool cache, `PLAYWRIGHT_BROWSERS_PATH`). Every CI job runs on self-hosted runners on one Mac, no GitHub-hosted minutes: the two macOS ARM64 runners (`[self-hosted, macOS, ARM64]`; each Rust-building job keeps its build output in a per-runner, per-job, per-trigger `CARGO_TARGET_DIR` in the runner's tool cache, see `.github/actions/isolate-rust-home`, so PR output is never reused on `main`; xtask's reports stay in the checkout's `target/`) and, for the full lane's `check-linux` job (`cargo xtask check` on Linux ARM64), a Linux runner in a Docker container (`[self-hosted, Linux, ARM64]`; started with `tools/ci-runner/linux/up.sh`, see its README; [X5](docs/todos/done/X5-linux-ci-container.md)). `check-linux` runs only while the repository variable `LINUX_RUNNER` is `true` and the runner's heartbeat (`LINUX_RUNNER_HEARTBEAT`) is under 15 minutes old, read once by `changes` as its `linux` output (`gate` accepts the skip otherwise). Windows is parked in [X6](docs/todos/ready/X6-windows-ci.md). Its `gate` job is the required check. A new full-lane job uses exactly `if: ${{ !cancelled() && needs.changes.outputs.code == 'true' }}` (`check-linux` adds `needs.changes.outputs.linux == 'true'`) and joins `gate`'s `needs` (see the comment at the top of `full.yml`). Both lanes use nextest's `ci` profile (no retries).

Reading API (ADR 0003, 0005): `Document::open(source, OpenOptions)` takes an owned or shared `ByteSource` (`Vec<u8>`, `Arc<[u8]>`, `&'static [u8]`, `Arc<dyn ByteSource>`; in-memory ones are parsed in place, others are read in 64 KiB windows bounded by `Limits::max_read_window`, and a source answering `Pending` makes open or any lazy call fail with `Error::DataPending { ranges }` listing the ranges it needs next: windows, stream data or xref-entry probes; the edge crate `lamina-source` has `SparseSource`, filled with `supply(offset, bytes)`, and `retry`/`open_with`, which fetch those ranges and call again, plus `FileSource` and `MmapSource`); `OpenOptions` holds `Limits` (hard limits fail with `Error::LimitExceeded`, soft ones drop with a warning), strict mode (`Error::Strict`) and the password: the standard security handler (R2–R6, ISO 32000 §7.6) decrypts strings and streams on load, tries it as user then owner password (owner first for R5/R6), and fails with `password-required` or `wrong-password`; `Document::encryption()` and `permissions()` describe the result. Warning and error codes are listed once in `fixtures/codes.json` (v2: `code`, `kind`, `summary`, `hint`, `since` per code; ADR 0026; its schema is `fixtures/codes.schema.json`), from which `cargo xtask gen codes` generates every surface's tables (never edit them by hand; a new code is one entry, one `docs/errors/<code>.md` page, its `code()`/`kind()` arms and a regeneration), and which `crates/lamina-cos/tests/codes.rs` checks against the Rust enums and the `docs/errors/<code>.md` pages; every error and `Warning` has `code()`, `kind()` (one of nine `ErrorKind`s, an exhaustive match per type that each crate's unit tests check against the file) and `location()` (positions are tagged: `Position::{FileOffset, Object, InStream}`), and no `Display` formats text read from the input. Typed views live in `lamina-model`: its `Document` wraps the COS one (and derefs to it) with the ID allocator; `doc.pages()`, `doc.outline()`, `doc.info()`, `doc.page_labels()`, `doc.name_tree(key)`; views raise warnings on the document via `lamina_cos::Document::report`. `LaminaId`s are `p12.0` (kind + object) or path IDs such as `p5.0/Kids/3` for direct dictionaries (ADR 0005 §5).

Content API (ADR 0023): `lamina_content::ContentIter::new(&bytes)` tokenizes decoded content into `Op`s (Annex A `Operator` + operands; inline images whole) and `Issue`s; `interpret_page(&doc, &page, &mut visitor)` (or `interpret_content(&doc, &bytes, resources, &mut visitor)`) runs it with graphics/text state, resources, Form XObjects (depth `max_xobject_depth`, cycles by object identity) and marked content, calling `Visitor` methods (`show_text` returns the `TextAdvance` of the glyphs; glyph decoding is `lamina-text`'s). Content repairs are `lamina_cos::Warning`s (`content-*`, `inline-image-unterminated`, `xobject-cycle`) recorded on the document; `max_content_operators` counts every operator of one call, forms each time they are drawn.

Editing API (ADR 0005 §3, 0006): the base bytes never change; every write goes through `lamina_cos::Document::edit()` → `CosMut` into the overlay (resolution reads it first; an entry equal to the base is dropped; `is_dirty()`), with a journal (`journal_mark`, `rollback_to`, `take_changes`). `lamina_ops::Document` wraps the model document and is the only write path for callers: `doc.transact(Origin::Local, |tx| { tx.apply(op)?; … })`, `tx.savepoint(…)`, or `begin`/`apply`/`commit`/`rollback`; `undo()`/`redo()` return `UndoOutcome::{Applied, Partial, Skipped}`. Ops (`SetInfo`, `RotatePage`) are serde JSON (`{ "op": "rotatePage", "args": { … } }`, envelope `OpLog { v: 1, ops }`), with frozen samples in `fixtures/ops/v1/`.

Saving API (ADR 0007, ADR 0005 §3; `lamina-save`): the `Save` trait on `lamina_ops::Document`: `doc.plan(&options)`, `doc.save(&mut sink, &options)` (write-only sink: a full rewrite leaves `SaveState::SavedNotRebased` until `doc.rebase(bytes)`) and `doc.save_and_rebase(sink, &options)` (a `ReadableSink`). Every save plans first: `SavePlanner::new(&doc)` detects the `SaveConstraint` (signatures from signature fields, `/Perms` DocMDP/UR3, `/Reference` transforms, `/Lock`, DocTimeStamp, and a repaired file's objects; `doc_mdp`; rewrite reasons `RepairedBase`, `EncryptedBase`, `NoBase`, `OpRequiresRewrite`; `signatures_unknown` when part of the form can't be followed (counts as signed); violations of the pending op classes, `lamina_ops::Document::pending_changes()`), `kind()` is `Free | AppendOnly | RequiresRewrite | Conflict`, and `SaveMode::{Auto (default), Incremental, FullRewrite}` is resolved per ADR 0007 §3; refusals are `would-invalidate-signatures` (the whole constraint), `requires-rewrite` and `encrypted-base` (every mode, unless `with_remove_encryption(true)`: a plaintext full rewrite); an unchanged document always saves incrementally (the base bytes unchanged). `with_invalidate_signatures(true)` is the explicit override (the writers write the output with the invalidated `/V` and `/Perms` entries removed, listed in `SaveReport::invalidated`; the document changes only through the rebase); `planner.would_violate(&op)` checks an edit early. `IncrementalWriter` / `FullWriter` over a `lamina_cos::Document` stream to a `WriteSink` (`Vec<u8>`, `IoWrite<W>`; append only). A failed save leaves the document `Dirty`; a failed rebase after a complete write returns `SaveError::NotRebased` with the output; undo history survives only an incremental save that freed nothing. `SaveOptions` (`mode`, overrides, `IncrementalOutput`, `Renumber::{Keep, Compact}`, `XrefKind::{Stream, Classic}`, `XrefEol`), `SaveReport`. `/ID[0]` is kept, `/ID[1]` is a content hash; output is byte-deterministic. The spike-era `Writer` / `incremental_update` (now in `lamina-save`) build test files from scratch; `lamina-cos`, `lamina-model` and `lamina-ops` reach it through a dev-dependency.

`spikes/pdfium-wasm/` — `@embedpdf/pdfium` beside `@lamina/pdf` in one web worker (Round C1b); standalone, its own pnpm project, not in CI: `cargo xtask wasm`, then `sh scripts/pack-lamina.sh && pnpm install && node scripts/make-fixtures.mjs && pnpm exec playwright test && node scripts/summarise.mjs` (Chromium, Firefox, WebKit; see its README).

`spikes/hayro-parity/` — hayro vs PDFium render parity (Round C1a); standalone, not in CI: `scripts/fetch-pdfium.sh && scripts/fetch-corpora.sh` once (downloads into gitignored folders), then `cargo run --release` writes `out/dpi96/results.csv` and `summary.md` (see its README).

`spikes/pdf-basics/` — the same minimal PDF core in Rust and TypeScript (see its `SPEC.md`):

```sh
# Rust (needs rustup; targets wasm32-unknown-unknown, aarch64-apple-ios, aarch64-linux-android)
cd spikes/pdf-basics/rust
cargo test
cargo clippy --all-targets --all-features --locked -- -D warnings
scripts/check-targets.sh                               # everything: cross-target checks, wasm build, fmt, clippy, tests
cargo build --release --target wasm32-unknown-unknown  # wasm loaded by the TS tests

# TypeScript (Node ≥ 20, pnpm)
cd spikes/pdf-basics/ts
pnpm install
pnpm typecheck && pnpm lint && pnpm test               # WASM interop tests run once the Rust wasm is built
pnpm size                                              # min+gz bundle size
```

Rust code follows the `rust-best-practices` skill (no `unwrap`/`expect` in library code, clippy clean with `-D warnings`). Library code in both languages is bytes-in/bytes-out: no file system, network or Node-only APIs, so it runs on web, mobile and desktop.
