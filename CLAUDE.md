# CLAUDE.md

Guidance for Claude Code (and humans) working in this repository.

## What Lamina PDF is

Lamina PDF is a platform for anything and everything PDF: creating PDFs from code, parsing and extracting content, rendering, editing, form filling, signing, and transforming documents. The first core crates (`laminapdf-syntax` and `laminapdf-cos`, ported from the pdf-basics spike, `laminapdf-model`, `laminapdf-ops`, `laminapdf-save`, `laminapdf-content`, `laminapdf-text` and `laminapdf-build`) and the `laminapdf` façade over them exist, with its WASM bindings (`laminapdf-wasm`, built into the `@laminapdf/wasm` package) and the TypeScript API over them (`@laminapdf/sdk`), and the docs site (`apps/docs`, the only app so far). Decisions are recorded as ADRs in `docs/decisions/`; accepted so far: a Rust core, `MIT OR Apache-2.0`, bytes in / bytes out with no AGPL/GPL dependencies ([0001](docs/decisions/0001-core-language-and-licence.md)); wasm-bindgen + tsify bindings ([0002](docs/decisions/0002-binding-strategy.md)); the Cargo + pnpm + `cargo xtask` monorepo, npm packages under `@laminapdf` (amended 2026-10-31) ([0015](docs/decisions/0015-monorepo-layout-and-tooling.md)); one lockstep version for every crate, `@laminapdf/wasm`, `@laminapdf/sdk` and the render packages (`@laminapdf/render`, `-hayro`, `-pdfium`) and `@laminapdf/viewer`, driven by Changesets and copied into Cargo by `cargo xtask version sync`, `0.x` with `-alpha.N` pre-releases, `v<version>` tags and a release lane that publishes on `v*` tags: crates.io trusted publishing, npm staged publishing approved by the owner ([0017](docs/decisions/0017-versioning-and-release.md)); cargo-deny and licence hygiene ([0019](docs/decisions/0019-supply-chain-and-licence-hygiene.md)); the reader tolerance policy and `Limits` ([0003](docs/decisions/0003-reader-tolerance-and-limits.md)); the document model ([0005](docs/decisions/0005-document-model.md); generation strategy §6: our own builder over `laminapdf-cos` reusing `pdf-writer`/`subsetter`/`skrifa`/HarfRust, per the `krilla-fit` spike, accepted when its PR merges); the op log and undo ([0006](docs/decisions/0006-op-log-and-undo.md)); the save planner ([0007](docs/decisions/0007-save-planner.md)); the test strategy ([0018](docs/decisions/0018-test-strategy.md)); content-stream reading ([0023](docs/decisions/0023-content-stream-reading.md)); the error and diagnostic contract, `LaminaPdfError` in TS ([0026](docs/decisions/0026-error-and-diagnostic-contract.md)); coordinates in top-left points of the displayed CropBox, raw user space only in `UserSpace…` types, 0-based page `index` ([0027](docs/decisions/0027-coordinates-units-and-page-indexing.md)); the façade rules, the lock in the binding edge (core stays `Send + !Sync`), `Job::step(Budget)` in work units and `CancelToken` ([0028](docs/decisions/0028-facade-rules-jobs-and-cancellation.md)); mobile bindings: UniFFI `=0.32.2`, a `crates/lamina-ffi` edge crate, hand-written Swift/Kotlin layers that cancel async calls through a Rust token, SwiftPM and Maven Central AARs, 16 KB pages, `mobile-release` and size budgets ([0029](docs/decisions/0029-mobile-bindings-and-packaging.md)); for the web reader: the `RenderBackend` trait (bounded RGBA tiles, never model data from the renderer), PDFium by default on every viewer surface (pinned and SHA-256 checked) with hayro as the CI oracle and measured switch criteria, MuPDF prohibited, the two-parsers rule ([0004](docs/decisions/0004-render-backend.md)); React 19 chrome around a framework-free `@laminapdf/viewer`, one document worker per document, a typed RPC extending `@laminapdf/sdk/worker`, transferred `ImageBitmap`s, single-threaded with no COOP/COEP in v0.1 ([0009](docs/decisions/0009-web-client-architecture.md)); one `Platform` interface with capability flags and no platform checks in UI code ([0010](docs/decisions/0010-platform-adapter.md)); static-assets Workers on Cloudflare (staging separate, production only from `web-v*` tags), documents never through our servers (`#url=` fragment), ten testable privacy guarantees, strict headers, opt-in-only telemetry and hosted features ([0011](docs/decisions/0011-cloudflare-topology-and-privacy.md)). The plan for the rest is in `docs/plans/architecture.md`, with the shareable libraries (contracts, CLI/MCP, AI extraction, agent docs, mobile; Rounds L1–L6; ADR 0029 accepted, 0030–0031 proposed) in `docs/plans/shareable-libraries.md`; don't assume decisions that aren't in an ADR.

## Working agreements

- **Always work in a git worktree.** Start every piece of work in a new worktree off main (see docs/guidelines/git-workflow.md). The repo is a bare clone; worktrees are folders inside it: `git worktree add -b <type>/<desc> <type>-<desc> main`. Never `git stash` across worktrees; remove the worktree after merge.
- **Work from the todo board.** Every PR implements one todo from [`docs/todos/`](docs/todos/README.md) (`ready/` → `ongoing/` → `done/`), except bot, CI-maintenance, typo and board-only PRs. Pick one from `ready/` whose dependencies are all `done/`; claim it by opening its work PR at once; its first commit moves it to `ongoing/`. The open PR is the claim, so check `gh pr list` before picking. Move it to `done/` in the same PR before merge, updating links and regenerating the board (`cargo xtask todos`). Plans link to their todos. See [git workflow §2](docs/guidelines/git-workflow.md#pick-work-from-the-todo-board).
- **Pull requests only.** `main` was initialized directly; every change since goes through a branch + PR. Branch names: `<type>/<short-description>` (e.g. `docs/pdf-research`).
- **Review every PR with `/code-review`, then merge.** After opening a PR, run `/code-review high <PR#>` (trivial PRs: `low`) without `--comment`: don't post review comments. Fix the findings in new commits whose messages list each finding and its fix. If there were more than 6 findings, run `/code-review low <PR#>` after the fixes and record those the same way. A non-trivial PR that adds or changes prose people read also gets `/writing-review`, whose findings are counted and fixed separately ([§7](docs/guidelines/git-workflow.md#7-review-and-merge-process)). Run `cargo xtask ci` locally, then squash-merge once CI is green. See [review and merge process](docs/guidelines/git-workflow.md#7-review-and-merge-process).
- **Conventional Commits** for commit messages: `type(scope): summary`.
- **Document as you go.** Plans go in `docs/plans/`, decisions in `docs/decisions/`, research in `docs/research/`. Update the folder's `README.md` index whenever you add a file.
- **Cite sources.** PDF behavior claims should point to ISO 32000-2 (PDF 2.0) or another primary source. Clearly label recommendations and opinions.
- **Spec first.** When implementing PDF features, read the relevant research chapter in `docs/research/` and the spec section before writing code. Real-world PDFs are frequently malformed — parsers must be tolerant, writers must be strict.
- **Use the project's skills.** Load the `/rust-best-practices` skill before writing or reviewing any Rust code, and the `/tauri-v2` skill before any Tauri work (`apps/desktop`, `src-tauri`, `tauri.conf.json`, commands, IPC, capabilities, the updater, bundling). Load `/writing` before drafting prose people read, and run `/writing-review` on it once the PR is open; [git workflow §7](docs/guidelines/git-workflow.md#7-review-and-merge-process) says which prose and how to handle the findings. Tell subagents to load these skills too. Where a skill and the guidelines in `docs/guidelines/` disagree, the guidelines win: note it in the commit message, and if the skill's rule is better, change the guideline in its own PR.
- **Mind licenses.** Many PDF libraries are AGPL or dual-licensed (e.g. iText, MuPDF/PyMuPDF). Don't add a dependency without checking its license.

## Code organization

Conventions that hold whatever the architecture ADRs decide (crate/package names in them are examples):

- [`docs/guidelines/code-organization.md`](docs/guidelines/code-organization.md): layout (`crates/laminapdf-*`, `packages/` as `@laminapdf/*`, `apps/`, `fixtures/`, `tools/xtask`, `spikes/` outside every workspace), dependency direction (pure bytes-in/bytes-out core, platform code only at the edges), public API, tests, when to split.
- [`docs/guidelines/rust.md`](docs/guidelines/rust.md): edition 2024, workspace `[lints]`, no `unwrap`/`expect`/`panic`/indexing in libraries, `unsafe` only in edge crates with `// SAFETY:`, `thiserror` errors.
- [`docs/guidelines/typescript.md`](docs/guidelines/typescript.md): strict tsconfig, ESM-only, no Node-only APIs in shared packages, named exports only, Biome, Vitest.
- [`docs/guidelines/maintainability.md`](docs/guidelines/maintainability.md): one home per concept (search before writing a helper), size budgets that only go down, one public path per item, no test code in shipped code, comments that say why.
- [`docs/guidelines/docs-writing.md`](docs/guidelines/docs-writing.md) and [`docs/guidelines/examples.md`](docs/guidelines/examples.md): reader-facing docs tell a story in plain English, with no internal IDs; examples use only the public API, carry no test scaffolding and read like code we would merge.

## Commands

Every repo-wide task goes through `cargo xtask` (source: `tools/xtask`). It runs from any directory and is exactly what CI runs. Needs rustup (the toolchain in `rust-toolchain.toml` installs itself), Node ≥ 22 (`.nvmrc`: 24) and pnpm (version pinned in `package.json`).

```sh
pnpm install                 # once per worktree: Biome, TypeScript (needed by the TS checks)
cargo xtask check            # everything a PR must pass: `check docs` + `check rust` + `check ts`
cargo xtask check docs       # docs-links + docs-prose + docs-snippets + todos --check + portable paths + capability matrix static checks
                             #   + gen codes --check + gen boundary --check + version sync --check (fast; no network, no build, no node_modules)
cargo xtask check docs-prose [--all-strict] [--warnings] [--json]  # reader-facing text (docs site, docs/errors, package
                             #   READMEs) vs docs/guidelines/docs-writing.md (word lists: tools/xtask/docs-prose.toml); errors on
                             #   files changed since the merge base with main (drafts included), counted warnings elsewhere
cargo xtask check docs-snippets [--all-strict] [--warnings] [--json]  # the examples and Snippet's glob vs
                             #   docs/guidelines/examples.md (headers, shown on a page or in examples/UNUSED.md, TS/Rust pairs in
                             #   tools/xtask/docs-snippets.toml, public imports, no test scaffolding, ≤ 100 lines); strict on changed
                             #   examples, warnings elsewhere
cargo xtask biome-examples [--all-strict]  # Biome with --error-on-warnings on the changed TS examples (every one with --all-strict)
cargo xtask clippy-examples [--all-strict] [--warnings] [--json]  # clippy on Lamina PDF's examples with
                             #   tools/xtask/clippy-examples/clippy.toml (functions ≤ 40 lines) and let_underscore_must_use;
                             #   strict on changed examples, warnings elsewhere
cargo xtask check rust       # fmt --check, maintainability, portability, clippy native + wasm32 (-D warnings), clippy-examples,
                             #   tests, rustdoc, cargo-deny
cargo xtask check maintainability  # docs/guidelines/maintainability.md's Rust rules, no build: ≤ 800 non-test lines per module
                             #   and no new size-lint #[expect] (tools/xtask/maintainability-baseline.toml), no pub type name in
                             #   two crates and no façade name re-exported twice (maintainability-duplicates.toml); both only shrink;
                             #   no `matches!` or `Err(…)` or-pattern on LimitExceeded or DataPending outside laminapdf_cos::error;
                             #   no copied test helper (`fn fixtures_dir`, `fn classic`, `struct Rng`) or cross-crate `#[path]` outside

cargo xtask check ts         # biome ci (packages/sdk/biome.json's examples override warns; changed examples are linted
                             #   again with --error-on-warnings), typecheck and tests of packages/* and apps/*, the docs site's build
                             #   (apps/docs: TypeDoc, snippets, code table; fails on a broken internal link), npm licences
cargo xtask fmt              # format Rust and TS/JSON (fmt --check only verifies)
cargo xtask lint             # clippy (native all-targets + wasm32 core crates) and biome ci
cargo xtask test             # cargo nextest (or cargo test) + doc tests, then TS tests
cargo xtask portability      # core crates: no fs/net/process/thread/clocks, no edge deps, forbid(unsafe),
                             #   cargo check for wasm32-unknown-unknown, aarch64-apple-ios, aarch64-linux-android
cargo xtask wasm             # build the wasm32 crates with the `wasm-release` profile, then @laminapdf/wasm's three modules
                             #   (wasm-bindgen + wasm-opt, binaryen fetched into target/tools/) into packages/wasm/dist/,
                             #   and their Node tests (wasm-bindgen-test, test/smoke.test.ts), then @laminapdf/sdk over them
                             #   (tsc, typecheck, Vitest in Node and Vite, publint, attw --pack)
cargo xtask size             # raw/gzip/brotli of each module, min+gzip glue and @laminapdf/sdk's JS; fails above packages/wasm/size-budgets.json
                             #   (ADR 0016 §6), writes target/size-report.json, twiggy diff on > 5 % growth
cargo xtask pdf-runtimes [node|chromium|firefox|webkit|deno|bun|workerd]… [--label <name>]  # @laminapdf/sdk's example suite per runtime (default
                             #   all; after `wasm`): byte-identical to the goldens; hello/report timings and WebAssembly memory
                             #   vs pdf-library §4 in the job summary (recorded, not asserted); `node` is the one on PATH;
                             #   Deno, Bun, wrangler and Playwright are dev deps (`playwright install` runs first);
```

CI has two PR lanes ([ADR 0018 §2](docs/decisions/0018-test-strategy.md#2-ci-lanes) and its implementation note). The fast lane (`.github/workflows/ci.yml`) runs on every PR, but skips its jobs on docs-only PRs (same `cargo xtask changes` classification); its two `pdf-runtimes` jobs run `cargo xtask pdf-runtimes` in every runtime (Chromium, Firefox and WebKit; Deno, Bun, workerd and Node 22 and 26) over the `wasm` job's build (an artifact; Node 24, `.nvmrc`, is the `wasm` job's own run; Playwright browsers stay in each runner's tool cache, `PLAYWRIGHT_BROWSERS_PATH`); the full lane's `changes` job runs `cargo xtask check docs` on every PR, so docs-only PRs are still checked under `gate` (the fast lane's Rust job runs it only on pushes to `main`). The full lane (`.github/workflows/full.yml`) runs on every PR too: its `changes` job (`cargo xtask changes`) classifies the PR against the docs allowlist (defined once, in `is_docs` in `tools/xtask/src/changes.rs`); for code PRs and every push to `main` it runs, one after another in its `suites` job, the full differential set, the capability matrix check (`cargo xtask capabilities --check`), the round-trip suite (`cargo xtask roundtrip`: qpdf, pdf.js and PDFium on the runner; the fast lane runs only its Lamina PDF half, `laminapdf-save`'s `roundtrip_suite.rs`) and the `laminapdf` examples (`cargo xtask examples`, `cargo xtask render-golden`; the fast lane runs `crates/laminapdf/tests/examples.rs`), and in its `fuzz` job every fuzz target (30 s each on PRs, 2 minutes on `main`, 4 at once). Every CI job runs on self-hosted runners on one Mac, no GitHub-hosted minutes: the macOS ARM64 runners (`[self-hosted, macOS, ARM64]`; Node and pnpm come from `.github/actions/node-pnpm`, which keeps the pnpm store in the runner's tool cache; each Rust-building job keeps its build output in a per-runner, per-job, per-trigger `CARGO_TARGET_DIR` in the runner's tool cache, see `.github/actions/isolate-rust-home`, so PR output is never reused on `main`; xtask's reports stay in the checkout's `target/`) and, for the full lane's `check-linux` job (`cargo xtask check` on Linux ARM64), a Linux runner in a Docker container (`[self-hosted, Linux, ARM64]`; started with `tools/ci-runner/linux/up.sh`, see its README; [X5](docs/todos/done/X5-linux-ci-container.md)). `check-linux` runs only while the repository variable `LINUX_RUNNER` is `true` and the runner's heartbeat (`LINUX_RUNNER_HEARTBEAT`) is under 15 minutes old, read once by `changes` as its `linux` output (`gate` accepts the skip otherwise). Windows is parked in [X6](docs/todos/ready/X6-windows-ci.md). Branch protection requires the full lane's `gate` and the fast lane's `fast-gate` (X7), each passing when every job of its lane passed or was skipped on a docs-only PR. A new job in either lane uses exactly `if: ${{ !cancelled() && needs.changes.outputs.code == 'true' }}` (`check-linux` adds `needs.changes.outputs.linux == 'true'`) and joins the `needs` of its lane's gate (`fast-gate` or `gate`; see the comments at the top of `ci.yml` and `full.yml`), which `tools/xtask/src/workflows.rs` tests. Both lanes use nextest's `ci` profile (no retries). On pushes to `main`, the fast lane's Rust job renders the workspace's rustdoc into an emptied `doc/` and uploads it as the `rustdoc` artefact (the docs site points to it). The docs workflow (`.github/workflows/docs.yml`) deploys `apps/docs` to Cloudflare for changes to the site or its inputs: for a same-repository PR, `preview-build` builds it without secrets and `preview-deploy` (secrets, no PR code: `wrangler.toml` and the Wrangler version from the default branch) uploads the artifact as a `pr-<n>` preview and keeps one PR comment with its URL; `production` builds and deploys on pushes to `main`; without the `CLOUDFLARE_API_TOKEN`/`CLOUDFLARE_ACCOUNT_ID` secrets the deploy steps skip with a notice (setup in `apps/docs/README.md`). The site has no GitHub links unless built with `LAMINA_PDF_DOCS_GITHUB=1` (the repository is private).

The release lane (`.github/workflows/release.yml`, ADR 0017 §6, ADR 0018 §2) runs on `v*` tags and on `workflow_dispatch` (`gh workflow run release.yml --ref <ref> [-f ref=<tag-or-sha>]`): `guard` (`cargo xtask release-guard`: refuses unless the latest full nightly run on `main` succeeded on the release commit or an ancestor: a scheduled run, or a dispatch with every input at its default, which nightly.yml's `run-name` titles "Nightly (full budgets)"; other dispatches don't count (ADR 0018 §2); `version check-tag`), then the fast lane (`check`, `wasm` with publint/attw, `size`), the full lane's suites, `@laminapdf/sdk` in every runtime, the nightly lane (`nightly.yml` via `workflow_call` with `record: false`: nothing recorded, no issue) and `cargo xtask verify-install` (Node 22/24/26, Deno, Bun, Chromium, workerd, Rust path + git dependency pinned to the tag); then, once the `release` job reports every check passed, the publish jobs (ADR 0017 §7): `publish-crates` (`cargo xtask publish crates`: `cargo publish --workspace` of the twelve `publish = true` crates with a token from crates.io trusted publishing, the only job with `id-token: write`), `publish-npm` (`cargo xtask publish npm-pack`, without the token: the fixed group built and packed with `pnpm pack`; then `npm-stage`: each tarball staged with `npm stage publish`, npm 11.17.0 through `npx`, using the stage-only `NPM_TOKEN` secret; the owner approves each version on npmjs.com) and `github-release` (`cargo xtask sbom`: CycloneDX SBOMs, attached to the GitHub release with `cargo xtask release-notes`' CHANGELOG section). Only a tag push publishes (`github.event_name == 'push' && github.ref_type == 'tag'`); a dispatch, even on a tag, runs every step with `--dry-run`, and a re-run skips what is already at the version (`release_workflow_should_publish_only_from_its_publish_jobs_and_only_on_a_tag_push` in `tools/xtask/src/release.rs` checks it).

Fuzzing (`fuzz/`, see its README) needs nightly Rust and cargo-fuzz (pinned in `doctor.rs`). Python (pypdf, pinned in `tools/corpus-facts/requirements.txt`) is only needed to regenerate facts; tests read the committed JSON.

The nightly lane (`.github/workflows/nightly.yml`, cron, `workflow_dispatch`, and `workflow_call` for the release lane; ADR 0018 §2) runs on `main`, on the same self-hosted runners as the PR lanes: the live differential, every fuzz target for 10 minutes (corpus kept in the Actions cache), the scaling tests, the benchmarks (after every job that doesn't depend on them, whatever its result, so they don't share the Mac with those; history in `history.jsonl` on the `bench-data` branch, under a runner label per machine, `macos-arm64/<runner name without its number>`), `@laminapdf/sdk` in every runtime with its timings and WebAssembly memory appended to the same history (`pdf-runtimes`, after `bench`; `pdf/<runtime>/<case>` keys; recorded, never a regression issue), the hayro-vs-PDFium render diff (`render-diff`, X3b: `cargo xtask render-diff --pages 20` over the external corpus with PDFium from `cargo xtask fetch-pdfium`; the pass+minor share per source appended to the same history as `render-diff/<source>` basis points, with the sampling; a drop of more than 2 points against the last point from the same runner and sampling opens "Nightly render-diff regression on <ref>", never a failure; report and diff images in the `render-diff` artefact; every job that fetches the history pushes it with `.github/actions/bench-history`, which retries a refused push), veraPDF (`verapdf`, B8b: `cargo xtask verapdf` over every example that claims a profile; any violation fails; writes nothing but its artefact) and the external link check (`links`: a dead URL fails it and its table goes in the issue; a URL that passes only on a retry is reported as flaky; one whose last answer is 403 (not retried) or 429 (after its retries) is reported as refused, with a warning, and doesn't fail it; hosts that always refuse bots go in `.config/link-check.toml` with a reason). GitHub ends a timed-out job `cancelled`, usually because it landed on a hung runner, and the report counts it as a failure; a run someone cancelled opens no issue. A failed or timed-out job, a flaky scaling test or a flaky link opens or comments on the `nightly` issue "Nightly lane failing on <ref>", where flaky results, which passed on their retry, are marked as not blocking the release; a benchmark regression over 10% and a render-diff regression open their own issues and never fail the run; every write (history pushes, the fuzz cache, issues) is gated on the `record` input, which the release lane sets to `false` (`release_lane_should_call_the_nightly_lane_without_recording` in `tools/xtask/src/release.rs` checks each step). Its jobs are the `cargo xtask` tasks above. The live differential needs the corpus (`cargo xtask corpus fetch`), qpdf at the version pinned in `doctor.rs`, `pnpm --dir tools/differential install --frozen-lockfile` (pdf.js) and Python with `tools/differential/requirements.txt` (`$LAMINA_PDF_PYTHON`); every reader runs at once, in chunks of separate processes under time limits, so a crash or hang costs one file (`tools/xtask/src/runner.rs`). Reading API (ADR 0003, 0005): `Document::open(source, OpenOptions)` takes an owned or shared `ByteSource` (`Vec<u8>`, `Arc<[u8]>`, `&'static [u8]`, `Arc<dyn ByteSource>`; in-memory ones are parsed in place, others are read in 64 KiB windows bounded by `Limits::max_read_window`, and a source answering `Pending` makes open or any lazy call fail with `Error::DataPending { ranges }` listing the ranges it needs next: windows, stream data or xref-entry probes; the edge crate `laminapdf-source` has `SparseSource`, filled with `supply(offset, bytes)`, and `retry`/`open_with`, which fetch those ranges and call again, plus `FileSource` and `MmapSource`); `OpenOptions` holds `Limits` (hard limits fail with `Error::LimitExceeded`, soft ones drop with a warning), strict mode (`Error::Strict`) and the password: the standard security handler (R2–R6, ISO 32000 §7.6) decrypts strings and streams on load, tries it as user then owner password (owner first for R5/R6), and fails with `password-required` or `wrong-password`; `Document::encryption()` and `permissions()` describe the result. Warning and error codes are listed once in `fixtures/codes.json` (v2: `code`, `kind`, `summary`, `hint`, `since` per code; ADR 0026; its schema is `fixtures/codes.schema.json`), from which `cargo xtask gen codes` generates every surface's tables (never edit them by hand; a new code is one entry, one `docs/errors/<code>.md` page, its `code()`/`kind()` arms and a regeneration), and which `crates/laminapdf-cos/tests/codes.rs` checks against the Rust enums and the `docs/errors/<code>.md` pages; every error and `Warning` has `code()`, `kind()` (one of nine `ErrorKind`s, an exhaustive match per type that each crate's unit tests check against the file) and `location()` (positions are tagged: `Position::{FileOffset, Object, InStream}`), and no `Display` formats text read from the input. Typed views live in `laminapdf-model`: its `Document` wraps the COS one (and derefs to it) with the ID allocator; `doc.pages()`, `doc.outline()`, `doc.info()`, `doc.page_labels()`, `doc.name_tree(key)`; views raise warnings on the document via `laminapdf_cos::Document::report`. `LaminaPdfId`s are `p12.0` (kind + object) or path IDs such as `p5.0/Kids/3` for direct dictionaries (ADR 0005 §5).

Content API (ADR 0023): `laminapdf_content::ContentIter::new(&bytes)` tokenizes decoded content into `Op`s (Annex A `Operator` + operands; inline images whole) and `Issue`s; `interpret_page(&doc, &page, &mut visitor)` (or `interpret_content(&doc, &bytes, resources, &mut visitor)`) runs it with graphics/text state, resources, Form XObjects (depth `max_xobject_depth`, cycles by object identity) and marked content, calling `Visitor` methods (`show_text` returns the `TextAdvance` of the glyphs; glyph decoding is `laminapdf-text`'s). Content repairs are `laminapdf_cos::Warning`s (`content-*`, `inline-image-unterminated`, `xobject-cycle`) recorded on the document; `max_content_operators` counts every operator of one call, forms each time they are drawn.

Editing API (ADR 0005 §3, 0006): the base bytes never change; every write goes through `laminapdf_cos::Document::edit()` → `CosMut` into the overlay (resolution reads it first; an entry equal to the base is dropped; `is_dirty()`), with a journal (`journal_mark`, `rollback_to`, `take_changes`). `laminapdf_ops::Document` wraps the model document and is the only write path for callers: `doc.transact(Origin::Local, |tx| { tx.apply(op)?; … })`, `tx.savepoint(…)`, or `begin`/`apply`/`commit`/`rollback`; `undo()`/`redo()` return `UndoOutcome::{Applied, Partial, Skipped}`. Ops (`SetInfo`, `RotatePage`) are serde JSON (`{ "op": "rotatePage", "args": { … } }`, envelope `OpLog { v: 1, ops }`), with frozen samples in `fixtures/ops/v1/`.

Saving API (ADR 0007, ADR 0005 §3; `laminapdf-save`): the `Save` trait on `laminapdf_ops::Document`: `doc.plan(&options)`, `doc.save(&mut sink, &options)` (write-only sink: a full rewrite leaves `SaveState::SavedNotRebased` until `doc.rebase(bytes)`) and `doc.save_and_rebase(sink, &options)` (a `ReadableSink`). Every save plans first: `SavePlanner::new(&doc)` detects the `SaveConstraint` (signatures from signature fields, `/Perms` DocMDP/UR3, `/Reference` transforms, `/Lock`, DocTimeStamp, and a repaired file's objects; `doc_mdp`; rewrite reasons `RepairedBase`, `EncryptedBase`, `NoBase`, `OpRequiresRewrite`; `signatures_unknown` when part of the form can't be followed (counts as signed); violations of the pending op classes, `laminapdf_ops::Document::pending_changes()`), `kind()` is `Free | AppendOnly | RequiresRewrite | Conflict`, and `SaveMode::{Auto (default), Incremental, FullRewrite}` is resolved per ADR 0007 §3; refusals are `would-invalidate-signatures` (the whole constraint), `requires-rewrite` and `encrypted-base` (every mode, unless `with_remove_encryption(true)`: a plaintext full rewrite); an unchanged document always saves incrementally (the base bytes unchanged). `with_invalidate_signatures(true)` is the explicit override (the writers write the output with the invalidated `/V` and `/Perms` entries removed, listed in `SaveReport::invalidated`; the document changes only through the rebase); `planner.would_violate(&op)` checks an edit early. `IncrementalWriter` / `FullWriter` over a `laminapdf_cos::Document` stream to a `WriteSink` (`Vec<u8>`, `IoWrite<W>`; append only). External tool versions are pinned in `tools/xtask/src/doctor.rs` (CI installs the same ones): `cargo-deny` is required by `check`; `cargo-nextest` is optional (falls back to `cargo test`), except for `differential --full`, which needs it.

Research spikes (`spikes/`) are throwaway-quality APIs used to inform decisions, not the product. They are outside both workspaces; CI still runs the pdf-basics spike's checks, in the fast lane's `msrv-and-spike` job.

`spikes/krilla-fit/` — krilla vs a builder over `laminapdf-cos` (Round B1); standalone, not in CI: `scripts/fetch-font.sh` once, then `cargo run --release` prints the measurements (see its README).

`spikes/lamina-ffi/` — the `laminapdf` façade bound with UniFFI `=0.32.2` (Round L6a, ADR 0029); standalone, not in CI: `cargo test` (Rust), `scripts/build-kotlin.sh` (Kotlin JVM tests; JDK 17+ and Gradle 8), `scripts/run-on-mac.sh` on Apple silicon with Xcode (XCFramework, Swift tests, Android NDK libraries, 16 KB check, AAR, sizes into `target/mac-report.md`; see its README).

`spikes/pdfium-wasm/` — `@embedpdf/pdfium` beside `@laminapdf/sdk` in one web worker (Round C1b); standalone, its own pnpm project, not in CI; frozen before the `@laminapdf` rename, so it still imports `@lamina/pdf` from `vendor/lamina-*-0.0.0.tgz` and needs that rename (and its lockfile regenerated) before a re-run: `cargo xtask wasm`, then `sh scripts/pack-lamina.sh && pnpm install && node scripts/make-fixtures.mjs && pnpm exec playwright test && node scripts/summarise.mjs` (Chromium, Firefox, WebKit; see its README).

`spikes/hayro-parity/` — hayro vs PDFium render parity (Round C1a); standalone, not in CI: `scripts/fetch-pdfium.sh && scripts/fetch-corpora.sh` once (downloads into gitignored folders), then `cargo run --release` writes `out/dpi96/results.csv` and `summary.md` (see its README).

`spikes/pdf-basics/` — the same minimal PDF core in Rust and TypeScript (see its `SPEC.md`):

```sh
# Rust (needs rustup; targets wasm32-unknown-unknown, aarch64-apple-ios, aarch64-linux-android)
cd spikes/pdf-basics/rust
cargo test
cargo clippy --all-targets --all-features --locked -- -D warnings
scripts/check-targets.sh                               # everything: cross-target checks, wasm build, fmt, clippy, tests
cargo build --release --target wasm32-unknown-unknown  # wasm loaded by the TS tests

# TypeScript (Node ≥ 20, pnpm)
cd spikes/pdf-basics/ts
pnpm install
pnpm typecheck && pnpm lint && pnpm test               # WASM interop tests run once the Rust wasm is built
pnpm size                                              # min+gz bundle size
```

Rust code follows the `rust-best-practices` skill (no `unwrap`/`expect` in library code, clippy clean with `-D warnings`). Library code in both languages is bytes-in/bytes-out: no file system, network or Node-only APIs, so it runs on web, mobile and desktop.
