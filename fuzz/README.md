# fuzz

cargo-fuzz targets for Lamina PDF's parsers and readers ([ADR 0018](../docs/decisions/0018-test-strategy.md) tier 9), in the layout OSS-Fuzz expects for Rust (`fuzz/Cargo.toml`, `fuzz/fuzz_targets/<name>.rs`). This folder is its own Cargo workspace, excluded from the root one (`exclude = ["spikes", "fuzz"]`; `cargo xtask portability` checks it), because libFuzzer needs nightly Rust. The root `rust-toolchain.toml` pin does not apply: every command here runs as `cargo +nightly …`.

| Target | Drives | Seeds |
| --- | --- | --- |
| `lex` | `Lexer::next_token` until the end or an error; asserts the lexer always advances | `fixtures/corpus`, `fixtures/golden` |
| `parse_object` | `parse_object_with` and `Parser::indirect_object` (with a failing `/Length` resolver, so the `endstream` scan runs); whatever parses must serialise | as above |
| `flate_decode` | `filters::flate_decode` on the input minus its last four bytes, and the filter pipeline with PNG predictor parameters from those four bytes | the stream data of every fixture, each followed by `[1, 1, 8, 1]` (no predictor) |
| `open` | `Document::open`, then every read path and model view, each view on its own (`exercise.rs`), first with the empty password, then with each line of `seeds/open/passwords.txt` | fixtures, plus everything under `seeds/open/` |
| `ops_json` | `OpLog::from_json`, then the log applied to `corpus/hello.pdf` and `corpus/outline.pdf` as one transaction, saved (`Auto`) and reopened; and op by op, all undone, after which a save must write the base unchanged | `fixtures/ops/v1/` |
| `save_roundtrip` | eight control bytes (mode, overrides, xref layout, numbering; seven steps of rotate, set title, undo, redo) before a PDF: open, apply, save; every saved file must reopen, and a full rewrite must rebase | every fixture PDF (and `fixtures/signed/`) after fixed control bytes |
| `copy_pages` | `ObjectCopier` (todo E2p): the first eight pages of the input, read as a PDF, copied into an empty document and into `corpus/outline.pdf`; a copy that fails must leave the target unchanged, and one that succeeds must save into a file that reopens without repair with the pages added | fixtures |
| `page_tree` | the page-tree walk and page views; input that is not a whole file becomes the body of the `/Pages` object in a small file with a page and an intermediate node (with its own page) to inherit through | fixtures, plus `seeds/page_tree/` |
| `content` | the content-stream interpreter (`laminapdf-content`, [ADR 0023](../docs/decisions/0023-content-stream-reading.md)) on every page; input that is not a whole file becomes the page content of a small file whose resources hold a font, an image, a form that uses the page's resources, a form that draws itself, a graphics state, a shading, a pattern, a colour space and a property list. Also asserts balanced marked-content and form events | fixtures, plus `seeds/content/` (content streams) |
| `annots` | the annotation views and ops (`laminapdf-model`'s `Document::annotations`, `laminapdf-ops`' `UpdateAnnot` and `DeleteAnnot`, todo E4b) on the input as a PDF: every page's annotations read, then up to 16 of them moved, edited and deleted, each in a transaction undone at once: an op applies or fails with an error, and undo leaves the overlay empty | `seeds/annots/` (the `fixtures/annotations/` files: every subtype, threads with a cycle and a group, locks, a tagged page). Not yet in `cargo xtask fuzz` or the nightly lane, whose matrix only the owner can change: run it with `cargo +nightly fuzz run annots` |
| `content_append_scan` | the append API (`laminapdf-content`'s `scan_balance` and `PageContentWriter::wrap_existing`, todo E2e) on the input split at its zero bytes into up to eight content streams of one page (the second Flate-compressed): every unmatched `Q` the scan reports is a `Q` byte, the wrapped content, read again, keeps the depth, text and marked-content state and has nothing unmatched, a wrap refuses with `invalid-structure` and writes nothing or leaves the page wrapped (a second wrap does nothing) with only the streams that held an unmatched `Q` changed, and a rollback empties the overlay | `seeds/content_append_scan/` (streams with surplus and stray `Q`s, a wrapped page, an inline image, an unterminated string). Not yet in `cargo xtask fuzz` or the nightly lane, whose matrix only the owner can change: run it with `cargo +nightly fuzz run content_append_scan` |
| `extract_text` | text extraction (`laminapdf-text`'s `TextExtractor`, todo B9c) on every page, with `lines` and `visible`; input that is not a whole file is both the page content and the `/ToUnicode` CMap of a small file with a simple font (`/Differences`) and a Type 0 font (Identity-H). Asserts run glyph ranges in bounds and finite quads | fixtures, plus `seeds/extract_text/` (a CMap and content streams) |
| `extract` | extraction for retrieval (`laminapdf-extract`) of every page, by layout and by content order, with hidden runs kept; asserts finite boxes, normalised boxes in [0, 1], unique block IDs and no hidden run in a block | fixtures, plus `seeds/extract/` (a page whose text an annotation's appearance covers) |
| `engine_protocol_decode` | the desktop app's frames between its main process and its engine (`laminapdf-desktop-protocol`'s `read_frame`, [ADR 0008](../docs/decisions/0008-desktop-shell.md) §3), read in both directions; asserts that every frame decodes or fails with a protocol error, and that a decoded message encodes again | `seeds/engine_protocol_decode/` (every message, each way) |
| `document` | `laminapdf.document/1` (`laminapdf-build`'s `flow::document::fill` and `Builder::document`, todo T4e): the input split at its first zero byte into a template and its data, both read as JSON, filled and laid out in the standard 14 fonts; asserts that every failure is a coded error and a document that builds also saves | `seeds/document/` (the invoice template with its data, and every placeholder) |
| `markdown` | the Markdown front end (`laminapdf-build`'s `Builder::markdown`, todo T4d) on the input read as UTF-8, in the standard 14 fonts and in Noto Sans with a contents page and an image; asserts that every failure is a coded error, every warning's offset lies inside the Markdown, and a document that builds also saves | `fixtures/markdown/`, plus `seeds/markdown/` (a Latin document with every construct) |
| `xmp_parse` | the XMP packet reader (`laminapdf_model::xmp::Packet`, todo E1b) on the raw input: a packet that parses must write back byte for byte, read every mapped field, and after a title, authors, date and keywords edit write a packet that parses again with those values | `fixtures/golden/xmp/` (the producers' packets and their edited goldens) |

Each target is one line calling a function in [`crates/laminapdf-model/tests/common/fuzz_entry.rs`](../crates/laminapdf-model/tests/common/fuzz_entry.rs) (`annots`: [`crates/laminapdf-ops/tests/common/annot_fuzz_entry.rs`](../crates/laminapdf-ops/tests/common/annot_fuzz_entry.rs); `content`: [`crates/laminapdf-content/tests/common/fuzz_entry.rs`](../crates/laminapdf-content/tests/common/fuzz_entry.rs); `content_append_scan`: [`crates/laminapdf-content/tests/common/append_fuzz_entry.rs`](../crates/laminapdf-content/tests/common/append_fuzz_entry.rs); `markdown`: [`crates/laminapdf-build/tests/common/fuzz_entry.rs`](../crates/laminapdf-build/tests/common/fuzz_entry.rs); `document`: [`crates/laminapdf-build/tests/common/document_fuzz_entry.rs`](../crates/laminapdf-build/tests/common/document_fuzz_entry.rs); `engine_protocol_decode`: [`crates/laminapdf-desktop-protocol/tests/common/fuzz_entry.rs`](../crates/laminapdf-desktop-protocol/tests/common/fuzz_entry.rs); the save targets: [`crates/laminapdf-save/tests/common/fuzz_entry.rs`](../crates/laminapdf-save/tests/common/fuzz_entry.rs), with [`copy.rs`](../crates/laminapdf-save/tests/common/copy.rs) for `copy_pages`), which `fuzz/src/lib.rs` includes (with `exercise.rs`), so the integration tests and the fuzzer share the code. Invariants: no panic, no hang (`-timeout=10`), memory under `-rss_limit_mb=2048`, default [`Limits`](../docs/decisions/0003-reader-tolerance-and-limits.md).

## Running

```sh
rustup toolchain install nightly --profile minimal
cargo install cargo-fuzz --locked --version 0.13.2    # or: cargo xtask doctor --install
cargo xtask fuzz <target> --time 600                  # default 60 s
cargo xtask fuzz --all --time 30 --jobs 4            # every target, 4 at once (the full PR lane; 120 s on main)
cargo xtask fuzz seeds [<target>]                     # only build fuzz/corpus/<target>/
cargo xtask fuzz cmin [<target>]                      # minimise fuzz/corpus/<target>/ (cargo fuzz cmin)
cargo xtask fuzz tmin <target>                        # minimise every crash in fuzz/artifacts/<target>/
```

`cargo xtask fuzz` first builds the seed corpus `fuzz/corpus/<target>/` (gitignored) from the PDFs in `fixtures/corpus/` and `fixtures/golden/`, plus `fixtures/regressions/<target>/` and everything under `fuzz/seeds/<target>/` (except `passwords.txt`) copied verbatim; seed names carry their source path, then runs `cargo +nightly fuzz run <target> fuzz/corpus/<target> -- -max_total_time=<N> -print_final_stats=1 -timeout=10 -rss_limit_mb=2048`. The nightly lane ([`.github/workflows/nightly.yml`](../.github/workflows/nightly.yml), todo X3a) runs every target for 10 minutes each night (and on demand). It starts from the corpus the full lane last saved on `main` (or its own last one), minimises it with `cargo xtask fuzz cmin` before saving it back, minimises crashes with `cargo xtask fuzz tmin <target>` under the same libFuzzer limits, uploads them as artefacts and opens a `nightly` issue with the minimised inputs; the full PR lane ([`.github/workflows/full.yml`](../.github/workflows/full.yml)) runs each target for 30 s on every code PR and 2 minutes on every push to `main`, four at once (`--jobs 4`, at most 8: every target is built once first, falling back to one build per target to name a broken one; each run streams its output to `target/xtask/fuzz/<target>.log`, uploaded when the job fails or is cancelled, and prints it whole, every line prefixed with `[<target>]`, when it ends; the per-input `-timeout` is 10 s times the number of jobs, so a busy shared machine doesn't turn a slow input into a timeout crash, while `-rss_limit_mb=2048` stays per process). It starts from the corpus last saved by a push to `main`; only those pushes save it, after `cargo xtask fuzz cmin`, so the cache stays bounded. `--all` runs every target before failing and says whether a failure was a crash (new files in `fuzz/artifacts/<target>/`) or a build or setup problem.

Every run, one target or `--all`, keeps its output in `target/xtask/fuzz/<target>.log`. A run that fuzzed also writes `target/xtask/fuzz/<target>.json`, whether it ended cleanly or crashed. That summary holds the time budget (`seconds`), how long libFuzzer says it fuzzed (`fuzzed_seconds`, from its `Done … runs in … second(s)` line, absent after a crash), libFuzzer's `stat::number_of_executed_units` (`executions`), the files in the corpus folder after the run (`corpus_files`) and whether the run saved a crash input (`crashed`). A run that failed before fuzzing, such as a broken build, writes no summary. The nightly uploads each summary, and `cargo xtask proof` gathers them into the night's proof record.

Encrypted seeds are maintained with decryption ([B2b](../docs/todos/done/B2b-standard-security-decryption.md)): the files go in `seeds/open/encrypted/` and their passwords, one per line, in `seeds/open/passwords.txt` (lines starting with `#` are ignored).

## When a target finds a crash

1. Reproduce: `cargo +nightly fuzz run <target> fuzz/artifacts/<target>/<crash-file>`.
2. Minimise: `cargo +nightly fuzz tmin <target> fuzz/artifacts/<target>/<crash-file>` (or `cargo xtask fuzz tmin <target>` for every crash; the nightly issue already carries the minimised input, base64-encoded when it is at most 4 KiB).
3. Commit the minimised input, raw bytes as the target received them, as `fixtures/regressions/<target>/<hash>` (the hash from the artefact name) and list it in `fixtures/README.md`. `crates/laminapdf-model/tests/regressions.rs` (for `content`, `crates/laminapdf-content/tests/regressions.rs`; for `ops_json`, `save_roundtrip` and `copy_pages`, `crates/laminapdf-save/tests/regressions.rs`; for `extract_text`, `crates/laminapdf-text/tests/regressions.rs`; for `extract`, `crates/laminapdf-extract/tests/regressions.rs`; for `engine_protocol_decode`, `crates/laminapdf-desktop-protocol/tests/regressions.rs`) replays every file there through the same `fuzz_entry` function, so it fails before the fix; also add a named test for the behaviour in the crate whose code was wrong. The seed step picks the file up from then on.
4. Fix the bug in the same PR.
